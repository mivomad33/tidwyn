# 디자인 기준

Tidwyn의 모든 화면이 따르는 기준이다. 시안이 없는 화면도 이 문서만 보고 같은 모양으로 만든다.

## 방향

**강조색을 꽉 채운 한 칸과 그 안의 흰 T를 브랜드로 삼고, 나머지는 글자·흐린 글자·선으로 끝낸다.**

- 이 제품에 맞는 이유: Tidwyn은 매일 폰과 브라우저 탭 사이에서 바로 찾아야 하는 읽을거리다. 그래서 표시는 가장 작은 크기에서 먼저 알아볼 수 있어야 한다. 반면 화면은 차분하고 믿을 만해야 하므로, 강렬한 색은 표시와 화면마다 하나인 주요 행동에만 쓴다.
- 표시의 고유한 모양: T 가로획의 왼쪽 위를 획 높이만큼 45도로 잘랐다. 흔한 앱 타일과 갈리는 부분이다.
- 범위: 기존 화면의 레이아웃, 색 토큰, 글꼴, 머리글의 글자 이름 표시는 그대로다. 이번 방향은 브랜드 표시와 없는 페이지, 오류 정정 안내, 정정 표시를 더한다.

## 토큰

토큰의 원본은 코드다.

| 무엇 | 파일 |
|---|---|
| 색 | `site/src/lib/theme.ts` (`LIGHT`, `DARK`) |
| 글꼴, 글자 크기, 간격, 모서리, 움직임 | `site/src/styles.css` |
| 시안 사본 | `docs/specs/20261031-1840-public-ready/design/final/tokens.css`, 같은 폴더의 `site.css` |

시안 사본의 변수 이름은 `--c-` 접두사를 쓴다. 값은 코드와 같고 이름만 아래 표처럼 대응한다.

### 색

| 역할 | 코드 이름 | CSS 변수 | 시안 변수 | 라이트 | 다크 |
|---|---|---|---|---|---|
| 바탕 | `bg` | `--bg` | `--c-bg` | `#ffffff` | `#161618` |
| 글자 | `fg` | `--fg` | `--c-text` | `#1d1d1f` | `#ececee` |
| 흐린 글자 | `muted` | `--muted` | `--c-muted` | `#6b6b70` | `#9a9aa0` |
| 선 | `line` | `--line` | `--c-line` | `#ececee` | `#2a2a2e` |
| 상자 | `chip` | `--chip` | `--c-box` | `#f5f5f7` | `#222226` |
| 강조 | `accent` | `--accent` | `--c-accent` | `#c2410c` | `#fb923c` |
| 강조 바탕 | `accentbg` | `--accentbg` | `--c-accent-bg` | `#fff1e8` | `#3a2414` |
| 읽음 표시 | `check` | `--check` | `--c-check` | `#3b7fd0` | `#6aa5ec` |
| 읽음 체크 글자 | `checkInk` | `--check-ink` | `--c-check-ink` | `#ffffff` | `#161618` |
| 안 읽음 테두리 | `ring` | `--ring` | `--c-ring` | `#d1d1d6` | `#3a3a3f` |
| **강조 면 위 글자 (새 토큰)** | `onAccent` | `--on-accent` | `--c-on-accent` | `#ffffff` | `#161618` |

- `onAccent`는 이번에 코드에 더한다. 대비는 라이트 5.18:1, 다크 7.98:1이다. `textPairs`에 이 조합을 넣는다.
- 대분류 색은 코드에 있는 값을 쓴다(라이트/다크): 정치 `#7c3aed`/`#a78bfa`, 경제 `#c2410c`/`#fb923c`, 사회 `#0f766e`/`#2dd4bf`, 국제 `#b91c1c`/`#f87171`, IT·AI `#1d4ed8`/`#60a5fa`, 과학·건강 `#15803d`/`#4ade80`, 문화·스포츠 `#be185d`/`#f472b6`.
- 지표와 영상의 색(`up`, `down`, `plot`, `thumb`, `durFg`, `durBg`)은 코드에만 있고 이번 시안에서 쓰지 않았다. 해당 화면에서 그대로 쓴다.
- 표시 색: 아이콘 칸과 공유 이미지 띠는 라이트·다크 모두 `#c2410c`, T는 `#ffffff`다. 이 값은 표시 파일 안에 고정하고 테마를 따르지 않는다(시안의 `--c-tile`, `--c-tile-ink`).

### 글꼴

- 목록: `Pretendard, "Pretendard Variable", -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", system-ui, sans-serif`
- 외부 글꼴을 내려받지 않는다. 공유 이미지의 글자는 Pretendard(SIL OFL)를 윤곽선으로 바꿔 넣는다.

### 글자 크기

새로 만드는 요소는 아래 단계만 쓴다.

| 크기 | 굵기 | 쓰는 곳 |
|---|---|---|
| 22px | 800 | 페이지 제목 (`.page-title`, 줄 높이 1.3) |
| 17px | 700 | 목록 제목, 메일 주소 |
| 15px | 700 또는 400 | 버튼, 보조 링크, 짧은 소식 |
| 14px | 400, 머리말 700 | 안내문, 정정 사유, 제보 링크 (줄 높이 1.65, 메일 상자와 요청 주소는 1.5) |
| 12px | 700 또는 600 | 정정 표시, 대분류 근처의 메타, 바닥글 |

- 머리글 이름은 기존 그대로 19px 800이다.
- 기존 CSS에는 이보다 많은 크기(10~22px 사이 19종)가 있다. 새 화면에서 이 크기를 늘리지 않는다. 합치는 일은 사람이 정한다(아래 "확인 방법"의 예외).
- 긴 안내문은 375px에서도 글자를 줄이지 않고 줄 수만 늘린다.

### 간격

| 값 | 쓰는 곳 |
|---|---|
| 18px | 화면 좌우 여백 |
| 14px·12px | 뉴스 줄·짧은 소식 줄의 위아래 안쪽 여백 |
| 6~12px | 한 묶음 안 |
| 16px | 문단 사이, 요약과 바뀐 내용 사이 |
| 24px | 묶음 사이 |
| 30px | 소개의 절 제목 위 |
| 640px | 본문 최대 폭 (`#root`) |

선 1px과 여백으로 구역을 나눈다. 상자나 카드를 늘리지 않는다.

### 모서리

| 값 | 쓰는 곳 |
|---|---|
| 4px | 배지, 포커스 윤곽 |
| 6px | 출처 링크 |
| 8px | 버튼, 입력, 알림, 아이콘 버튼 |
| 10px | 상자(`.story`, 메일 상자, 카드) |
| 50% | 읽음 동그라미 |
| 999px | 칩 |

아이콘은 16px 직각, 32px `rx 3`, 64 격자 원본 `rx 5`다. 180px와 512px은 직각이고 모서리는 기기가 깎는다.

### 그림자

쓰지 않는다. 예외는 일정 주소로 들어왔을 때 줄 자리를 바꾸지 않고 강조하는 `box-shadow: 0 0 0 6px var(--accentbg)` 하나다.

### 움직임

- 대기 표시 회전 0.8s linear, 일정 강조 전환 0.6s뿐이다. 둘 다 `prefers-reduced-motion`에서 끈다.
- 새 요소에 움직임을 더하지 않는다. 카드 펼침은 전환 없이 바로 열린다.

## 브랜드 표시

### 아이콘

| 파일 | 크기 | 도안 |
|---|---|---|
| `icon-16.svg`, `icon-16.png` | 16px | 전용 도안. 직각 칸, `M4 2h10v4h-4v8H6V6H2V4h2z`. 45도 절단을 2×2px 계단으로 다시 그렸다. 가로획 12×4px, 기둥 4px, 사방 주황 2px |
| `icon-32.svg`, `icon-32.png` | 32px | 전용 도안. `rx 3`, `M11 4h16v6h-8v18h-6V10H5z` |
| `icon.svg`, `icon-48.png` | 원본, 48px | 64 격자, `rx 5`, `M25 9h26v12H38v34H26V21H13z` |
| `icon-180.svg`, `icon-180.png`, `icon-512.png` | 180px, 512px | 같은 T, 직각 칸. 모서리가 투명하지 않다 |

- 한 색 면 + 흰 T뿐이다. 그림자, 그라데이션, 테두리를 더하지 않는다.
- 'Tidwyn' 글자 전체를 아이콘에 넣지 않는다.
- 16~32px은 큰 도안의 축소가 아니라 격자에 맞춘 도안이다. 크기를 바꾸면 새로 그린다.
- 공통 head에 `<meta name="apple-mobile-web-app-title" content="Tidwyn">`을 넣는다.

### 공유 이미지

- 파일은 `share.svg`(원본)와 `share.png`(1200×630, 약 28KB)다. 사이트 전체에 한 장이고 라이트 바탕 한 벌이다.
- 구성: 왼쪽 주황 띠(폭 246px, 높이 전체) 안의 흰 T, 오른쪽 흰 바탕의 이름과 설명 두 줄이다. 요소를 더하지 않는다.
- 이름은 x 306~608, 설명은 같은 x에서 시작하는 64px 두 줄(`AI가 매일 모아 쉬운 말로 바꿔 쓴` / `한국·세계·IT·AI 뉴스 요약`, 첫 줄 끝 x 1106)이다. T의 세로 중심은 글 묶음과 같은 y 315다.
- 왼쪽 위 자르기(x 0~630)와 가운데 자르기(x 285~915) 모두 이름이 남는다. 1:1 자르기에서 설명 끝은 잘릴 수 있다.
- T는 `icon.svg`와 같은 도형이다.
- `og:description`: `AI가 매일 모아 쉬운 말로 바꿔 쓴 한국·세계·IT·AI 뉴스 요약` (기본값이다. 페이지마다 그 페이지 설명을 쓴다)
- `og:image:alt`, `twitter:image:alt`: 위 문구 앞에 `Tidwyn. `을 붙인다.

## 컴포넌트 규칙

### 강조색 쓰는 법

강조색은 한 화면에 한 역할이다.

| 화면 | 강조색을 쓰는 것 |
|---|---|
| 없는 페이지 | 주 버튼 |
| 소개의 오류 정정 절 | 메일 주소 |
| 뉴스 목록과 카드 | 쓰지 않는다. 정정 표시도 일반 글자색이다 |

대분류 색과 '어제에 이어' 배지는 기존 그대로 둔다.

### 버튼

| 종류 | 모양 | 쓰는 곳 |
|---|---|---|
| 주 버튼 `.btn` | 강조 면, `onAccent` 글자, 15px 700, 높이 48px, 모서리 8px. 767px 이하는 폭 전체, 768px 이상은 글자 폭 | 화면의 주요 복구 행동. 화면에 하나 |
| 아이콘 버튼 `.icon-btn` | 면 없음, 44×44px, 흐린 글자색, `aria-label` 필수 | 머리글의 검색·메뉴 |
| 조용한 링크 `.quiet` | 흐린 글자색, 밑줄(offset 2px) | 보조 동작 |
| 글 링크 `.text-link` | 강조색, 밑줄(offset 2px) | 기존 화면의 글 안 링크 |

포커스는 `2px solid` 강조색, offset 2px이다. 강조 면 위에서는 윤곽을 글자색으로 바꾼다.

### 입력

기존 `.search-form input`을 쓴다. 16px, 패딩 `8px 12px`, 모서리 8px, 테두리 선 색, 상자 바탕이다.

### 목록

- 뉴스 줄은 구분선 1px과 여백으로만 나눈다. 카드로 감싸지 않는다.
- 줄의 순서는 대분류, 제목, 이어지는 이슈, 오른쪽의 읽음 버튼이다.
- 안 읽은 제목은 700, 읽은 제목은 같은 색의 400이다.

### 정정 표시

- 표시는 `정정됨 · M월 D일` 글자 하나다. 일반 글자색, 12px, 700이고 면과 테두리를 쓰지 않는다. 빨강이나 경고색을 쓰지 않는다. 정정은 위험이 아니라 정보다.
- 표시가 있어도 없는 줄과 구조·높이가 같다. 대분류가 길어 표시가 다음 줄로 내려갈 때만 한 줄 늘어난다.
- 위치
  - 340~767px: 읽음 동그라미 왼쪽의 한 세로줄(`margin-left: auto`). 짧은 소식은 메타 줄 맨 뒤다. 표시 끝과 읽음 버튼 사이는 12px 띄운다.
  - 339.98px 이하: 왼쪽으로 붙여 대분류 뒤에 잇고, 대분류가 길어 내려가면 글 시작선에 둔다.
  - 768px 이상: 대분류 뒤.
- 펼쳐도 같은 자리에 남는다.
- 정정 줄에만 펼침 표시를 두지 않는다. 모든 줄이 펼쳐지므로 줄마다 규칙이 달라진다.
- 표시와 사유는 같은 정정 기록에서 만든다. 표시만 있고 사유가 없는 줄이 생기면 안 된다.

### 바뀐 내용

- 펼친 카드(`.fix`): 요약 바로 아래에 16px 띄워 둔다. 선과 면이 없고 14px, 줄 높이 1.65, 일반 글자색이다. 머리말은 같은 크기의 700이다.
- 정정이 한 건이면 날짜는 표시에만 두고 머리말은 `바뀐 내용:`이다. 여러 건이면 최신순으로 쌓고(사이 8px) 머리말에 날짜를 붙인다: `11월 2일 바뀐 내용:`
- 짧은 소식(`.short-fix`): 펼침이 없어 메타 줄 아래에 사유가 늘 보인다. 본문은 흐린 글자색, 머리말은 일반 글자색이다.
- 사유는 줄이지 않고 왼쪽 맞춤으로 줄바꿈한다. 문구는 '무엇을 무엇으로 바로잡았다'로 끝나는 한 문장이다.
- 숫자와 단위가 줄 끝에서 갈리지 않게 `white-space: nowrap`으로 묶는다(`.addr-nb`).

### 펼침 스크롤

정정 기록이 있는 카드를 펼칠 때 줄 윗선이 머리글 위로 올라갔거나 마지막 `.fix` 끝이 화면 밖이면, `scrollIntoView({ block: 'start' })`로 줄 윗선을 머리글 바로 아래에 둔다. 그 밖에는 움직이지 않는다. `scroll-margin-top`은 60px이고, 머리글이 두 줄인 339.98px 이하는 96px다.

### 제보 링크

- 카드 맨 아래의 `.report`: `틀린 내용 알리기 · mivomad33@gmail.com`. 14px, 흐린 글자색, 둘 다 밑줄(offset 2px)이다. 메일 앱이 없어도 주소를 볼 수 있게 글에 함께 쓴다. 넘치면 주소를 통째로 다음 줄로 내린다.
- 카드의 링크는 제목, 날짜, 주소, `틀린 내용:`이 채워진 메일을 연다.
- 짧은 소식은 펼침이 없어 목록 끝에 `짧은 소식 틀린 내용 알리기` 한 줄을 둔다.

### 상자와 카드

- 상자는 상자 바탕, 모서리 10px, 패딩 12px이다. 그림자와 테두리가 없다.
- 새 상자는 이유가 있을 때만 쓴다. 이번에 더한 상자는 메일 상자 하나이고, 카드 안에 상자를 겹치지 않는다.
- 메일 상자(`.mailbar`): 상자 전체가 링크다. 첫 줄은 14px 일반 글자색의 `틀린 내용은 날짜와 뉴스 제목을 적어 이 메일로 알려 주세요.`, 둘째 줄은 17px 700 강조색 밑줄의 메일 주소다. 방침 문단보다 앞에 둔다.

### 대화상자와 알림

- 대화상자는 없다. 필요해지면 직접 만들지 않고 검증된 컴포넌트를 쓴다.
- 안내는 기존 `.notice`를 쓴다. 강조 바탕, 13px, 모서리 8px, `role="note"`이다. 토스트를 쓰지 않는다.

### 빈 상태, 오류, 로딩

- 빈 상태와 로딩은 기존 `.state`를 쓴다. 가운데 정렬, 14px, 흐린 글자색, 패딩 `32px 18px`이다. 로딩은 `.spinner`를 쓴다.
- 오류는 `.state.error`다. 문구는 글자색으로 올린다.
- 없는 페이지
  - 머리글과 바닥글을 유지한다. 왼쪽 정렬이고 그림이 없다.
  - 순서는 제목(`이 주소에는 페이지가 없다`, 22px 800), 안내 한 줄, `404 · 요청한 주소 <경로>`, 주 버튼(`최근 뉴스 브리프 보기`), 보조 링크(`이슈 목록`, `검색`)다.
  - 자바스크립트 없이 보는 정적 페이지에서는 검색을 쓸 수 없어 안내를 `지난 뉴스는 날짜 목록에서 찾을 수 있다.`로, 보조 링크를 `이슈 목록`, `날짜 목록`으로 둔다. 정적 페이지의 머리글과 메뉴에도 검색 입구를 두지 않는다.
  - 안내는 원인을 사실로 말한다. 사과나 농담을 쓰지 않는다.
  - 요청 주소는 `location.pathname`만 보여 준다. 쿼리와 해시는 뺀다. 긴 주소는 줄바꿈한다.
  - 버튼 묶음은 어느 폭에서나 안내 바로 아래에 붙이고, 남는 높이는 보조 링크와 바닥글 사이로 간다.

### 정적 페이지

- 앱을 받기 전이나 받지 못했을 때 보이는 보조 화면이다. 뉴스는 모두 펼쳐 두고, 구역 제목은 17px 700 글자색에 윗선을 둔다.
- 브리프 맨 위에 구역 이동 칩을 두고, 제보 링크는 앱과 같은 자리에 둔다.
- 머리글 아래 메뉴는 앞 5개 항목만 한 줄로 둔다. 나머지는 바닥글에 있다.

### 키보드

- 머리글 맨 앞에 `본문으로 건너뛰기` 링크를 둔다. 포커스를 받을 때만 보인다.
- 메뉴는 Tab으로 밖에 나가면 닫는다.
- 앵커 대상과 본문 포커스는 고정 머리글과 하단 탭에 가리지 않게 `scroll-margin`을 준다. `html`의 `scroll-padding`은 쓰지 않는다(고정 요소에 포커스가 갈 때 페이지가 튄다).

### 문구

- 평서문("-다")을 쓰고, 읽는 사람에게 부탁하는 문장만 존댓말로 쓴다.
- 소개의 제보 안내: `뉴스 제목을 눌러 펼치면 맨 아래에 '틀린 내용 알리기'가 있다. 누르면 내용이 채워진 메일이 열린다. 짧은 소식은 목록 맨 끝의 링크를 쓴다.`
- 바닥글 설명: `Tidwyn · AI가 매일 모아 쉬운 말로 바꿔 쓴 뉴스 요약`
- 브리프 화면의 탭 제목은 이름부터 쓴다: `Tidwyn · 10월 30일 브리프`. 탭이 좁아도 이름이 남게 하기 위해서다. `site/src/lib/format.ts`의 `pageTitle`을 쓰는 브리프 쪽만 바꾸고, 다른 화면의 제목 순서는 그대로 둔다.

## 배치와 반응형

- 한 열이고 본문 최대 폭은 640px이다. 폭이 커져도 레이아웃은 그대로이고 가운데에 놓인다. 왼쪽 아이콘 칸으로 본문을 들여 쓰지 않는다.
- 머리글은 위에 붙어 있다. 왼쪽 이름 또는 뒤로, 가운데 날짜, 오른쪽 검색·메뉴다.

| 폭 | 바뀌는 것 |
|---|---|
| 339.98px 이하 (확대 200% 포함) | 머리글이 두 줄이 되어 날짜가 둘째 줄로 간다. 정정 표시는 왼쪽으로 붙는다. `scroll-margin-top`은 96px다 |
| 340~767px | 정정 표시가 오른쪽 세로줄에 모인다. 주 버튼이 폭 전체다. 바닥글 링크가 높이 44px이다 |
| 768px 이상 | 정정 표시가 대분류 뒤에 온다. 주 버튼이 글자 폭이다 |

- 모바일 주요 버튼 위치: 없는 페이지의 주 버튼은 안내 바로 아래, 폭 전체다. 667px 높이 화면의 첫 화면 안에 들어온다. 누를 곳은 44px 이상이다.
- 누를 곳을 넓힐 때는 보이는 글자와 줄 높이를 그대로 두고 padding·min 크기를 음수 여백으로 상쇄한다.

## 하지 말 것

- 보라·파랑 그라데이션, 반짝이 아이콘, AI 상징: 차분한 읽을거리와 반대이고 흔한 AI 제품으로 보인다.
- 신문·지구본 아이콘, 시계·달력, 번개, 로봇: 뜻을 잘못 전하거나 평범하다.
- 강조색 뿌리기: 강조가 없어진다. 정정 표시, 사유, 링크, 대분류를 모두 색으로 쓰지 않는다.
- 정정 표시를 배지나 경고색으로 만들기: 읽은 줄에서 제목보다 먼저 보이고, 정정을 위험처럼 전한다.
- 모든 것을 둥근 카드에 담기, 카드 안의 카드: 선과 여백으로 나눈다.
- 그림자, 장식 블롭, 글래스 효과: 이 제품에 맞는 이유가 없다.
- 이모지를 아이콘 대신 쓰기.
- 없는 페이지의 일러스트, 농담, 사과: 차분함과 믿음에 어긋난다. 숫자 404를 제목보다 크게 쓰지 않는다.
- 공유 이미지에 스크린샷, 인물, 장식을 넣기: 작은 미리보기에서 읽히지 않는다.
- 아이콘에 테마별 다른 면 색을 쓰기: 어느 탭에서나 같은 윤곽이어야 알아본다.
- 메일 주소나 정정 사유를 말줄임으로 자르기.
- 머리글의 글자 이름을 아이콘으로 바꾸기: 기존 표시는 그대로다.

`design-check`는 이 문서를 기준으로 본다. 관문과 심각도는 `~/.claude/skills/shared/design-review.md`를 따른다.

| 항목 | 기준 |
|---|---|
| 가로 스크롤 | 어느 폭에서도 없다 |
| 잘린 글 | 말줄임표 없이 잘린 글이 없다 |
| 접근성 | axe `critical`·`serious` 0개(색 대비 포함) |
| 누를 곳 | 모든 폭 24px 이상, 모바일 44px 이상(글 안의 링크는 예외) |
| 모바일 입력 글자 | 16px 이상 |
| 글자 크기 종류 | 한 화면 6종 이하 (아래 예외) |
| 콘솔 오류 | 없다 |

- 촬영 폭: 375, 1280. 이번 단계의 명세서가 정한 화면 확인은 375·1440이다. 좁은 폭 규칙을 고치면 320도 본다.
- 테마: 라이트, 다크.
- 상태
  - 없는 페이지: 기본, 긴 주소, 667px 높이의 첫 화면
  - 오류 정정 안내: 기본, `#corrections`로 들어온 경우
  - 브리프: 표시 없는 줄과 섞인 목록, 펼친 카드, 긴 사유와 여러 건 정정, 짧은 소식의 정정
  - 아이콘: 16·32·48·180·512px, 라이트·다크 탭, 좁은 탭, 홈 화면, 흰 바탕 검색 결과
  - 공유 이미지: 원본, 왼쪽 위·가운데·오른쪽 1:1 자르기, 400·300·120px
- 데이터는 지어낸 예시를 쓴다. 실제 뉴스와 실제 인물 이름을 쓰지 않는다.

**알려진 예외 (해소되지 않음):** 글자 크기 종류 관문은 브리프 화면에서 실패한다(목록 11종, 펼친 카드와 긴 사유 13종). 이 크기는 모두 기존 `site/src/styles.css`에 있고, 요청서가 기존 화면을 바꾸지 말라고 정했다. 이번에 더한 정정 표시와 사유, 제보 링크는 12·14px만 쓴다. 사이트 전체를 11·11.5→12px, 12.5→13px, 15.5→16px로 합칠지는 사람이 정한다. 그때까지 이 실패는 남고, 새 요소가 종류를 늘리지 않았는지만 본다.

**사람이 정할 일:** 모든 뉴스 줄에 펼침 표시를 둘지는 기존 화면 변경이라 사람이 정한다.

### 뺀 방향과 이유

점수는 둘씩 비교에서 이긴 확신도의 합이다. 어느 시안도 레퍼런스를 넘지 못했고, 가장 높은 평가가 '비슷'이었다.

| 순위 | 방향 | 점수 | 뺀 이유 |
|---|---|---|---|
| 2 | 쉬운 말 안내 (d5) | 34 | 머리글을 소문자 Nunito로 바꿔 요청서의 '머리글 글자 이름 표시'와 '외부 글꼴 금지'를 어겼다. 폰 한 화면의 뉴스가 적고, 정정 상자가 본문을 밀어낸다. 연한 칸의 아이콘은 라이트 탭에서 윤곽이 사라진다 |
| 3 | 이어지는 선 (d3) | 34 | 계단 모양 아이콘이 T로 읽히지 않고 번개나 상승 그래프로 오해될 수 있다. 산세리프 이름과 장식 점이 일반 서비스처럼 보인다. 한 줄에 주황 요소가 셋이라 정정 줄을 찾기 어렵다. 공유 이미지는 1:1로 자르면 이름이 잘린다 |
| 4 | 잉크 제호 (d1) | 27 | 표시만 보면 세리프 글자가 d2보다 낫다는 평이 여러 건이었지만, 작은 화면(없는 페이지, 메일 안내, 정정 표시)의 다음 행동에서 d2에 졌다. 레퍼런스 대비는 비슷·비슷 |
| 5 | 색인 카드 (d4) | 21 | 둘씩 비교 점수가 낮고 레퍼런스 대비가 비슷·못함이다 |
| 6 | 마침표 (d6) | 13 | 둘씩 비교 점수가 가장 낮고 레퍼런스 대비가 못함·비슷이다 |

d4와 d6의 세부 이유는 순위 기록에 없다. 전체 근거는 `docs/specs/20261031-1840-public-ready/design/explore/round-1/summary.md`, 레퍼런스 원칙은 `docs/specs/20261031-1840-public-ready/design/explore/research/research.md`에 있다.
