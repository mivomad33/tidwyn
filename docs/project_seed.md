## 배경과 목표

매일 받는 뉴스 브리프를, 뉴스를 쌓고 서로 연결해 흐름까지 보여 주는 개인 뉴스 아카이브로 키우는 프로젝트다. 로컬에서 수집하고 공개 정적 사이트로 배포한다.

**제품명.** Tidwyn(타이드윈). tide(흐름)와 twine(엮는 실)을 합친 만든 단어로, 흐름을 따라 사건을 엮는다는 뜻이다.

**현재 방식.** 클라우드 예약 작업이 매일 새벽 3시 45분(KST)에 실행된다. 한국, 세계, IT·AI 세 섹션을 섹션당 5~10개씩 순위를 매겨 정리하고 푸시 메시지로 보낸다. 실행은 약 9분 걸리고 안정적으로 동작한다.

**한계.** 실행마다 기억 없이 새로 시작해서 이어지는 이야기를 따라가지 못한다. 지난 브리프는 실행마다 다른 세션에 흩어져 다시 찾기 어렵다. 뉴스끼리의 관계(같은 사건, 같은 카테고리)도 표현되지 않는다.

**목표.**

- 이전 뉴스와 이어서 브리핑하고, 관련 뉴스를 링크나 카드로 함께 보여 준다
- 모든 뉴스에 카테고리를 붙인다 (예를 들어, 대분류와 소분류 두 단계 카테고리)
- 이슈(예: 미국-이란 갈등)를 매개로 관련 뉴스를 묶고 타임라인으로 보여 준다
- 출처와 관련 기사 링크, 이미지(원문 주소 연결)를 함께 보여 준다
- 쌓인 데이터를 바탕으로 한국 정치경제, 세계 정치경제, AI 업계의 큰 흐름을 리포트한다

## 요구사항

이어지는 이야기와 사건 연결이 핵심이고, 분량과 커버리지는 지금처럼 넓게 유지한다.

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 이어지는 이야기 | 필요 | 지금 방식의 가장 큰 문제 |
| 카테고리 표시 | 필요 | 뉴스 성격을 한눈에 파악 |
| 사건 연결 | 필요 (이슈 단위로 묶기) | 관련 뉴스를 함께, 타임라인으로 보기 |
| 흐름 리포트 | 필요 | 쌓인 데이터로 큰 흐름 파악 |
| 분량 | 현재 수준 유지 (섹션당 5~10개) | 주요 뉴스를 모두 커버하는 것이 더 중요 |
| AI 선별의 한계 | 감수 | 알고 있는 한계로 받아들임 |
| 수집 소요 시간 | 제한 없음 | 오래 걸리면 하루 늦게 봐도 괜찮음 |

## 검토한 방식과 결론

로컬에서 직접 수집하고 공개 정적 사이트로 배포하는 방식을 택했다. 클라우드 예약 작업은 네트워크 제한과 용량 문제 때문에 제외했다.

| 방식 | 장점 | 문제 | 결론 |
| --- | --- | --- | --- |
| 클라우드 예약 + 로컬 DB | 자동 실행 | 실행 시각에 PC와 데스크톱 앱이 켜져 있어야 함 | 제외 |
| 클라우드 예약 + GitHub에 SQLite 파일 커밋 | SQL로 자유롭게 사용 | 1년에 약 100MB로 파일 한도(100MB)에 도달, 바이너리 이력이 수 GB까지 불어남 | 제외 |
| 클라우드 예약 + 텍스트 원본, DB는 빌드 | 용량·이력 문제 없음 | 매번 DB를 다시 만들어야 해서 번거로움 | 제외 |
| 클라우드 예약 + 원격 DB (Supabase 등) | 가장 자유로움, 무료로 충분 | 예약 작업 환경에서 접속 차단 (2026-10-26 테스트: Supabase, Neon, Turso 모두 막힘, GitHub만 허용) | 제외 |
| **로컬에서 직접 실행 + 로컬 DB** | 접속 제한 없음, DB를 자유롭게 사용, 용량 걱정 없음 | 직접 실행 필요, 폰에서 밖에서는 못 봄 | **채택** |
| **+ 공개 정적 사이트 배포** | 폰으로 어디서든 보기 | 빌드 결과물 관리 필요 | **채택** |

용량 추정은 하루 30~40건, 한 건 3~5KB, 검색 인덱스 포함 약 두 배로 계산한 값이다.

## 전체 구조

매일 아침 로컬에서 스킬을 한 번 실행하면 뉴스와 유튜브 영상 수집, 저장, 빌드, 배포가 이어서 진행된다.
로컬 DB가 원본이고, 사이트와 백업은 모두 DB에서 만들어진다. 흐름 리포트도 DB에서 만들어 사이트에 함께 싣는다.

## 데이터 설계

사건 연결의 매개는 이슈(스토리)다. 모든 뉴스는 하나 이상의 이슈에 속하고, 이슈끼리도 관계를 가진다.

| 데이터 | 담는 내용 |
| --- | --- |
| 뉴스 | 날짜, 섹션(한국·세계·IT·AI), 순위, 제목, 한 줄 요약, 본문(배경·핵심·비유·전망), 대분류, 소분류 |
| 이슈 | 이름, 별칭 목록, 대분류·소분류, 시작일, 최근 업데이트일, 상태(진행 중·종료), 지금까지 요약 |
| 뉴스-이슈 연결 | 어떤 뉴스가 어떤 이슈의 몇 번째 전개인지 |
| 이슈 관계 | 관련 이슈 (예: 미국-이란 갈등 ↔ 국제 유가) |
| 인물·기관·국가 | 이름, 별칭, 종류, 한 줄 설명, 등장한 뉴스와 이슈 |
| 일정 | 예정일, 내용, 관련 이슈, 결과(날짜가 지난 뒤 연결된 뉴스) |
| 지표 | 날짜별 값 (환율, 코스피, 미국 기준금리, 유가 등) |
| 용어 | 용어, 쉬운 설명, 처음 나온 뉴스 |
| 출처 | 뉴스별 원문 링크, 매체명, 이미지 주소 |
| 유튜브 영상 | 영상 ID, 지역, 종류(일반·AI), 제목, 채널, 길이, 수집일, 추천 여부, 추천 이유, 요약, 관련 이슈 |
| 일일 브리프 | 날짜별 브리프 전체, 그날의 키워드 |
| 리포트 | 주간·월간 흐름 리포트 |

예시는 다음과 같다.

- 이슈: 미국-이란 갈등 (대분류 국제 / 소분류 중동·안보)
  - 협상 결렬 → 제재 발표 → 유가 급등 순서로 뉴스가 쌓인다
  - 관련 이슈: 국제 유가, 호르무즈 해협

**일관성 규칙.** AI는 실행마다 판단이 조금씩 달라서 같은 사건이 다른 이슈로 중복 생성되기 쉽다. 다음으로 막는다.

- 대분류는 고정 목록 7\~8개 (정치, 경제, 사회, 국제, IT·AI 등)
- 소분류는 정해진 목록에서만 고르고, 새로 만들면 표시를 남긴다
- 수집할 때 기존 이슈 목록과 별칭을 먼저 읽고 붙일 곳을 판단한다
- 주 1회 중복 이슈를 찾아 합친다

## 이해를 돕는 기능

쌓인 뉴스를 빨리 이해하고 흐름을 읽도록 돕는 여섯 가지 기능을 넣는다. 모두 첫 단계부터 데이터를 모은다.

| 기능 | 내용 | 도움이 되는 점 |
| --- | --- | --- |
| 이슈별 지금까지 요약 | 이슈 페이지 맨 위 5줄: 무슨 일인지, 현재 상황, 핵심 인물·국가, 다음에 볼 것. 새 뉴스가 붙을 때마다 고쳐 쓴다 | 오랜만에 보는 이슈도 30초 안에 따라잡기 |
| 앞으로의 일정 | 선거, 금리 결정, 실적 발표, 판결, 출시 등 예정된 일을 달력으로 모은다. 날짜가 지나면 결과 뉴스와 연결 | 다음에 무슨 일이 있는지 알고 뉴스 보기 |
| 주요 지표 기록 | 환율, 코스피, 미국 기준금리, 유가 등을 매일 기록하고 이슈 페이지에 그래프로 붙인다 | 사건의 실제 영향을 숫자로 확인 |
| 데이터에 질문하기 | 프로젝트의 질문용 스킬로 로컬 DB에 자연어로 묻는다 (예: 이란 갈등 지금까지 정리) | 정해진 화면 밖의 각도로 꺼내 보기 |
| 인물·기관·국가 페이지 | 여러 이슈에 걸친 등장 이력을 보여 준다 | 이슈와 다른 두 번째 연결 축 |
| 용어 사전 | 어려운 용어를 한 번 정리하고 뉴스에서 링크한다 | 같은 설명 반복 없이 이해 |

지표는 검색으로 모으므로 틀릴 수 있다. 공식 출처를 우선하고, 확인되지 않은 값은 비워 둔다.

## 유튜브 영상 추천

수집 스킬을 실행할 때 YouTube Data API로 인기 영상을 함께 모으고, 정보와 통찰을 주는 롱폼 영상만 AI가 골라 매일 보여 준다. 지역은 한국과 미국이다.

**일반 추천 영상.**

- 수집: 한국·미국 인기 차트를 페이지 끝까지 전부 받는다 (차트당 최대 약 200개)
- 카테고리: 뉴스·정치, 과학·기술, 그 밖에 차트가 열려 있는 정보성 카테고리(노하우·스타일, 인물·블로그 등, 개발할 때 확인). 교육 차트는 제공되지 않는다
- 뉴스·정치 차트를 받는 이유: YouTube에는 경제·교양 카테고리가 따로 없어 경제·분석 영상이 대부분 이 차트에 섞여 나온다
- 제외: 세로 영상과 4분 미만 영상(숏폼), 이미 추천한 영상, 일반 뉴스 클립·정치 토크·라이브 다시보기(기사로 이미 수집하므로 AI가 선별 단계에서 뺀다)
- 선별: 조회수는 보지 않는다. 제목과 설명으로 후보 약 10개를 먼저 고르고, 자막으로 실제 내용을 확인해 최종 선정한다
- 기준: 유용한 정보, 높은 콘텐츠 품질, 좋은 인사이트와 통찰. 같은 주제는 가장 좋은 1\~2개만, 언어는 한국은 한국어·미국은 영어
- 개수: 지역별 최대 5개. 좋은 영상이 없는 날은 억지로 채우지 않는다

**AI 관련 영상.** 인기 차트에는 AI 영상이 거의 없어서 이것만 검색으로 모은다.

- 고정 키워드: AI, LLM, 인공지능, AI 에이전트, 주요 모델·회사 이름 등
- 최근 48시간 업로드, 롱폼만, 한국어·영어 각각, 관련도 순
- 선별 방식은 일반 추천과 같다. 지역별 최대 3\~5개

**자막 요약.** 선정한 영상은 자막을 받아 내용을 요약해 함께 보여 준다.

- 공식 API로는 남의 영상 자막을 받을 수 없어 비공식 도구(youtube-transcript-api, yt-dlp 등)를 우선 쓴다. 약관상 애매하고 갑자기 막힐 수 있다
- 막히면 Gemini API에 영상 주소를 넣어 요약하는 방식으로 바꾼다 (비용과 조건 확인 필요)
- 공개 사이트이므로 자막 전문은 올리지 않고 요약만 올린다. 미국 영상은 제목과 요약을 한국어로 보여 준다

**API 할당량.** 하루 기본 한도는 1만 단위이고 검색은 하루 100번까지다. 차트 수집은 하루 약 30 단위, AI 검색은 하루 10\~20번이면 충분해서 문제없다.

## 수집 스킬

아침에 Claude Code에서 프로젝트의 브리핑 스킬을 직접 실행하면, 수집부터 배포까지 중간에 멈추지 않고 혼자 끝나야 한다. 시간 제한은 두지 않는다. 오래 걸리면 그날 브리프를 하루 늦게 봐도 된다.

1. 마지막 수집일을 확인하고, 빠진 날짜가 있으면 모두 수집한다 (사흘 만에 실행해도 사흘치가 채워짐)
2. 기존 브리프 기준으로 뉴스를 조사하고 순위를 매긴다 (세 섹션, 섹션당 5\~10개, 배경·핵심·비유·전망, 출처)
3. 기존 이슈 목록을 읽고 각 뉴스를 이슈에 연결하거나 새 이슈를 만든다
4. 대분류·소분류를 붙이고, 등장하는 인물·기관·국가를 뽑아 연결한다
5. 새 뉴스가 붙은 이슈의 지금까지 요약을 고쳐 쓴다
6. 새로 알게 된 예정 일정을 저장하고, 날짜가 지난 일정은 결과 뉴스와 연결한다
7. 주요 지표를 기록한다
8. 새 용어를 사전에 추가하고 뉴스에 링크한다. 이어서 유튜브 인기 차트와 AI 영상을 수집하고, 걸러서 선별한 뒤 자막을 요약한다
9. 로컬 DB에 저장하고, 이어지는 이야기가 있는 뉴스에는 이전 전개를 함께 표시한다
10. 정적 사이트를 빌드해 배포한다
11. DB를 텍스트로 내보내 백업한다

**지켜야 할 것.**

- 실행 중 승인 요청으로 멈추지 않도록 필요한 권한을 프로젝트 설정에 미리 허용한다
- 기사 문장은 그대로 옮기지 않고 바꿔 쓴다. 직접 인용은 15단어 미만, 출처당 한 번
- 확인되지 않은 내용은 해당 섹션 끝에 한 줄로 밝힌다

## 웹 화면과 배포

사이트는 GitHub Pages에 공개로 배포한다. 1GB 한도 안에서 약 10년을 쓸 수 있도록 가볍게 만든다.

**참고 서비스.** 화면의 기능과 UI/UX는 [Kagi News](https://news.kagi.com)를 최대한 참고해 만든다.

**화면 구성.**

- 날짜별 브리프: 기존 브리프처럼 섹션과 순위로 보기
- 이슈 페이지: 맨 위에 지금까지 요약, 그 아래 타임라인, 관련 지표 그래프, 관련 이슈 링크
- 뉴스 카드: 카테고리 표시, 이어지는 이야기의 이전 전개를 간략한 카드로 함께 표시, 용어 사전 링크
- 일정 달력: 다가오는 일정과 지난 일정의 결과
- 인물·기관·국가 페이지: 등장한 이슈와 뉴스 목록
- 지표 페이지: 주요 지표 그래프
- 용어 사전
- 카테고리 필터와 검색
- 출처와 관련 기사 링크, 이미지는 원문 주소만 연결 (파일은 올리지 않음)
- 흐름 리포트 페이지, 추천 영상(날짜별 브리프에 한국·미국·AI 영상을 요약과 함께 표시, 관련 이슈 페이지에도 연결)

**용량 관리.**

- 빌드 결과물은 이력을 남기지 않는다. 배포용 브랜치에 강제 푸시해서 저장소에는 현재 사이트 한 벌만 둔다
- 뉴스마다 HTML을 만들지 않는다. 화면 틀 하나에 데이터를 월별 JSON으로 나눠 필요할 때 불러온다
- 검색은 Pagefind처럼 인덱스를 잘게 나누는 도구를 쓴다
- 예상 크기는 1년에 약 100MB, GitHub Pages 사이트 한도는 1GB

공개 사이트이므로 기사 이미지 파일을 직접 올리면 재배포가 되어 저작권 문제가 생긴다. 이미지는 원문 주소 연결로만 보여 준다.

## 흐름 리포트

큰 흐름은 하루치로는 의미가 약해서, 매일이 아니라 주간과 월간으로 만든다. 데이터가 한 달 정도 쌓인 뒤부터 쓸 만한 리포트가 나온다.

- 대상: 한국 정치경제, 세계 정치경제, AI 업계
- 주간 리포트: 한 주 동안 크게 움직인 이슈, 새로 생긴 이슈, 끝난 이슈
- 월간 리포트: 한 달 흐름 요약과 지금 어디로 가고 있는지
- 주요 지표의 변화와 다가오는 일정을 근거로 함께 쓴다
- 근거가 된 이슈와 뉴스로 링크한다
