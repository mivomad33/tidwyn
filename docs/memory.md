# 기록

다른 문서 주제에 속하지 않지만 이후 세션에서도 알아야 할 내용을 적는다.

## 보류된 이슈

- 2026-10-28: Claude Code의 검색 도구로 Reuters·AP 기사의 원문 주소를 거의 찾지 못한다(검색 도구가 도메인을 거부하거나 결과에 나오지 않음). 그래서 이 매체들은 후보 목록에서 "그날 중요한 뉴스" 신호로만 쓰이고, 대표 출처는 주요 일간지·방송·IT 매체로 채워진다. 1.5단계 끝에 사용자가 "꼭 할 일은 아니다"로 판단했다. 구글 뉴스 중간 주소를 원문으로 풀기는 구글 내부 요청을 흉내 내야 해서 하지 않았다.
- 2026-10-29: 지금은 사용자가 매일 직접 `/brief`를 돌린다. 다른 사람에게 알리려면 이것이 걸리므로, **단계 구현이 다 끝난 뒤** 맥에서 Claude Code 예약 실행(새벽 무인 `/brief`)을 건다(사용자 결정). 맥을 켜 두는 전기료가 한 달 수백 원이라 클라우드 서버(한 달 7천~9천 원)보다 싸고 확실하다. 할 때 챙길 것: 전원 연결 시 잠자기 방지, 운영용 main 전용 폴더(D14는 main 체크아웃·변경 없음일 때만 실행하므로 작업 브랜치가 열려 있으면 거부됨, D14 바꾸기 필요), 실패 시 폰 알림. D14를 바꾸므로 작은 단계로 명세서를 쓰고 구현한다.

## 결정

- 2026-10-28: Claude Code의 웹 페이지 읽기 도구(WebFetch)가 Reuters, AP, 연합뉴스, BBC 페이지를 읽지 못하는 문제는 1.5단계에서 이렇게 정했다: `feeds` 명령이 RSS 후보 목록(공식 RSS + 구글 뉴스 RSS)을 만들고, Claude는 그 제목·요약·발행 시각을 근거로 쓰며 원문 주소는 웹 검색으로 찾는다. 막힌 매체 페이지는 curl 등으로 읽지 않는다(1.5단계 명세서 R1·R4). 구글 뉴스 robots.txt가 AI 봇을 막는 것은 알고 감수한 결정이다(사용자 결정).
- 2026-10-28: 3단계 호스팅은 GitHub Pages 대신 Vercel(`tidwyn.vercel.app`)로 정했다(사용자 결정, 3단계 명세서 P1, plan D2 바뀜). 무료 플랜의 CLI 업로드 한도(총 100MB, 파일 15,000개)가 GitHub Pages(1GB)보다 작다는 것을 알고 고른 것이다. 한도에 가까워지면 Pro로 올리거나 옮긴다.
- 2026-10-29: Vercel 화면 작업(Claude in Chrome)은 Vercel에 `mivomad33`(팀 `mivomad33`, Hobby)으로 로그인된 Chrome 프로필로 한다(사용자 결정). Vercel CLI의 사용자 이름은 `mivomad33-8917`이고 팀(scope)은 `mivomad33`이다(같은 계정). 연결된 다른 Chrome 프로필은 다른 Vercel 팀(`inhan-s-projects`)으로 로그인되어 있어 쓰지 않는다. 화면의 팀 이름이 `mivomad33`인지 확인하고 작업한다.
- 2026-10-29: 원본 저장소(`mivomad33/tidwyn`)는 3단계 구현 중에는 비공개로 push만 하고, 3단계 머지 뒤 머지한 세션이 공개 전 점검을 통과시킨 뒤 공개로 바꾼다(사용자 결정, 3단계 명세서 P14). README·라이선스 없이 공개되는 기간을 없애기 위해서다.
- 2026-10-29: 명세서 폴더의 화면 확인 스크린샷(`docs/specs/*/screenshots/`)은 git에 넣지 않고 로컬에만 둔다(`.gitignore`). 실제 데이터로 찍으면 공개 저장소에 실제 이름·기사 사진이 실리기 때문이다(4단계 review-done, 사용자 결정). 3단계 스크린샷은 이미 공개 main에 있어 그대로 두었다.

- 2026-10-29: 모바일 하이브리드 앱은 만들지 않고 웹으로 간다. 홈 화면 추가 수준의 PWA도 지금은 하지 않는다(사용자 결정). 읽기 전용 사이트라 기기 기능이 필요 없고, 스토어 심사(Apple 4.2 최소 기능, 5.2 지식재산)와 비용·배포 흐름 부담이 크기 때문이다. 나중에 PWA를 하면 아이폰 홈 화면 앱은 Safari와 로컬 스토리지를 따로 써서 읽은 기록이 넘어가지 않는다는 점을 고려한다. 푸시 알림은 서버가 필요해 순수 정적 구조를 깨므로 따로 정한다.

- 2026-10-29: `/browser-check` 점검 목록 파일은 `.test-data/browser-check/`에 둔다(git이 무시해 커밋하지 않는다. 저장소가 공개라서다, 사용자 결정). 점검은 지어낸 데이터(`site/dev/fixtures.ts`, 5단계 화면은 `--schedules N`)로 빌드한 결과물을 `site/dev/serve.ts`로 E2E와 다른 포트에 띄워 앱 안 브라우저로 본다. 사이트는 정적이라 DB·외부 호출이 없고, 로컬 주소에서는 방문 통계를 보내지 않는다. 자동 테스트(`pnpm verify`, `pnpm e2e`)는 임시 폴더와 `.test-data/e2e`(포트 4319)만 써서 점검 환경과 겹치지 않는다.
