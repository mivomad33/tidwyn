## 사용자가 할 일

### 마지막 확인(명세서 5장)

1. **멈추지 않는 시험 실행(4.6-1, 4.1-8)**
   - 작업 브랜치를 체크아웃한 채로 Claude Code를 권한 건너뛰기 모드로 연다.
   - `/brief test`를 실행한다.
   - 시작할 때 실행 설정에 "모드: 시험 모드", 시험 데이터 폴더(`.test-data/<시각>/`), 작업 브랜치, "백업 저장소: 커밋 안 함"이 보이는지 본다.
   - 묻지 않고 끝까지 진행되는지 본다.
   - 끝나면 프로젝트에 `data/` 폴더가 없고, `git branch --list data`가 비어 있는지 본다.
2. **실행 조건(4.1-2)**
   - 작업 브랜치를 체크아웃한 채로 `/brief`(시험 모드 아님)를 실행한다.
   - "실행 조건이 맞지 않아 아무것도 쓰지 않고 멈춘다"와 이유(main이 아님), 할 일이 나오고 그대로 끝나는지 본다.
   - `data/`가 생기지 않았는지 본다.
3. **브리프 내용과 대화창 출력(4.1-7, 4.4-2)**
   - 1번 실행에서 대화창에 나온 결과와 `.test-data/<시각>/briefs/` 아래 마크다운을 읽는다.
   - 형식(S1)과 내용 품질이 괜찮은지 본다.
   - 시험 데이터 폴더(`.test-data/`)는 다 본 뒤 직접 지워도 된다.
4. **머지 뒤 첫 실제 실행**
   - 머지한 뒤 메인 작업 폴더에서 main을 체크아웃하고 변경 사항이 없는 상태로 `/brief`를 실행한다.
   - 이때 `data/`와 `data` 브랜치가 처음 생긴다.

`/brief`가 프로젝트 스킬 대신 Claude Code 내장 명령(brief-only 모드)으로 열리면 이름이 겹친 것이다. 대처는 [운영 문서](../../operations.md)의 "`/brief`가 스킬 대신 다른 것으로 열릴 때"에 있다.

## 재량으로 정한 것과 이유

- **런타임 의존성 없음:**
  - SQLite는 Node 24 내장 `node:sqlite`를 쓰고, TypeScript는 Node의 타입 제거 실행으로 빌드 없이 돈다.
  - 그래서 실행 조건 확인과 복원이 의존성 설치 없이 돈다(4.1-2, 4.5-3의 요구).
  - 개발 의존성(TypeScript 6.0, ESLint, typescript-eslint)만 pnpm으로 설치한다. TypeScript 7.0은 typescript-eslint의 지원 범위 밖이라 6.0으로 고정했다.
- **테스트 도구:** Node 내장 `node:test`.
- **명령 구성:** `start`가 4.1-1의 1~6단계를 순서대로 한다. 그래서 스킬은 시작 명령 하나 뒤에 날짜별 `validate`와 `save`를 반복하고, 끝에 `backup`과 `summary`를 부르면 된다.
- **스킬과 스크립트 사이의 데이터:**
  - Claude는 `<데이터 폴더>/work/<날짜>.json`에 브리프 데이터를 쓴다.
  - 실행 기록 `<데이터 폴더>/runs/<시각>.json`이 결과를 모은다.
  - 모두 데이터 폴더 안이라 실행 조건(변경 사항 없음)에 걸리지 않는다.
- **브리프 데이터:** JSON 항목 이름은 영어(`whyItMatters` 등)로 하고, 모르는 항목은 거부한다. 오타 난 항목이 조용히 빠지는 것을 막기 위해서다.
- **백업 커밋:**
  - worktree 없이 임시 인덱스와 git 저수준 명령으로 커밋한다.
  - 작업 트리와 HEAD를 건드리지 않고, 끊긴 실행이 남긴 작업 폴더 문제도 생기지 않는다.
  - `data` 브랜치 트리는 매번 백업 파일만으로 새로 만든다.
- **백업 형식:** `meta.json`(형식 버전 1, 첫 수집일)과 `YYYY-MM.json`(형식 버전, 달, 저장된 브리프).
- **복원:** 임시 파일에 다 만든 뒤 옮긴다. 기본 출력은 실제 데이터 폴더의 DB이고, 이미 있으면 `--force`가 필요하다.
- **경로 비교:** 실제 경로로 풀고 대소문자를 무시한다. 대소문자를 구분하는 파일 시스템에서는 다른 폴더도 실제 데이터 폴더로 볼 수 있지만, 실제 DB를 지키는 쪽(더 엄격한 쪽)이다.
- **시험 데이터 폴더:** 지금 작업 트리의 `.test-data/<KST 시각>/`(git이 무시).
- **환경 변수:** `TIDWYN_DATA_DIR`, `TIDWYN_BACKUP_REPO`.
- **발행일:** `YYYY-MM-DD`로 받는다.
- **스킬 문서 보완:** 4.1-7 뒤에 "4위 이하도 항목을 비우지 않는다"를 더했고, 서브에이전트가 지시가 담긴 페이지를 메인에 보고하게 했다.

   - 이번에는 검토를 통과한 뒤 명세서 브랜치를 main에 머지하고 지워, 명세서가 지정한 작업 브랜치가 없었다.
   - 제안 문장: "명세서가 작업 브랜치를 지정하면, 그 브랜치가 이미 머지·삭제됐을 때 어떻게 할지(같은 이름으로 main에서 새로 만든다 등)를 함께 적는다."
2. **외부 자료에 기대는 요구사항(빠뜨리기 쉬운 것, 공통):**
   - 조사 도구가 우선 출처(통신사)를 읽지 못해, 명세서의 출처 우선순위를 그대로 지킬 수 없었다.
   - 제안 문장: "웹 검색·페이지 읽기로 자료를 모으는 요구사항은, 우선 출처를 도구로 읽을 수 없을 때의 처리(대체 출처, 확인 수준 낮추기, 표시)를 정한다."
3. **형식 정의의 분량 지시:**
   - "4위 이하는 짧게"를 조사하는 AI가 "항목을 비워도 된다"로 읽었다. 검사가 잡았지만 한 번 고쳐야 했다.
   - 제안 문장: "분량을 줄이라는 지시는 생략해도 되는 항목과 구분해 적는다(줄이는 것이지 빼는 것이 아님을 밝힌다)."
   - 원칙 7(요구사항을 한 가지로 읽히게 쓰기)에 합칠 수 있다.
