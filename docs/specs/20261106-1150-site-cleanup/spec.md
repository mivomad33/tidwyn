# U1단계 명세서: 사이트 전체 정리

- 작성일: 2026-11-06
- 요약: 모든 화면의 글자 크기를 여섯 단계 토큰으로 합치고, 같은 역할의 칩·고르기 부품·글 링크·구역 제목·빈 상태·앱 밖 표시·날짜 표기를 공통 부품 하나씩으로 맞추고, '‹ 브리프'가 들어온 브리프의 날짜·탭(바로 앞 기록이면 펼친 카드·스크롤까지)으로 돌아가게 한다.
- 종류: 변경 건 (공개 사이트의 앱 화면, 정적 HTML, 디자인 기준 문서를 바꾼다. 데이터·수집·DB는 바꾸지 않는다)
- 단계: [`docs/plan.md`](../../plan.md)의 U1. UI/UX 감사 단계(U1·U2)의 첫 단계다. 뒤 단계 U2가 이 단계로 바뀐 크기와 배치 위에서 브리프 위계와 누를 곳을 맞춘다.
- 이 문서는 기획과 요구사항만 담는다. 설계와 작업 계획은 구현하는 AI가 정한다.
- 공개 여부: 원본 저장소와 사이트는 이미 공개다. 바뀐 화면은 머지 뒤 다음 `/brief`의 배포로 공개된다.

## 1. 목표

- **지금 상태:** UI/UX 감사(2026-11-06, [보고서](../../ui-ux-audit/20261106-1025/report.md))가 원인 10개를 찾았고, 사용자가 기준 수정을 모두 승인했다. 승인한 규칙은 이미 [`docs/design.md`](../../design.md)의 "글자 크기"와 "위계와 상호작용 규칙"에 있지만 코드는 그대로다. 2026-11-06 60aab61에서 감사와 같은 조건으로 다시 잰 값은 감사 값과 같다(감사 뒤 `site/`가 바뀌지 않았다).
  - 글자 크기: `site/src/styles.css`의 font-size 선언 137개가 모두 px 직접 값이고 19가지 값을 쓴다. 정상 데이터 375 라이트 전체 페이지 기준 글자 크기 종류가 브리프 14·빌더 탭 15·이슈 페이지 10·영상 페이지 9·지표 페이지 10·일정 9종 등이고, 관문 '글자 크기 종류 6종 이하'를 18개 주소 중 14개가 넘는다. 브리프의 글자 조합(`styles.typeCombos`)은 29개다.
  - 같은 역할 부품: 알약 칩 한 모양에 동작 3가지, 사각 표시 한 모양에 동작 3가지, 고르기 부품 모양 7종(일정 한 화면에 선택 표시 셋), 이동 글 링크 모양 8종·구역 제목 모양 6종(사이트 전체), 빈 상태 모양 3종, 앱 밖 링크 중 출처 칩만 ↗(감사 `inventory.md` P1-10~P1-17, P1-26~P1-37, P1-42, P1-44).
  - 날짜: 표기 11가지, 이슈 목록·이슈 페이지가 'YYYY-MM-DD'를 화면에 낸다. 지표 변화가 상자는 퍼센트만, 카드·지표 페이지는 값과 퍼센트다(P1-45~P1-47).
  - 되돌아가기: '‹ 브리프'가 영상 페이지에서만 보던 날짜로 가고 나머지는 최근 날짜로 간다. 이슈 페이지에는 브리프로 가는 길이 없다. 주소 해시로 연 탭은 기억되지 않는다. '‹ 브리프'를 누르면 방문 기록이 하나 쌓여, 폰에서 뒤로 밀면 방금 나온 페이지가 다시 열린다(P1-22, P1-41, P1-48, P1-53, P1-56, P1-63, P2-84).
- **바꾸려는 이유:** 글자 크기와 같은 역할 부품을 정리해 화면의 위계를 또렷하게 하고, 누르기 전에 결과를 알고, 보던 브리프로 돌아오게 한다(plan U1 목적).
- **쓰는 사람:** 매일 폰과 브라우저로 브리프를 보는 프로젝트 주인과, 검색으로 들어오는 공개 방문자.
- **충분한 수준:** 모든 화면이 여섯 단계 토큰만 쓰고 글자 크기 종류 관문을 통과한다. 칩·고르기 부품·글 링크·구역 제목·빈 상태·날짜 표기가 "위계와 상호작용 규칙"대로 공통 부품 하나씩으로 그려지고, '‹ 브리프'가 들어온 날짜·탭으로 간다(plan U1 끝난 상태). 감사가 넘긴 과제 셋을 처음 쓰는 사람이 헤매지 않고 해낸다.

## 2. 확정된 결정과 제약

### 2.1 계획과 감사에서 가져온 결정 (다시 묻지 않는다)

- **감사 승인(2026-11-06, 사용자):** 원인 C2·C3·C4·C5·C9·C10의 규칙은 [`docs/design.md`](../../design.md)의 "글자 크기"와 "위계와 상호작용 규칙" 문장 그대로다. 글자 크기는 22/19/17/16/14/12px 여섯 단계이고 묶는 규칙(12.5px 이하→12, 13~14.5→14, 15~16→16, 18→17, 21→22)도 그 표대로다. 처음 권한 5단계(목록 제목 19px)는 사용자가 "기사 제목이 너무 크다"고 해 뺐다. 2026-11-01의 "R11 글자 크기 그대로"는 뒤집혔다. 아이콘 글자 예외 문장만 S9로 바꾼다.
- **U1·U2 나누기(2026-11-06, 사용자):** C1(브리프 첫 화면 위계), C6(빌더·수요 항목 접기), C8(거르기 칩 이름·건수, '모든 분야'), C7(폰 누를 곳 44px)은 U2다.
- **기준 문서 안에서 지키는 결정:** 뉴스 줄에 펼침 표시를 두지 않는다(design.md "사람이 정할 일", C3도 바꾸지 않음). YouTube 약관 링크와 영상 제목 원문은 줄이거나 감추지 않는다(YouTube API 정책). 정정 표시는 일반 글자색이다.
- **디자인:** 새 방향이 없다. 화면은 `docs/design.md`를 따른다. 기준에 없는 부품(`Segmented` 등)은 기준의 토큰과 "위계와 상호작용 규칙"으로 만든다(`write-spec` 5장, 시안 없음).
- **운영(D14, 2026-10-31 memory):** 매일 06시경 예약 `/brief`가 메인 폴더 main의 깨끗한 작업 트리로 돈다. 작업은 메인 폴더 밖 worktree에서 한다. CI는 없다.

### 4.1 글자 크기 (C2)

1. **토큰:** `site/src/styles.css`에 글자 크기 토큰 여섯 개(`--fs-*`, 22/19/17/16/14/12px)를 두고, 모든 font-size 선언(정적 전용 규칙, 그래프 축, 아이콘 글자 포함)이 이 토큰만 쓴다(`inherit` 등 값을 정하지 않는 키워드는 된다). 기존 값은 design.md "글자 크기"의 묶는 규칙대로 바꾼다. 규칙에 없는 값(달 이동 ‹ › 20px 등)은 가까운 단계로 묶는다. 아이콘 글자(‹ › ▾ ▴ ✓ ↗)도 4.1-2 관문에서 세므로 단계 밖 값을 두지 않는다(S9). design.md의 "아이콘 글자는 이 단계 밖이어도 된다"는 이에 맞게 고친다(4.5-1).
   - 확인: 단위 테스트가 `styles.css`를 읽어 font-size 선언이 토큰(또는 값을 정하지 않는 키워드)만 쓰는지, 토큰 값이 여섯 개 그대로인지 본다. 일부러 `font-size: 15px`를 넣은 CSS로 이 테스트가 실패하는 것을 본다.
2. **관문:** 화면 18곳이 375·1280 라이트 전체 페이지에서 글자 크기 종류 6종 이하다(아이콘 글자 포함, 지금 브리프 14·빌더 15·이슈 페이지 10·영상 페이지 9·일정 9종 등). 펼친 카드(첫 뉴스 줄을 누른 상태), 많은 데이터, 빈 상태, 오류 상태의 브리프와 정적 HTML 화면(브리프, 날짜 목록, 용어 사전, 지표, 없는 페이지, 앱 전용 틀)도 같다.
   - 확인: 측정 도구로 재서 결과 보고서에 화면별 값(전·후)을 적는다. 측정 데이터 E2E 한 묶음이 375 폭에서 화면 18곳과 펼친 카드의 보이는 글자 요소의 계산된 font-size 종류가 6개 이하인지 보고, 정적 HTML 화면은 자바스크립트를 끈 E2E로 같은 것을 본다.

### 4.2 같은 역할 부품의 모양과 동작 (C3, C5, C10)

1. **알약 칩:** 알약 모양(모서리 999px)은 다른 화면으로 가는 칩과 거르기 칩(`ChipFilter`)에만 쓴다. 제자리에서 여는 용어 칩은 끝에 ▾를 둔다. 브리프 위 키워드(`.kw span`)는 알약·면 없이 글자로 쓴다. 같은 화면 안 이동 칩과 인물 목록 종류 칩은 S10대로 한다.
   - 확인: E2E가 키워드에 테두리·바탕·999px 모서리가 없는지, 용어 칩 끝에 ▾가 있고 누르면 제자리에서 설명이 열리는지, 다른 화면으로 가는 알약 칩(링크)을 누르면 주소가 바뀌고 거르기 칩(`ChipFilter`, `ToggleChip`, 인물 목록 종류 칩)은 다른 화면으로 가지 않고(경로 그대로) `aria-pressed`가 바뀌는지 본다. 인물 목록 종류 칩은 지금처럼 `?kind=`를 바꾸고(S10, `test/e2e/stage4.spec.ts`의 기존 단언 유지), 일정 '목록|달력' 등 기존 주소 동작도 그대로다.
2. **사각 표시:** 영상 묶음 표시(`.tag`)와 '전체' 탭 뉴스 줄의 섹션 표시(`.sec`)는 면·테두리 없이 글자로 쓴다. 일정 결과 '결과: …'(`a.res.ok`)와 '연기 → … ›'처럼 다른 화면으로 가는 결과는 글 링크 모양(4.2-5)이고, 누를 수 없는 결과('취소')는 글자다. 사각 면은 '어제에 이어' 배지 하나만 남는다(S3).
   - 이 항목의 대상은 줄 안의 작은 표시·태그(배지, 묶음·섹션 표시, 결과 표시)다. 안내 상자 `.notice`, 주 버튼 `.btn`, 본문으로 건너뛰기 `.skip`, 일정 강조 `.ev.hl`, 열린 용어 칩, 정정 표시는 해당하지 않고 바꾸지 않는다.
   - 확인: E2E가 각 요소의 계산된 배경·테두리를 본다. 측정 데이터 375의 화면 18곳과 펼친 카드에서, 줄 안의 표시(`.badge`, `.tag`, `.sec`, `.res`, `.kw span`과 클래스가 바뀌면 같은 역할의 요소) 중 배경이 강조 바탕(`--accentbg`)이거나 모서리가 있는 테두리 면을 가진 것이 '어제에 이어' 배지뿐인지 E2E로 센다. 칩·입력·카드·상자·고르기 부품과 위 제외 대상은 세지 않는다.
3. **닫힌 뉴스 줄:** 줄 전체가 펼침 버튼인 닫힌 뉴스 줄에는 이슈 이름('이어지는 이야기: …')을 쓰지 않는다. 이슈로 가는 링크는 펼친 카드에만 있다. 짧은 소식의 이슈 이름은 이슈 페이지로 가는 글 링크(4.2-5)다. 같은 이슈 이름은 어느 자리에서나 이슈 페이지로 간다. 버튼 안에 링크를 넣지 않는다.
   - 확인: E2E가 닫힌 줄에 이슈 이름이 없고 펼친 카드에서 이슈 링크를 누르면 `/issues/<id>`로 가는지 본다. axe(버튼 안 대화형 요소 없음)는 `design-check` 객관 관문.
4. **고르기 부품:** 둘~셋 중 하나를 고르는 구분은 공통 `Segmented` 하나(테두리 묶음, 선택 = 상자 바탕 + 700 글자색, 직접 구현, S7)로 만든다. 일정 '목록|달력', '다가오는 일정|지난 일정', 지표 기간 '1개월|1년|5년', 브리프 상자 탭 '이번 주 일정|지표'가 이것을 쓴다. 선택 표시의 검은 면은 거르기 칩에만 남는다. 달력의 날짜 고르기(`button.d`)는 구분이 아니라 그대로 두되, 고른 날의 표시는 검은 면 대신 `Segmented`와 같은 선택 표시를 쓴다. 저장 키(`tidwyn.scheduleView`, `tidwyn.briefBoxTab`)와 키보드 조작(상자 탭의 화살표 이동)은 지금처럼 동작한다.
   - 확인: 단위 테스트가 네 곳이 같은 공통 부품을 쓰는지 본다. 측정 데이터 일정 375 라이트에서 '목록|달력'과 '다가오는 일정|지난 일정'의 선택 버튼 `background-color`가 같다(지금 `rgb(29,29,31)`과 `rgb(245,245,247)`로 다름, 측정 도구나 E2E). 기존 저장·키보드 E2E가 통과한다.
5. **글 링크:** 다른 화면으로 가는 글 링크(앱 안 `a` 중 목록 행·칩·버튼·머리글이 아닌 것)는 `.text-link` 한 모양(흐린 글자색 + 밑줄 offset 2px, S6)이다. 굵기·색·밑줄이 같고 크기만 글자 크기 단계 안에서 다르다. 앱 밖 링크(4.2-8)의 약관 링크도 같은 모양에 ↗를 더한다. 다른 화면으로 가는 글 링크는 모두 밑줄을 두고, 끝 표시 ›는 더해도 된다. 일정 화면의 일정 이름(`a.t`)은 줄의 제목이라 아래 제목 자리 링크처럼 글자색·굵기를 두고, 다른 화면으로 가므로 밑줄만 더한다(C3 '일정 이름 포함'). 4.2-5 확인의 한 모양 조합에는 넣지 않고, E2E가 `a.t`에 밑줄이 있는지 따로 본다. 제목 자리의 링크(영상 페이지 h1의 영상 제목, 빌더 항목 이름 `.bname-l`, 이슈 페이지 지표 그래프 머리의 지표 이름 `.igh a`)는 항목 제목이라 글 링크가 아니다(앱 밖이면 4.2-8의 ↗만 따른다). 영상 줄의 '요약 보기 ▾'(제자리에서 여는 버튼)는 '구간별로 보기 ›'와 같은 색(흐린 글자색)·굵기를 쓰고 밑줄 없이 끝 표시 ▾로 구분한다. 영상 페이지의 구간 시각(`.vsectime`)은 `::after`로 줄 전체를 덮는 목록 행 링크라 글 링크가 아니고 지금 모양(강조색 밑줄)을 유지한다(4.2-8의 ↗만 더한다). 지금 '일정 전체 ›', '구간별로 보기', 약관 링크, `.bintro-l`, `.gl a`, `a.res`, `.quiet`, '이어지는 이야기 · … ›' 등이 서로 다르다(8종).
   - 확인: E2E가 측정 데이터 375의 화면 18곳과 펼친 카드에서 선택자 `.text-link, .quiet, .bintro-l, .breminder, .vrec, .gl a, a.res`와 `main a` 중 글이 `›`로 끝나는 것(목록 행·칩·버튼·제목 자리 링크(영상 h1, `.bname-l`, `.igh a`)·일정 이름 `a.t` 제외)의 (font-weight, color, text-decoration-line) 조합이 사이트 전체에서 1종이고 그 색이 흐린 글자색(`--muted`)인지 센다(조합에 크기는 넣지 않는다. 클래스 이름이 바뀌면 같은 역할의 요소로 바꿔 센다).
6. **구역 제목:** 구역 제목은 `.h` 한 모양(지금 펼친 카드 `.h`의 모양을 단계로 묶은 12px 700 흐린 글자색, design.md 글자 크기 표의 '칸 제목')이다. 이슈·인물·지표 h2, 펼친 카드 h4, 일정 '달 중'·날짜 머리(`h3.dh`), 짧은 소식·검색 묶음, 용어 사전 색인(`h2.idx`), 빌더 묶음 제목(`h2.bgroup-h`), 소개·처리방침·영상 페이지의 `.h`가 같은 모양이 된다. 페이지 제목(`h1`, 22px 800)과 항목 제목(빌더 항목·구간 제목)은 구역 제목이 아니다. 정적 HTML 브리프의 섹션 제목은 design.md "정적 페이지" 규칙(17px 700 글자색, 윗선)을 따른다.
   - 확인: E2E가 화면 18곳과 펼친 카드에서 선택자 `h2.h, h3.h, h4.h, .h, .list-h, h3.dh, h2.idx, .bgroup-h`(클래스가 바뀌면 같은 역할의 요소)의 (font-size, font-weight, color) 조합이 앱 전체에서 1종인지 센다(지금 6종).
7. **빈 상태:** 빈 상태는 공통 `Empty`(빌더·수요 묶음 안은 기준의 변형 하나)로 그린다. 정적 HTML의 빈 상태도 같은 모양(같은 클래스·구조)이다. 문구는 '이 날에는 …'처럼 띄어 쓴다(지금 '이날은 …', '이날의 …'). 띄어쓰기는 빈 상태뿐 아니라 화면에 나오는 오류·안내 문구(`site/src/lib/builder.ts`, `site/src/lib/demand.ts` 등)의 '이날'에도 같게 적용한다. 2026-11-02 사용자가 정한 '이날 새 변화는 받지 못했다.'는 띄어쓰기만 바꾼다('이 날 새 변화는 받지 못했다.', S11). `docs/memory.md` 2026-11-02 항목에는 이미 덧붙였다(다시 하지 않는다). 달력의 날 빈 상태도 같은 부품이다.
   - 확인: 단위 테스트(`site/src` 화면 문구와 정적 HTML 결과물에 '이날'이 없음, 정적 HTML의 빈 상태가 앱과 같은 클래스), E2E(빈 상태 데이터의 브리프·일정·이슈 목록·검색, 빌더·수요 0건 날).
8. **앱 밖 링크:** 새 탭으로 여는 앱 밖 링크(출처 칩, 영상 줄, 영상 페이지 제목, 구간 시각, 약관 링크)는 끝에 보이는 ↗를 둔다. 메일 링크(`mailto:`)는 새 탭이 아니라 ↗를 두지 않는다. YouTube 약관 링크와 영상 제목 원문은 줄이거나 감추지 않는다.
   - 확인: E2E가 화면 18곳에서 `target=_blank`인 모든 링크 중 보이는 글이 있는 것의 보이는 글(또는 가상 요소)에 ↗가 있는지 본다. 보이는 글이 없는 썸네일 링크(영상 줄·영상 페이지의 썸네일, `aria-hidden` 포함)는 빼고, 같은 곳으로 가는 글 링크가 ↗를 갖는지로 본다. 정적 HTML도 단위 테스트로 본다.
9. **같은 도착의 이름:** 링크 글은 도착 화면의 이름을 쓴다. `/`로 가는 링크(메뉴, 바닥글, 없는 페이지 주 버튼 등)는 '최근 브리프' 한 이름이다(되돌아가기 '‹ 브리프'는 4.4의 규칙이고 도착이 들어온 브리프다). 되돌아가기 글('‹ 이슈', '‹ 지표', '‹ 인물·기관·국가' 등)은 좁은 머리글 자리라 짧은 이름을 쓰고 이 항목에서 뺀다. 머리글의 이름 'Tidwyn'(`.brand`)은 브랜드 표시라 그대로 두고 이 항목에서 뺀다. 머리 날짜는 날짜 목록으로 간다는 것이 읽히는 이름을 갖는다. 화면 읽기 이름은 지금처럼 '날짜 목록'을 담고, 보이는 글은 날짜 그대로 두되 다른 화면으로 가는 표시(끝 › 등, 모양은 AI 재량)를 둔다. 이슈 영상의 'M월 D일 추천'은 그날 브리프의 영상 탭으로 간다는 글('M월 D일 브리프 영상' 등)로 쓴다.
   - 확인: E2E가 화면 18곳(앱과 정적 HTML)에서 `href="/"`인 링크의 보이는 글이 모두 '최근 브리프'인지(되돌아가기와 `.brand` 제외), 머리 날짜 링크의 접근 이름에 '날짜'가 들고 보이는 글에 이동 표시가 있는지, 영상이 있는 이슈 페이지(측정 데이터의 `/issues/18`·`/issues/3` 등, `/issues/28`에는 영상이 없다)의 영상 추천 링크 글에 '브리프'가 들고 그 날짜의 `#videos`로 가는지 본다.

### 4.3 날짜 표기 (C9)

1. **날짜 글:** 화면 글의 날짜는 'M월 D일'(요일이 필요하면 'M월 D일 (요일)'), 해가 다르면 'YYYY년 M월 D일'이다. '해가 다르면'의 기준 해는 기존 `shortDate(date, refYear)`처럼 그 화면이 정하는 기준 해(최근 브리프 날짜의 해 등)다. 줄 앞 날짜 칸·칩·그래프 축처럼 좁은 자리만 'MM-DD'다. 좁은 자리에서 해가 다르면 해를 알 수 있게 쓰되 'YYYY-MM-DD'는 쓰지 않는다(모양은 AI 재량). 지표 그래프 축이 해를 넘으면 해를 알 수 있게 쓴다. 이슈 목록 '최근 …', 이슈 페이지 '… 시작 · 최근 …'은 날짜 글이다(지금 'YYYY-MM-DD'·두 형식 섞임).
   - 확인: 단위 테스트가 날짜 표기 함수(앱·정적 공통)의 같은 해·다른 해 입력을 본다. 같은 데이터(이슈의 최근 날짜, 일정 날짜)가 화면마다 같은 함수를 거치는지 단위 테스트로 본다.
2. **지표 변화:** 지표 변화는 어느 화면이든 같은 단위(값 변화와 %, 예 '▼23.37 (0.87%)')다. 지금 상자의 좁은 표기는 퍼센트만이다. 퍼센트를 낼 수 없으면(앞 값이 0) 값 변화만 쓴다. %p 지표는 지금 규칙 그대로다.
   - 확인: 단위 테스트(`changeLabel`의 좁은 자리와 넓은 자리가 같은 단위), E2E(상자 지표 칸에 값 변화와 %가 함께 보임).
3. **다시 흩어지지 않음(S4):** 화면 18곳(앱, 측정 데이터 375)의 보이는 글과 정적 HTML 결과물의 본문 글에 'YYYY-MM-DD' 모양 날짜가 없다(주소·`datetime` 속성·메타 태그는 제외). 대상은 사이트가 쓰는 글(날짜 표기 함수를 거친 글과 화면 문구)이고, 데이터에서 온 이름·제목(저장소·제품 이름, 뉴스·영상 제목, 출처 이름. 예: 지어낸 빌더 저장소 이름 `fake-owner-2026-10-25-…`)은 뺀다. 정적 HTML 검사는 이 제외를 지키되 날짜 표기가 나오는 곳을 빠짐없이 덮는다.
   - 확인: E2E(앱 보이는 글)와 단위 테스트(빌드한 정적 HTML의 본문 글). 일부러 'YYYY-MM-DD'를 화면에 내게 바꿔 두 검사가 실패하는 것을 본다.

### 4.4 되돌아가기와 돌아올 때의 상태 (C4, S1, S2)

1. **'‹ 브리프'의 도착:** 브리프가 아닌 화면의 되돌아가기 '‹ 브리프'는 들어온 브리프의 날짜와 탭으로 간다. 들어온 브리프를 모르면(주소로 바로 연 경우, 새 브라우저 탭 등) 최근 날짜의 브리프다. 바로 앞 방문 기록이 들어온 그 브리프면 기록을 되돌린다(S1, 영상 페이지 포함). 그래서 펼친 카드·탭·고른 칩(S12)·스크롤이 되살아나고, 누른 뒤 폰·브라우저 뒤로를 눌러도 방금 나온 화면이 다시 열리지 않는다. 바로 앞 기록이 아니면 새 기록으로 이동한다.
   - **영상 페이지:** 바로 앞 기록이 그 브리프면 되돌리고, 그 밖에는 들어온 브리프를 알면 그 날짜·탭으로, 모르면 지금처럼 그 영상 날짜의 영상 탭(`/<날짜>#videos`)으로 간다(주소로 바로 연 영상 페이지가 지금보다 나빠지지 않게). 글은 도착 날짜로 4.4-3을 따른다. 들어온 브리프를 몰라 영상 날짜로 갈 때도 영상 날짜를 도착 날짜로 보아, 최근 날짜가 아니면 '‹ M월 D일 브리프'다.
   - 확인: E2E — (a) 11월 3일 브리프 '세계' 탭에서 카드를 펼치고 카드의 이슈 링크로 이슈 페이지에 간 뒤 '‹ 11월 3일 브리프'를 누르면 11월 3일, '세계' 탭, 펼친 카드, 이전 스크롤(±1줄)로 돌아오고, 이어서 뒤로를 누르면 이슈 페이지가 아니라 브리프 앞의 화면이 열린다. (b) 11월 3일 '세계' → 메뉴 '이슈 목록' → 이슈 목록에서 이슈 페이지(되돌아가기가 '‹ 이슈'인지 본다) → '‹ 이슈' → 이슈 목록의 '‹ 11월 3일 브리프'를 누르면 11월 3일·'세계'로 간다(새 기록). (c) 11월 5일 영상 탭에서 묶음 칩을 고르고 영상 페이지로 간 뒤 '‹ 11월 5일 브리프'를 누르면 그날 영상 탭, 칩·스크롤이 되살아난다(측정 데이터의 11월 3일에는 영상이 없다. 이 확인 때문에 측정 데이터를 바꾸지 않는다). 주소로 바로 연 지난 날짜(11월 5일) 영상 페이지의 되돌아가기 글은 '‹ 11월 5일 브리프'이고 그 날짜의 영상 탭으로 간다. (d) 새 브라우저 컨텍스트에서 주소로 바로 연 일정 화면의 '‹ 브리프'는 최근 날짜로 간다. (e) 11월 3일 브리프를 본 뒤 소개 → 처리방침으로 가면 처리방침의 '‹ 11월 3일 브리프'는 11월 3일로 간다. 실제 폰의 뒤로 밀기는 사용자가 마지막에 확인한다(머지 뒤, 5장).
2. **이슈 페이지의 되돌아가기:** 바로 앞 화면이 브리프(펼친 카드, 짧은 소식, 빌더·수요의 관련 이슈 등)인 이슈 페이지의 되돌아가기는 '‹ 브리프' 계열(4.4-3의 글, 4.4-1의 도착)이고, 이슈 목록에서 들어왔으면 '‹ 이슈'다. 그 밖(검색, 인물 페이지, 일정, 다른 이슈, 주소로 바로 연 경우)은 '‹ 이슈'다(S5, 정적 HTML과 같다).

## 7. 진행 규칙

### 멈추고 물을 것

- 배포, push, 외부 서비스 호출, 사이트 번들에 들어가는 새 패키지(S7, `package.json`의 어느 칸이든).
- 실제 데이터 폴더, 실제 DB, `data` 브랜치를 바꿔야 할 때.
- 요구사항끼리 충돌해 둘 다 만족할 수 없을 때(예: 4.1-2의 6종 관문과 4.2-6의 구역 제목 한 모양이 정적 HTML 규칙과 부딪쳐 기준 문서의 다른 결정을 바꿔야 할 때).

아래는 멈추지 않는다. 그 부분만 처리하고 계속한다.

- 측정 도구가 어떤 화면을 찍지 못할 때: 같은 조건의 E2E로 같은 값을 재고 보고서에 적는다.
- 기존 E2E가 이 명세서가 정한 동작 때문에 깨질 때: 4.5-2대로 고친다. 이 명세서가 정하지 않은 동작 때문에 깨지면 기존 테스트를 바꾸지 않고 원인을 고친다.
