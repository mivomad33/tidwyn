# 6단계 명세서: 주요 지표

- 작성일: 2026-10-29
- 요약: `/brief`가 한국은행 ECOS와 FRED의 API로 주요 지표 12개의 일별·월별 값을 기록하고 최근 5년치 과거 값을 채운다. Claude가 이슈마다 관련 지표를 고른다. 사이트에 지표 페이지(카드)와 지표마다의 그래프 페이지, 이슈 페이지의 지표 그래프, 브리프 위 '이번 주 일정 | 지표' 상자를 더한다.
- 종류: 변경 건 (1~5단계의 `/brief`, 저장, 백업, 사이트를 바꾼다. 실제 데이터가 매일 쌓이고 사이트가 공개되어 있다)
- 단계: [`docs/plan.md`](../../plan.md)의 6단계(주요 지표). 3단계를 참조한다.
- 이 문서는 기획과 요구사항만 담는다. 설계(스키마, 라이브러리, 폴더 구조)와 작업 계획은 구현하는 AI가 정한다.
- 공개 여부: 원본 저장소와 사이트는 이미 공개다. 새 데이터(지표 값)도 백업과 사이트로 공개된다.

## 1. 목표

- **지금 상태:** `/brief`가 매일 브리프를 모아 DB에 저장하고, 뉴스를 이슈·인물·기관·국가·용어·일정에 연결하고, 백업하고, 사이트를 빌드해 `https://tidwyn.vercel.app`에 배포한다(1~5단계). 지표는 데이터로 없다. 2026-10-29 기준 실제 DB는 스키마 버전 4(5단계 마이그레이션은 머지 뒤 첫 실제 `/brief`가 한다), 날짜 2개(2026-10-27, 10-28), 뉴스 62건, 이슈 53개다.
- **바꾸려는 이유:** 사건의 영향을 숫자로 확인한다(시드 "이해를 돕는 기능": 환율, 코스피, 미국 기준금리, 유가 등을 매일 기록하고 이슈 페이지에 그래프로 붙인다).
- **쓰는 사람:** 프로젝트 주인 한 사람. 사이트는 공개라 누구나 볼 수 있다.
- **충분한 수준(X11):** 실제 DB의 복사본으로 시험 실행한 결과가 다음을 보인다. 이슈에 고른 지표가 적절한지는 사용자가 마지막에 본다(5장).
  - 12개 지표 모두 2021-10-27부터 시험 날짜까지 출처가 낸 값이 받아져 있다(주 1회 갱신 지표와 월별 지표는 출처의 마지막 발표까지, 월별 물가는 1년 더 앞부터).
  - 흡수되지 않은 모든 이슈의 지표 판단이 끝났다(고른 것이 0개인 이슈도 "판단함"이다. 시험 실행의 합치기로 "판단 안 함"이 된 이슈는 4.10-2대로 한 번 더 판단한다).
  - 그 결과로 빌드한 사이트가 Vercel 미리보기로 배포되어, 폰 폭(375px)에서 브리프 위 상자(일정·지표 탭, 접기), 지표 페이지, 지표 하나의 페이지(기간 바꾸기), 이슈 페이지의 지표 그래프가 동작한다.

## 2. 확정된 결정과 제약

### 2.1 계획과 앞 단계에서 가져온 결정 (다시 묻지 않는다)

- plan D1~D14와 2.2 제약, 앞 단계 결정(1단계 S1~S14, 1.5단계 R1~R7, 2단계 I1~I8, 3단계 P1~P14, 4단계 E1~E15, 4.5단계 M1~M9, 5단계 C1~C15)을 따른다. 특히 다음이다.
  - **D1:** 수집부터 배포와 백업까지 `/brief` 한 번 실행으로 이어진다. 백업은 DB 전체를 복원할 수 있어야 하므로 지표 데이터를 백업과 복원에 넣는다. 다시 돌려도 안전해야 한다(같은 날짜의 같은 지표 값을 두 번 저장하지 않는다). 빠진 날짜는 다음 실행 때 채운다.
  - **D4:** 지표는 뉴스와 이슈에 붙는다. 담는 항목은 시드 "데이터 설계" 표를 따른다(지표: 날짜별 값). 스키마는 구현 재량이다.
  - **D7:** 비용은 Claude Code 구독료를 빼고 월 100달러 이내다. 이 단계의 비용은 7장 사전 승인을 따른다.
  - **D8, P13, E8, M3, C9:** 화면은 3단계 확정 시안 A와 4~5단계 확정 시안, 이 명세서의 확정 시안을 따른다.
  - **D9:** 지표는 공식 출처의 과거 값으로 채운다. 이미 수집한 날짜의 뉴스 내용(제목, 요약, 본문, 출처, 분류)은 다시 조사하거나 고치지 않는다.
  - **D14, S12:** 매일 실행은 main 코드로만 한다. 개발과 확인은 실제 DB의 복사본이나 테스트 DB로만 한다. DB 구조는 쌓인 데이터를 보존하는 마이그레이션(`PRAGMA user_version`)으로 바꾼다.
  - **시드:** 지표는 틀릴 수 있다. 공식 출처를 우선하고, 확인되지 않은 값은 비워 둔다.
  - **3단계:** 한 번 공개한 주소는 뒤 단계에서도 깨지지 않게 둔다(P4). 결과물 파일 수는 5년치 데이터에서 10,000개 이하(4.1-3), 결과물에 들어가면 안 되는 것(4.1-4), 화면 공통 규칙(4.3-6: 375px 우선, 넓은 화면은 가운데 한 단, 다크 모드는 기기 설정, 키보드로 모든 링크와 버튼을 씀, 본문 글자 대비 WCAG AA 4.5:1, `lang="ko"`), 첫 화면 gzip 300KB(4.3-7), 없는 페이지·불러오기 오류와 다시 시도·대기 표시(4.3-5), 방문 통계는 운영 주소에서 페이지 보기만(P10, 4.6-4)을 지킨다. `package.json`의 `dependencies`는 비워 두고 사이트 도구는 `devDependencies`로 둔다.
  - **4단계 E12:** 시험 결과는 Vercel 미리보기 배포로 사용자가 폰에서 본다. 운영 주소는 구현 중에 바꾸지 않는다. 미리보기는 Vercel 기본 보호로 로그인해야 열린다.
  - **4.5단계:** 브라우저 기억은 로컬 스토리지 키 하나씩(`tidwyn.` 접두사)이고 사이트 소개의 "읽은 기록 지우기"는 읽은 기록 키만 지운다.
  - **5단계:** 실제 DB는 아직 버전 4다. 5단계 머지 뒤 첫 실제 `/brief`가 마이그레이션 5와 일정 뽑기를 한다. 이 단계의 마이그레이션은 그 다음 버전이고, 버전 4와 5 DB 모두에서 올라가야 한다.
- **CLAUDE.md:** 여러 곳에서 쓸 로직과 UI는 공통 코드로 만든다. 화면은 3~5단계 컴포넌트(칩 줄, 목록 줄, 대분류 칩 거르기, 브라우저 기억)를 넓혀 쓰고 따로 비슷한 것을 만들지 않는다.
- **docs/memory.md:** 명세서 폴더의 화면 확인 스크린샷은 git에 넣지 않는다(`.gitignore`). 테스트용 가짜 마이그레이션에는 큰 숫자(예: 1000)를 쓴다. `/browser-check` 점검 목록은 `.test-data/browser-check/`에 두고, 지어낸 데이터(`site/dev/fixtures.ts`)로 빌드한 결과물을 `site/dev/serve.ts`로 띄워 본다.

- 추천 영상: 7~8단계
- 데이터에 질문하기: 9단계
- 흐름 리포트(지표를 근거로 쓰기 포함): 10단계

- 검색으로 지표 값 모으기, 공식 출처 페이지 긁기: X1
- 2021-10-27보다 앞의 값: X5
- 코스피·코스닥 값을 공개 백업에 넣기: X3

- 그래프에 일정 표시하기: 요청이 없었다

- 로컬 마크다운(브리프·이슈)에 지표 넣기: 4단계 E7, 5단계와 같은 이유(사이트가 생긴 뒤 쓸 일이 적다)

### 해당 없음

- 인증과 권한: 로그인이 없다. 누구나 모든 화면을 본다(3단계와 같다).
- 남용 방지와 입력 제한: 사이트에 새 입력이 없다. 출처 응답은 숫자 데이터로만 읽고 지시로 따르지 않는다(스킬 문서 0장).
- 개인정보: 지표는 시장·통계 숫자이고 사람에 대한 데이터가 아니다.
- 서버, 원격 DB, 예약 작업: 사용자가 `/brief`를 직접 실행한다(D1). 출처 API는 로컬 스크립트만 부른다.
- 사용 분석: 3단계 P10 그대로다. 새 화면도 같은 방식으로 페이지 보기만 남고, 미리보기 주소에서는 통계를 보내지 않는다(3단계 4.6-4).

## 4. 요구사항

요구사항마다 확인 방법을 붙인다. "자동 테스트"는 `pnpm verify`에 들어가는 테스트다. 자동 테스트는 네트워크를 쓰지 않고(출처 API는 가짜 응답으로 바꾼다), 실제 `data/`와 `.env.local`을 읽지 않는다. 예시 데이터(이슈 이름, 뉴스 제목, 지표 값)는 지어내서 만든다(저장소가 공개다). "E2E"는 `pnpm e2e`(Playwright)다. "화면 확인"은 앞 단계와 같다: 사이트를 로컬에서 띄워 Claude Code의 내장 브라우저로 폰 폭(375×812)에서 보고 스크린샷을 명세서 폴더의 `screenshots/`에 남긴다(git에 넣지 않는다). 화면 동작 중 자동화할 수 있는 것은 자동 테스트나 E2E로 둔다.

**용어 정의**

- **지표:** X2의 12개 중 하나다. 지표마다 고정된 짧은 영어 식별자(주소에 쓴다, 예: `usdkrw`)가 있고 바꾸지 않는다(이름은 AI 재량).
- **값:** 지표의 한 관측값이다. 날짜(일별은 그날, 월별은 그 달)와 숫자다. 날짜는 출처가 준 날짜 그대로다(한국 지표는 한국 날짜, 미국 지표는 미국 날짜).
- **출처:** ECOS(한국은행 경제통계시스템 Open API) 또는 FRED API다.
- **지표 받기:** `/brief`가 출처에서 값을 받아 저장하는 단계다.
- **받는 범위:** 지표마다 받을 날짜 범위다. 일별 지표는 값이 하나도 없으면 2021-10-27부터, 있으면 마지막 저장 값 날짜의 60일 전부터 실행한 날의 KST 날짜까지다. 월별 지표(물가)는 늘 2020-10부터 실행한 날의 달까지이고, 받은 값으로 그 지표의 저장 값을 통째로 바꾼다(X9-①).
- **지표 판단:** 이슈 하나에 관련 지표를 0~3개 고르는 일이다(X4). "판단함"인 이슈는 다시 판단하지 않는다(X9-⑤).
- **판단 파일:** 지표 판단 결과를 Claude가 쓰는 작업 파일이다. 데이터 폴더의 `work/` 아래에 둔다.
- **공개 지표:** 공개 끄기 설정(4.7-8)이 꺼져 있지 않은 지표다.
- **기준값(브리프 날짜 D):** 날짜가 D 이하인 그 지표의 가장 최근 값이다. **전날 대비**는 그 값과 바로 앞 값의 차이다(X9-④).
- **키:** `ECOS_API_KEY`, `FRED_API_KEY`. 프로젝트 폴더의 `.env.local`에 있다(6장). worktree에서 돌려도 `.env.local`은 메인 작업 폴더(데이터 폴더와 같은 기준)에서 읽는다. 자동 테스트는 키 파일 위치를 지정해 임시 폴더의 가짜 `.env.local`이나 가짜 환경 변수만 쓴다.
- 데이터 폴더, 실제 DB, 실행 조건, 시험 모드, 실행 기록, 뉴스 키, 사이트 데이터, 결과물, 합치기, 흡수, 되돌리기는 1~5단계 명세서의 용어 정의와 같다.

### 4.1 데이터와 저장

1. **지표 정의:** 12개 지표마다 식별자, 한국어 이름, 묶음(한국 / 미국·국제), 단위(원, %, pt, 달러/배럴 등), 주기(일·월), 출처와 출처의 코드, 화면 표시 방식(값, 전날 대비를 %로 보일지 %p·포인트로 보일지, 물가는 전년 동월 대비 상승률), 출처 표시 문구, 백업 여부(코스피·코스닥은 아님), 공개 여부를 코드에 둔다. DB에도 같은 식별자로 지표를 둔다(구조는 구현 재량).
   - 확인: 자동 테스트로 정의가 12개이고 식별자가 겹치지 않으며, 백업하지 않는 것이 코스피·코스닥 둘이다. 출처의 코드가 실제로 맞는지는 4.10-2 시험 실행에서 12개 모두 값이 받아지는 것으로 본다.
2. **값:** 같은 지표의 같은 날짜 값은 하나만 둔다. 다시 받은 값이 다르면 새 값으로 바꾼다. 숫자가 아닌 값(FRED의 `.` 등 빈 값)은 저장하지 않는다.
   - 확인: 자동 테스트로 같은 응답을 두 번 적용해도 값이 하나씩이고, 바뀐 값은 바뀌며, 빈 값은 저장되지 않는다.
3. **이슈-지표 연결과 판단 여부:** 이슈마다 지표 판단 여부와 고른 지표를 저장한다. "판단함"인 이슈는 0~3개다. 합치기로 "판단 안 함"이 된 이슈는 다음 판단 전까지 3개를 넘을 수 있고(4.3-6), 사이트는 그 연결을 그대로 보인다. 흡수된 이슈의 연결은 남는 이슈로 본다.
   - 확인: 자동 테스트로 판단한 이슈가 "판단함"으로 나오고, 0개를 고른 이슈도 "판단함"이다.
4. **마이그레이션:** 지금 형식(버전 5, 또는 아직 5단계 마이그레이션 전인 버전 4)의 DB를 열면 새 버전으로 마이그레이션되고, 기존 데이터는 그대로 남으며, 모든 이슈가 "지표 판단 안 함"이 된다. 실행 전 사본이 마이그레이션 전에 남는 순서(1단계)는 그대로다.
   - 확인: 자동 테스트로 버전 4와 버전 5 스키마의 DB(브리프, 이슈, 대상, 용어, 일정, 합치기 기록 포함)를 새 코드로 열면 마이그레이션되고, 기존 데이터를 그대로 읽으며, 모든 이슈가 지표 판단 대상으로 나온다.
5. **기존 저장과의 관계:** 브리프 작업 파일, 이슈 연결 파일, 인물·용어 뽑기 파일, 일정 파일의 형식에 지표 항목을 더하지 않는다. 1~5단계의 저장·검사·연결·뽑기 동작은 바꾸지 않는다.
   - 확인: 1~5단계 테스트가 통과한다(4.10-1).

### 4.2 지표 받기 (X1, X5, X9)

1. **실행 위치:** 새 명령(지표 받기, 지표 판단의 후보 목록·검사·적용)은 기존 명령처럼 실행 조건(S12: 실제 데이터 폴더에서는 main 체크아웃·변경 없음일 때만)을 따른다. `/brief`에서 지표 받기는 날짜별 단계와 지표 판단(4.3)이 끝난 뒤, 합치기 전에 한 번 돈다(순서표의 위치와 번호는 AI 재량). 스크립트 명령 하나가 12개 지표를 받는 범위만큼 받아 저장한다. Claude가 값을 검색하거나 고치지 않는다. 시험 모드(`/brief test`)에서도 돈다.
   - 확인: 스킬 문서(4.9-1)에 이 위치와 명령이 있다(읽어서 확인, 문서 속 명령 이름이 실제 명령과 같은지 자동 테스트). 자동 테스트로 새 명령이 실제 데이터 폴더 모드에서 실행 조건에 맞지 않으면 거부된다(기존 명령의 실행 조건 테스트 방식과 같다).
2. **출처 호출:** ECOS와 FRED의 공식 API만 `https://` 주소로 부르고, 키는 같은 이름의 환경 변수가 있으면 그것을, 없으면 `.env.local`에서 읽는다. 출처의 호출 한도와 한 번에 받는 행 수 한도를 지킨다(나눠 받기, 호출 사이 간격은 AI 재량. 한도 값은 구현할 때 공식 문서로 확인한다). 요청마다 시간 제한을 두고, 실패하면 몇 번 다시 시도한다(횟수는 AI 재량).
   - 확인: 자동 테스트로 가짜 출처 응답(정상, 빈 값 섞임, 한도 오류, 시간 초과, 인증 오류)에 대해 저장 결과와 실패 기록이 맞다. 4.10-2에서 실제 출처로 12개 모두 받아진다.
3. **실패 처리(X9-②):** 지표 하나의 받기가 실패하면(키 없음, 인증 오류, 네트워크, 형식 오류) 그 지표의 값은 그대로 두고 실행 기록과 요약에 실패와 이유(키 문제면 "키 확인 필요")를 남긴다. 나머지 지표, 백업, 빌드, 배포, 요약은 계속한다. 다음 실행이 받는 범위 규칙으로 빠진 만큼 채운다.
   - 확인: 자동 테스트로 한 지표만 실패시킨 실행(데이터 폴더 지정)에서 나머지 지표가 저장되고, 다음 실행의 받는 범위에 실패한 지표의 빠진 날짜가 들어가며, 키가 없을 때 모든 지표가 "키 확인 필요"로 실패하고 다른 단계가 끝까지 돈다.
4. **받는 범위:** 용어 정의의 받는 범위대로 받는다. 출처가 아직 내지 않은 날짜(오늘, 휴장일, 다음 달 물가)는 빈 채로 둔다.
   - 확인: 자동 테스트로 값이 없는 지표, 마지막 값이 어제인 지표, 마지막 값이 90일 전인 지표의 받는 범위가 맞다(테스트에서는 날짜를 넣어 준다). 월별 지표는 매번 처음부터 받고, 저장된 지수와 모두 다른 값(기준년이 바뀐 응답)을 받은 뒤 저장 값이 모두 새 값이며 상승률이 새 값으로만 계산된다. 빈 응답·앞부분이 빠진 응답에서는 실패로 기록되고 저장 값이 그대로다.

### 4.3 이슈 지표 판단 (X4, X9-⑤, X10)

1. **실행 위치와 대상:** 날짜별 단계(일정 뽑기까지)가 모두 끝난 뒤, 지표 받기 전에 "지표 판단 안 함"인 이슈를 모두 판단한다. 흡수된 이슈는 대상이 아니다. 판단은 서브에이전트에 맡기지 않고 메인이 한다(앞 단계와 같다).
   - 확인: 스킬 문서에 이 순서와 명령이 있다(읽어서 확인과 명령 이름 자동 테스트). 4.10-2 시험 실행에서 모든 이슈가 판단된다.
2. **후보 목록:** 스크립트 명령이 `work/` 아래 파일로 다음을 쓴다: 지표 목록(식별자, 이름, 묶음, 한 줄 설명)과 판단할 이슈마다 식별자, 이름, 대분류·소분류, 지금까지 요약, 최근 뉴스 제목 몇 건. 이슈가 많으면 파일 여러 개로 나눈다(한 파일의 이슈 수는 AI 재량).
   - 확인: 자동 테스트로 판단 안 한 이슈만 목록에 들고(판단함, 흡수된 것은 빠짐), 나눈 파일의 이슈를 합치면 대상 전체다.
3. **판단 파일과 검사:** Claude는 이슈마다 지표 식별자 0~3개를 쓴다. 스크립트가 검사해 다음을 거부한다: 목록에 있는 이슈가 파일에 빠짐, 없는 이슈 또는 목록에 없는 이슈, 없는 지표 식별자, 4개 이상, 같은 지표를 두 번. 통과하면 파일 단위로 한 번에 적용하고 그 이슈들을 "판단함"으로 둔다. 거부하면 아무것도 적용하지 않는다.
   - 확인: 자동 테스트로 거부 경우마다 거부되고 DB가 바뀌지 않으며, 맞는 파일(0개, 1개, 3개를 고른 이슈 섞임)이 적용된다.
4. **판단 기준(스킬 문서에 적는다):** 이슈의 뉴스가 그 지표의 움직임을 직접 말하거나, 그 이슈가 그 지표를 움직이는 원인으로 보도된 경우만 고른다(예: 중앙은행 금리 결정 이슈와 그 나라 기준금리·국채 금리, 중동 분쟁 이슈와 유가). 관계가 막연하면(모든 경제 뉴스에 환율 등) 고르지 않는다. 대부분의 정치·사회·IT 이슈는 0개다. 기계로 검사할 수 없어 사용자가 마지막에 본다(X11).
   - 확인: 스킬 문서에 기준이 있다(읽어서 확인). 4.10-2 결과의 적절함은 사용자가 마지막에 본다(5장).
5. **고쳐서 다시 검사와 실패:** 위반이 나오면 Claude가 판단 파일을 고쳐 다시 검사한다. 파일마다 최대 2번이다. 그래도 위반이 남으면 그 파일은 적용하지 않고 실행 기록에 실패로 남긴다. 그 이슈들은 "판단 안 함"으로 남아 다음 실행이 다시 판단한다. 판단 실패는 지표 받기, 합치기, 백업, 빌드, 배포, 요약을 멈추지 않는다.
   - 확인: 자동 테스트(데이터 폴더 지정 흐름)로 실패한 파일의 이슈가 다음 실행 대상에 다시 나오고, 실패가 실행 기록과 요약에 남으며, 뒤 단계(지표 받기, 백업, 빌드, 요약)가 끝까지 돈다.
6. **이슈 합치기와 되돌리기(X9-⑤):** 2단계 이슈 합치기를 적용하면 흡수되는 이슈의 지표를 남는 이슈에 더한다(같은 지표는 하나로). 합친 수가 3개를 넘으면 남는 이슈의 연결을 지우지 않고 "판단 안 함"으로 되돌려, 다음 지표 판단이 다시 고르게 한다(다시 판단하면 그 결과로 바꾼다). 둘 중 하나라도 "판단 안 함"이면 남는 이슈는 "판단 안 함"이다. 이슈 합치기 되돌리기(`unmerge`)는 두 이슈의 지표 연결과 판단 여부를 합치기 전으로 되돌린다(합친 뒤 다시 판단한 경우에도 합치기 전 상태로 되돌린다). 같은 남는 이슈에 나중에 다른 합치기가 있었으면 그 합치기로 들어온 지표는 남는 이슈에 남긴다(기존 `unmerge`가 뉴스·이름을 넘겨받는 방식과 같다). 지표 기록이 없는 옛 합치기(6단계 전 기록)를 되돌리면 두 이슈 모두 "판단 안 함"이 된다. 되돌린 결과 남는 이슈의 지표가 3개를 넘으면 연결은 두고 "판단 안 함"으로 둔다(합치기와 같은 규칙).
   - 확인: 자동 테스트로 지표가 합쳐지고, 3개를 넘으면 "판단 안 함"이 되며, 되돌리면 두 이슈가 합치기 전과 같고, 나중 합치기로 들어온 지표가 남고(그래서 3개를 넘으면 "판단 안 함"), 옛 합치기를 되돌리면 둘 다 "판단 안 함"이다.

### 4.4 백업과 복원 (D1, X3)

1. **백업 형식:** 백업에 지표 값(백업하지 않는 지표 빼고), 이슈-지표 연결과 판단 여부를 넣는다. 지표 값은 날짜 밖 파일에 둔다(파일 나누기는 AI 재량이되 백업 파일 이름 규칙은 3단계 4.1-4의 구분이 유지되게 하고, 결과물 검사의 백업 이름 목록에 더한다). 백업의 지표 파일에 지표마다 출처 표시 문구(4.1-1)를 함께 넣는다(ECOS 약관 제7조②, 공개 백업도 재배포다). 형식 버전을 올리고(지금 4), 복원은 지금 형식(1~4)과 새 형식을 모두 읽는다. 옛 형식 백업을 복원하면 모든 이슈가 "지표 판단 안 함"이고 지표 값이 없다(다음 `/brief`가 처음부터 받는다).
   - 확인: 자동 테스트로 지표 값·연결이 있는 DB를 백업하고 빈 곳에 복원하면 같은 데이터가 나오되 코스피·코스닥 값만 없고(왕복), 백업 파일 어디에도 코스피·코스닥 값이 없고, 백업의 지표 파일에 지표마다 출처 문구가 있으며, 복원한 DB에서 다음 실행의 받는 범위가 코스피·코스닥은 처음부터다. 형식 4 백업을 복원하면 모든 이슈가 판단 대상이다.
2. **공개 데이터 검사:** 새 백업 데이터도 3단계의 push 전 공개 전 점검과 결과물 검사를 그대로 받는다. 결과물에 들어가면 안 되는 파일 이름 목록(`src/siteCheck.ts`)에 이 단계의 새 백업 파일, 판단 파일·후보 목록 파일 이름을 더한다(3단계 4.1-4).
   - 확인: 기존 공개 전 점검 테스트가 통과하고, 4.10-2 시험 결과물이 결과물 검사를 통과한다. 자동 테스트로 결과물에 새 백업 파일이나 판단·후보 목록 파일 이름의 파일을 넣으면 결과물 검사가 실패한다.

### 4.5 `start` 출력과 실행 요약

1. **`start` 출력:** 지금 출력에 "지표 판단 안 한 이슈 수"(흡수된 이슈는 세지 않는다. 요약의 수도 같다)와 "키: ECOS 있음/없음, FRED 있음/없음"(값은 보이지 않는다) 줄을 더한다.
   - 확인: 자동 테스트로 두 줄이 나오고, 키 값이 출력에 없다.
2. **요약:** 실행 요약에 다음을 더한다: 지표 판단한 이슈 수와 지표를 고른 이슈 수, 판단에 실패한 파일과 남은 위반, 아직 판단 안 한 이슈 수. 지표마다 받은 값 수와 마지막 값의 날짜, 실패한 지표와 이유. 사이트 빌드 줄에 공개 지표 수.
   - 확인: 자동 테스트로 요약 출력에 위 줄이 나온다.

### 4.6 사이트 데이터 (X6~X9)

1. **사이트 데이터:** 빌드할 때 DB에서 공개 지표만 사이트 데이터에 넣는다.
   - 지표 목록: 지표마다 식별자, 이름, 묶음, 단위, 주기, 마지막 값과 날짜, 전날 대비(월별은 전달 대비), 1년 작은 그래프용 값, 출처 표시 문구, 관련 이슈(그 지표를 고른 이슈의 식별자·이름, 최근 업데이트 순).
   - 지표마다 그 지표의 마지막 값 기준 최근 5년 값(물가는 전년 동월 대비 상승률로 계산한 값). 그보다 앞의 저장 값은 사이트에 넣지 않는다(DB와 백업에는 남는다).
   - 브리프 날짜마다 상자에 보일 지표의 기준값과 그 날짜, 전날 대비(X9-④).
   - 이슈 데이터에 고른 지표(식별자)와 그래프 기간(이슈 시작일 30일 전부터 그 지표의 마지막 값 날짜까지, 지표마다).
   - 확인: 자동 테스트로 지어낸 DB(날짜 10개 이상, 일별·월별 지표, 휴장일 빈 값, 1년 전 같은 달 지수가 빠진 월별 지표, 합친 이슈 1개, 공개 끈 지표 1개, 값이 하나도 없는 공개 지표 1개)에서 위 항목이 나오고, 브리프 날짜의 기준값이 그 날짜 이하의 가장 최근 값이며, 물가 상승률 계산이 맞고(빠진 달은 빈 값, 마지막 값·전달 대비는 상승률이 있는 달끼리), 공개 끈 지표는 어디에도 없다.
2. **파일 수와 크기:** 3단계 4.1-3의 파일 수 한도(5년치 데이터에서 결과물 10,000개 이하)를 지표를 더한 5년치에서도 지킨다(5단계 측정 조건에 지표 12개 × 5년 값, 이슈의 2할이 지표 1~3개를 고른 것을 더한다). 3단계 4.3-7의 첫 화면 크기(브리프 첫 화면, 새 상자 포함 gzip 300KB 이하)를 그대로 지킨다. 지표 페이지와 지표 하나의 페이지(5년 그래프 포함)가 처음 받는 사이트 데이터도 gzip 300KB 이하다. 나누는 방법은 AI 재량이다. 단, 결과물 파일·폴더 이름이 결과물 검사(`src/siteCheck.ts`)의 이름 규칙 전체에 걸리지 않게 한다(5단계 4.6-2와 같다).
   - 확인: 지어낸 5년치로 빌드해 결과물 파일 수가 10,000개 이하이고, 위 화면들이 처음 받는 데이터 크기가 300KB 이하다(5단계와 같은 크기 측정 명령(`site/size.ts`)이나 자동 테스트. 쓴 것을 보고서에 적는다). 보고서에 결과물 크기·파일 수와 5단계 보고서 값과의 차이, 실제 데이터 복사본의 값, 1년 뒤 예상 크기(Vercel 무료 한도 100MB에 닿는 예상 시점 포함)를 적는다.
3. **같은 DB, 같은 결과:** 3단계 4.1-2를 새 데이터에도 지킨다(빌드한 날의 시계를 쓰지 않는다).
   - 확인: 3단계의 같은 결과 테스트가 지표가 있는 DB로도 통과한다.

### 4.7 화면 (X6~X8)

화면은 [design/site.html](design/site.html)(확정 시안)을 따른다. 시안의 설명 글과 이 명세서가 다르면 명세서를 따른다. 시안에 없는 것은 3단계 확정 시안 A와 지금 사이트의 색·글꼴·간격·컴포넌트를 쓴다. 오름·내림 색은 새 색 토큰으로 라이트·다크에 두고 대비를 지킨다. 그래프는 직접 그리든 `devDependencies` 라이브러리를 쓰든 AI 재량이고, 4.6-2의 크기와 3단계 4.3-7을 지킨다. 3단계 4.3-5(없는 페이지, 불러오기 오류와 다시 시도, 대기 표시)와 4.3-6(화면 공통)을 모든 새 화면과 동작에 지킨다.

1. **브리프 위 '이번 주 일정 | 지표' 상자(X7, 5단계 4.7-4 바뀜):** 5단계의 '이번 주 일정' 상자 자리에 상자 하나를 둔다. 위 줄에 탭 두 개('이번 주 일정 N', '지표')와 오른쪽 접기 버튼(▴)이 있다.
   - 일정 탭은 5단계 4.7-4의 내용(최대 5개, 줄을 누르면 일정 화면의 그 일정)을 그대로 보이고, 일정 목록 아래 줄에 '일정 전체 ›'를 둔다(지표 탭의 '지표 전체 ›'와 같은 자리. 5단계의 제목 줄 자리는 탭과 접기 버튼이 차지한다).
   - 지표 탭은 일별 공개 지표의 기준값을 가로로 넘기는 칩으로 보인다(칩마다 이름, 값, 전날 대비. 순서는 원/달러, 코스피, 미국채 10년, WTI부터, 나머지는 AI 재량). 그 아래 "MM월 DD일 값 · 지표 전체 ›"가 있다(날짜는 그 브리프 날짜). 칩을 누르면 그 지표의 페이지로, '지표 전체'는 지표 페이지로 간다. 기준값의 날짜가 브리프 날짜와 다른 칩은 그 날짜를 작게 붙인다.
   - 그 주 일정이 없으면 일정 탭을 보이지 않고 지표만 보인다. 기준값이 있는 공개 지표가 없으면 지표 탭을 보이지 않는다. 둘 다 없으면 상자도 접은 줄도 없다.
   - 접기 버튼을 누르면 상자가 배경 없는 한 줄 "이번 주 일정 N · 원/달러 <값> <전날 대비> ▾"로 접힌다(없는 쪽은 줄에서 빠진다. 원/달러의 기준값이 없으면 칩 순서에서 기준값이 있는 첫 지표를 보인다). 다시 누르면 편다. 버튼은 `aria-expanded`로 상태를 알린다. 탭은 키보드로 고를 수 있고 고른 탭을 보조 기술에 알린다.
   - 접은 상태는 5단계의 접기 키(`tidwyn.weekBox`)를 그대로 써서 이어지고, 고른 탭은 새 로컬 스토리지 키 하나에 기억한다(처음엔 일정 탭, 일정이 없는 날짜에서는 지표 탭). 저장할 수 없거나 값이 깨졌으면 오류 없이 기본값이다. 사이트 소개의 "읽은 기록 지우기"는 이 키들을 지우지 않는다. 사이트 소개의 브라우저 기억 설명에 새 키를 더한다.
   - 섹션 탭과 대분류 칩에 관계없이 같다.
   - 확인: 자동 테스트로 상자의 지표 값이 브리프 날짜의 기준값이고 일정·지표가 없는 경우의 탭 규칙이 맞다. E2E로 탭을 바꾸고, 접고 펴며, 새로 고치거나 다른 날짜로 가도 접은 상태와 탭이 이어지고, 키보드로 탭과 접기를 쓰며 `aria-expanded`가 바뀌고, 사이트 소개의 '읽은 기록 지우기' 뒤에도 고른 탭과 접은 상태가 남으며, 사이트 소개에 새 키 설명이 있다. 5단계의 '이번 주 일정' E2E가 새 상자에서도 통과하도록 고친다(4.10-1의 허용 범위). 화면 확인(일정 탭, 지표 탭, 접음, 다크, 일정 없는 날짜).
2. **지표 페이지:** 제목 '지표', 그 아래 "MM월 DD일까지의 값 · 공식 출처(한국은행 ECOS, FRED)" 한 줄(날짜는 공개 일별 지표의 마지막 값 날짜 중 가장 늦은 날), '한국'과 '미국·국제' 묶음의 카드(폰은 두 열, 넓은 화면은 세 열). 카드마다 이름, 마지막 값(단위), 전날 대비(색과 ▲▼, 변동 없으면 "변동 없음"), 1년 작은 그래프다. 월별 물가는 "9월 2.1%"처럼 그 달과 상승률, "전달 대비"로 보인다. 카드를 누르면 지표 하나의 페이지로 간다. 바닥에 출처 표시(4.7-6)가 있다. 값이 하나도 없는 공개 지표(복원 직후의 코스피·코스닥, 첫 받기가 실패한 지표)는 카드와 브리프 위 상자에서 빼고, 그 지표 하나의 페이지는 "아직 값이 없다"를 보이며, 이슈 페이지에서는 그 그래프를 빼고 보인다.
   - 확인: 자동 테스트로 카드 순서, 값·변화 표기(단위, 소수 자리, %·%p), 오름·내림·변동 없음 표시가 맞다. 자동 테스트로 값이 하나도 없는 공개 지표가 카드·상자 칩·이슈 그래프에 없고 그 지표 하나의 페이지가 "아직 값이 없다"를 보이며, 고른 지표가 없는 이슈에 '관련 지표'가 없다. E2E로 브리프 위 칩·지표 페이지 카드·이슈 페이지 그래프 제목을 누르면 그 지표 하나의 페이지로, 지표 하나의 페이지의 관련 이슈를 누르면 그 이슈 페이지로 간다. 화면 확인(375px, 다크, 1440px).
3. **지표 하나의 페이지:** 제목(지표 이름), 마지막 값·전날 대비·날짜·출처, 기간 전환 '1개월 | 1년 | 5년'(처음 1년), 큰 그래프(축에 처음·끝 날짜, 가로 눈금선), 그래프 아래 '관련 이슈'(그 지표를 고른 이슈 목록, 없으면 보이지 않는다, 많으면 처음 일부와 더 보기). 그래프 위를 누르거나 끌면(마우스는 올리면) 그 날짜와 값이 보이고, 키보드로도 날짜를 옮겨 볼 수 있다(방식은 AI 재량). 그래프마다 보조 기술용 요약(기간, 처음·마지막 값, 최고·최저)이 있다. 고른 기간은 주소에 담거나 담지 않거나 AI 재량이다.
   - 확인: 자동 테스트로 기간마다 그래프에 들어가는 값 범위, 요약 글이 맞고, 관련 이슈가 많을 때 처음 일부만 보이고 더 보기로 나머지가 보인다. E2E로 기간을 바꾸면 그래프가 바뀌고 그래프를 눌러 날짜·값이 보인다. 화면 확인(1년, 5년, 값을 누른 상태, 다크, 1440px).
4. **이슈 페이지의 지표 그래프:** 이슈 페이지에서 타임라인 아래, '일정' 위에 '관련 지표'를 둔다. 고른 공개 지표마다 그래프 하나(제목 줄에 이름, 마지막 값, "M월 D일부터"), 기간은 4.6-1의 그래프 기간이다. 그 이슈의 뉴스가 있는 날(흡수된 이슈의 뉴스 포함)에 강조색 점을 찍고, "이 이슈 뉴스가 있는 날" 범례를 둔다. 점의 날짜에 값이 없으면(휴장일) 그 앞의 가장 가까운 값 위치에 찍는다. 그래프의 누르기·요약은 4.7-3과 같다. 그래프 제목을 누르면 지표 하나의 페이지로 간다. 그 아래 출처 표시. 고른 지표가 없으면 '관련 지표'를 보이지 않는다.
   - 확인: 자동 테스트로 그래프 기간과 점의 날짜가 맞다(흡수된 이슈 뉴스, 휴장일 포함). 화면 확인(지표 1개, 3개, 다크).
5. **메뉴:** 머리 메뉴에 '지표'를 더한다(위치는 AI 재량). 바닥글에 더할지는 AI 재량이다.
   - 확인: 화면 확인(메뉴 연 상태).
6. **출처 표시:** 지표 페이지, 지표 하나의 페이지, 이슈 페이지의 지표 그래프 아래에 보이는 지표의 출처를 밝힌다. ECOS 지표는 "자료: 한국은행 ECOS"(ECOS 약관 제7조②: ECOS에서 제공된 정보임을 표시)와 작성기관(코스피·코스닥은 한국거래소, 물가는 국가데이터처 등 ECOS가 표시하는 작성기관), FRED 지표는 "<원 기관> via FRED"다. FRED API 이용 약관(https://fred.stlouisfed.org/docs/api/terms_of_use.html, 2026-10-29 확인)이 요구하는 것을 사이트 소개와 지표 페이지 바닥에 싣는다: 고지 문구 "This product uses the FRED® API but is not endorsed or certified by the Federal Reserve Bank of St. Louis.", 약관 링크, 그리고 사이트 소개에 "이 사이트를 이용하면 FRED® API 이용 약관을 따르는 것으로 본다"는 한 줄(약관의 users agreeing 조항. 2회차 검토에서 AI가 정함: 약관을 지키는 쪽이고 문구는 언제든 고칠 수 있다). 구현할 때 약관 원문을 다시 열어 문구가 바뀌었으면 새 문구를 쓴다. 사이트 소개(`/about`)에 지표는 공식 출처에서 받은 값이지만 늦게 반영되거나 출처가 고칠 수 있고 날짜는 출처 기준이라는 것을 한 줄 더한다.
   - 확인: 자동 테스트로 지표마다 출처 문구가 있고 화면에 나오며, FRED 고지 문구와 약관 링크가 사이트 소개와 지표 페이지에 있고, 약관 동의 한 줄이 사이트 소개에 있다. 보고서에 확인한 약관 주소와 실은 문구를 적는다.
7. **지표 주소:** 지표 페이지와 지표 하나의 페이지 주소는 깔끔한 경로(예: `/indicators`, `/indicators/<식별자>`, 경로 이름은 AI 재량)이고, 한 번 공개한 주소는 뒤 단계에서도 깨지지 않게 둔다(3단계 P4). 없는 식별자와 공개 끈 지표의 주소는 없는 페이지를 보인다. 직접 열거나 새로 고쳐도 화면이 나온다(3단계 4.6-2의 대체 경로 설정에 더한다).
   - 확인: 자동 테스트로 주소 규칙이 맞다. 로컬 보기 서버(`pnpm site:preview`)에서 새 주소를 직접 요청해 200과 화면 틀이 온다.
8. **공개 끄기 설정(X3):** 지표마다 사이트 공개를 끄는 설정을 코드의 지표 정의(4.1-1)에 둔다. 끄면 다음 빌드부터 그 지표가 사이트 데이터, 브리프 위 상자, 지표 페이지, 이슈 페이지 어디에도 없고 주소는 없는 페이지다. 값 받기와 저장, 이슈 판단의 후보(4.3-2)는 계속한다(다시 켜면 바로 보인다). 운영 문서에 끄는 방법(정의를 고쳐 main에 머지한 뒤 `/brief` 또는 손으로 하는 배포)을 적는다.
   - 확인: 자동 테스트로 공개를 끈 지표의 식별자와 값이 사이트 데이터 파일 어디에도 없다(코드 묶음(JS)에 지표 정의가 들어가는 것은 괜찮다. X3이 막는 것은 값의 게시다).
9. **화면 확인의 상태:** 위 화면을 375px 라이트로, 지표 페이지·지표 하나의 페이지·브리프 위 상자·이슈 페이지는 다크로도, 지표 페이지와 지표 하나의 페이지는 넓은 화면(1440px)으로도 확인한다. 빈 상태(공개 지표가 하나도 없음, 값이 하나도 없는 공개 지표, 관련 이슈 없음, 기간 안 값이 하나뿐)와 데이터를 불러오지 못한 오류 상태, 지표 하나의 페이지의 데이터 대기 표시(느린 응답으로 재현, 3단계 4.3-5)도 하나씩 본다. 가로 스크롤이 없다(넘기는 칩은 상자 안에서만 넘긴다). 새 화면의 글자 색 대비가 WCAG AA(4.5:1) 이상이다(오름·내림 색, 칩 배경 위 글자 포함). 그래프 선과 점은 배경과 3:1 이상이다.
   - 확인: 스크린샷을 보고서에 링크한다. 대비는 쓴 색으로 계산해 보고서에 적고, 오름·내림 색과 그래프 선·점 색을 `site/src/lib/theme.ts`의 대비 검사에 더한다(글자는 `textPairs` 방식 4.5:1, 선·점은 `iconPairs` 방식 3:1). 지어낸 데이터(`site/dev/fixtures.ts`)가 지표(12개, 5년, 휴장일, 공개 끈 지표, 값 없는 지표, 관련 이슈 여러 개)를 만들게 넓혀 화면 확인·`/browser-check`·크기 측정에 쓴다. 가로 스크롤 없음은 E2E로 375px에서 본다.

### 4.8 키가 새지 않게 막기

1. **키를 두는 곳:** 키는 `.env.local`(git이 무시한다)과 실행 중 환경 변수에만 있다. 실행 기록, 작업 파일, 로그, 대화창 출력, 오류 메시지, DB, 백업, 결과물, 커밋 어디에도 키 값을 쓰지 않는다. 주소에 키가 들어가는 요청(ECOS는 경로, FRED는 `api_key` 쿼리)은 오류를 남길 때 주소의 키를 가린다. 키는 지표 받기와 점검 코드 안에서만 읽고, 하위 프로세스(사이트 빌드, `vercel`, git) 환경에 넣지 않는다.
   - 확인: 자동 테스트로 가짜 키를 넣고 ECOS와 FRED 모두 실패하는 출처 응답(인증 오류, 네트워크 오류)을 낸 실행에서 실행 기록·요약·출력에 가짜 키 문자열이 없다.
2. **점검:** 공개 전 점검(`precheck`)과 결과물 검사가 키 값(`.env.local`과 환경 변수 `ECOS_API_KEY`·`FRED_API_KEY`에 있는 값 모두)을 찾아, `precheck`가 지금 검사하는 모든 대상(모든 로컬 브랜치의 이력과 추적하는 지금 파일, `data` push 전 검사 포함)이나 결과물에 있으면 실패한다(키 값은 출력하지 않고 "키 값이 들어 있음"과 파일 이름만 보인다). 둘 다 없으면(빈 값이나 너무 짧은 값은 없는 것으로 본다, 기준은 기존 `src/precheck.ts`의 짧은 값 건너뛰기와 같은 방식) 이 검사는 건너뛰고 그렇다고 보인다.
   - 확인: 자동 테스트로 가짜 키가 든 결과물 파일과 커밋(작업 브랜치에만 있는 커밋 포함)에서 검사가 실패하고(키를 파일로 줄 때와 환경 변수로 줄 때 모두), 출력에 가짜 키 값이 없으며, 키가 없는 결과물은 통과하고, 키가 어디에도 없으면 건너뛴다는 말을 보이고 통과한다.

### 4.10 기존 기능 유지와 시험 실행

1. **기존 테스트와 검증:** 1~5단계 테스트(`pnpm verify`, `pnpm e2e`)가 통과한다. 기존 테스트에서 허용하는 변경은 5단계 명세서 4.9-1과 같고, 여기에 더해 이 명세서가 바꾸는 화면·출력을 통째로 비교하는 단언(메뉴 항목 목록, 브리프 위 상자의 구조, 사이트 데이터·결과물의 파일 목록)을 바뀐 동작에 맞게 고쳐도 된다. 새 항목(이슈의 지표, 브리프 날짜의 지표)은 비어 있으면 빼서 기존 통째 비교 단언을 바꾸지 않는다. 고친 줄과 이유를 보고서에 적는다.
   - 확인: `pnpm verify`와 `pnpm e2e` 통과. `git diff main -- test/`(E2E는 `test/e2e/`)의 기존 줄 변경이 허용 범위뿐이다(보고서에 목록).
2. **시험 실행:** 실제 `data/tidwyn.db`를 파일 그대로(`cp`, DB를 열어서 복사하지 않는다) `.test-data/` 아래 새 폴더에 복사하고, 그 복사본으로 다음을 한다. 실제 `data/`와 실제 DB, `refs/heads/data`에는 쓰지 않는다.
   - 데이터 폴더 지정(`TIDWYN_DATA_DIR`=복사 폴더) `/brief` 흐름으로 `start`를 돌려 마이그레이션(실제 DB가 그때 버전 4면 5단계 마이그레이션도)과 새 줄을 확인한다.
   - 그 복사본에 5단계 일정 뽑기가 안 된 날짜가 있으면 스킬 문서대로 함께 한다(5단계 시험과 같은 방식, 결과 수만 보고서에 적는다).
   - 모든 이슈를 스킬 문서의 지표 판단 절차대로 판단한다. 구현하는 AI가 Claude의 역할(판단 파일 쓰기)을 스킬 문서 기준(4.3-4)대로 한다. 새 날짜 수집은 하지 않는다.
   - 지표 받기를 실제 출처(`.env.local`의 키)로 돌려 12개 지표의 5년치를 받는다. 같은 명령을 한 번 더 돌려, 첫 받기의 지표별 마지막 날짜 이하의 값 수가 그대로이고 같은 날짜 값이 겹치지 않는지 본다(60일 다시 받기). 그 사이 출처가 새 날짜 값을 올려 더해진 값 수는 따로 적는다.
   - 합치기 주기가 되었으면 합치기도 한다. 그 합치기로 "판단 안 함"이 된 이슈가 있으면 수를 보고서에 적고 지표 판단 절차를 한 번 더 돌린다(실제 실행에서는 다음 `/brief`가 한다). 이어서 백업(지정 폴더라 커밋 없음), 빌드까지 돌리고 요약을 확인한다.
   - 그 결과물을 미리보기로 배포하고(`deploy --dir <결과물> --preview`, 사전 승인) 4단계 4.8-1과 같은 확인을 한다: `vercel inspect <미리보기 주소> --scope mivomad33`가 Ready이고, 로그인 없이 `curl`로 요청하면 사이트 내용이 아닌 응답(401·403 또는 Vercel 로그인으로 보내는 응답)이 오며, 미리보기 배포 직후 운영 배포 ID가 시작 때 진행 기록에 적은 것과 같다.
   - 같은 결과물을 로컬 보기 서버로 띄워 4.7의 화면 확인 스크린샷을 남긴다(미리보기는 로그인이 필요해 AI가 열지 않는다). 빈 상태·오류 상태처럼 실제 복사본에 없는 상태는 지어낸 데이터로 찍는다.
   - 백업 결과를 빈 폴더에 복원해 다시 빌드하면, 사이트 데이터에서 코스피·코스닥의 식별자와 그 항목(지표 목록·값·브리프 날짜별 기준값·이슈의 지표 연결)을 걸러 낸 나머지가 같다(복원 직후 코스피·코스닥은 값이 없는 공개 지표다, 4.7-2). 복원 폴더에서 지표 받기를 돌린 뒤에는 원래 시험 DB의 지표별 마지막 날짜까지의 코스피·코스닥 값이 원래와 같다(그 뒤에 더해진 날짜는 비교하지 않는다).
   - 확인: 보고서에 시험 폴더 경로, 지표마다 받은 값 수와 첫·마지막 날짜, 두 번째 받기에서 바뀐 값 수와 더해진 값 수, 판단한 이슈 수와 지표를 고른 이슈 수, 실패와 고친 횟수, 합치기 결과, 빌드 결과(공개 지표 수, 크기, 파일 수), 미리보기 주소와 확인 결과, 복원 비교 결과, 스크린샷 링크, 이슈별로 고른 지표 전체 목록(이슈 이름, 고른 지표)이 든 검토 파일 경로(git이 무시하는 시험 폴더 안. 보고서와 진행 기록에는 경로와 수만 적는다)가 있다. 1장 "충분한 수준"이 모두 보인다.
3. **실제 데이터 보호:** 구현을 시작할 때 `data/tidwyn.db`의 해시와 `git rev-parse refs/heads/data`를 진행 기록에 적고 끝날 때 다시 본다. 다르면 `data/runs/`로 사용자의 실제 실행 때문인지 확인해 보고서에 적는다.
   - 확인: 비교 결과를 보고서에 적는다.

2. 시험 실행으로 이슈마다 고른 지표 목록(보고서에 경로가 있는 검토 파일)을 보고, 관계가 분명한 것만 붙었는지, 빠진 중요한 연결이 없는지 본다(X4, X11). 고칠 것이 있으면 알려 준다(기준을 고쳐 다시 구현한다). 머지 뒤 첫 실제 `/brief`가 실제 DB의 모든 이슈를 다시 판단해 검토 없이 운영에 올리므로, 그 실행 뒤 이슈 페이지를 몇 개 다시 본다(보고서의 "머지 뒤 첫 실제 `/brief`" 항목에 이 안내를 넣는다).
3. 화면이 확정 시안(design/site.html)과 같은 느낌인지 본다.
4. 머지를 승인한다. 머지한 세션이 공개 전 점검 → main push를 한다(CLAUDE.md). 운영 사이트는 머지 뒤 첫 실제 `/brief`가 바꾼다.

## 7. 진행 규칙

- 작업 브랜치는 `spec/stage6-indicators`다(이 명세서를 쓴 브랜치를 이어 쓴다). 사용자 검토를 통과하면 main에 squash merge하고 브랜치를 지운다. 머지 전에 사용자에게 확인한다. 머지 뒤 공개 전 점검과 main push는 CLAUDE.md대로 머지한 세션이 한다. 이 단계에는 CLAUDE.md 작업 규칙의 예외가 없다.
