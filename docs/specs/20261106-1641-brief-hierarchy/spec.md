# U2단계 명세서: 브리프 위계와 누를 곳

- 작성일: 2026-11-06
- 요약: 브리프 첫 화면에서 탭 본문(뉴스 목록, 영상·빌더·수요 항목)이 먼저 보이게 일정 상자를 접힌 채 시작하고 요약·키워드를 뉴스 탭에만 두며, 빌더·수요 항목을 뉴스 줄처럼 접고, 거르기 칩을 있는 값·건수로 바꾸고, 폰의 모든 누를 곳을 44px로 넓힌다. U1에서 넘어온 일정 이름 링크의 도착과 섹션 탭의 Tab 순서도 맞춘다.
- 종류: 변경 건 (공개 사이트의 앱 화면, 정적 HTML, 디자인 기준 문서를 바꾼다. 데이터·수집·DB는 바꾸지 않는다)
- 단계: [`docs/plan.md`](../../plan.md)의 U2. UI/UX 감사 단계(U1·U2)의 둘째 단계이고, U1(완료)이 바꾼 크기와 배치 위에서 한다.
- 이 문서는 기획과 요구사항만 담는다. 설계와 작업 계획은 구현하는 AI가 정한다.
- 공개 여부: 원본 저장소와 사이트는 이미 공개다. 바뀐 화면은 머지 뒤 다음 `/brief`의 배포로 공개된다.

## 1. 목표

- **지금 상태:** UI/UX 감사(2026-11-06, [보고서](../../ui-ux-audit/20261106-1025/report.md))의 원인 C1·C6·C7·C8 규칙은 [`docs/design.md`](../../design.md)의 "위계와 상호작용 규칙"에 있지만 코드는 그대로이고, design.md "확인 방법"의 "알려진 예외 (해소 예정)" (가)·(나)로 남아 있다. 2026-11-06 main(1cc2a3c, U1 머지 뒤)에서 측정 데이터로 잰 값:
  - 브리프 375 첫 화면: 첫 뉴스 줄(`.list .item`) 윗선 464px(1280은 420px). 그 위에 그날 요약 문단·키워드, 펼친 '이번 주 일정|지표' 상자, 대분류 칩 줄이 있다. 빌더 탭 첫 항목 윗선 454px, 수요 탭 482px(영상·빌더·수요 탭에도 요약·키워드와 상자가 그대로 있다).
  - 빌더 탭 375 전체 페이지 높이 2809px, 첫 빌더 항목의 '기한' 칸 윗선 721px(1280은 2612px·676px). 수요 탭 3156px. 빌더·수요 항목은 칸 7~14개가 늘 펼쳐져 있다.
  - 거르기 칩: 대분류 칩은 그 탭에 없는 분야도 모두 보이고(누르면 '이 분류의 뉴스가 없다.'), 건수가 없고, 첫 칩이 '전체'라 하단 섹션 탭 '전체'와 같은 글이다. 대분류 'IT·AI'는 섹션 탭 'IT·AI'와 같은 글이다.
  - 폰 누를 곳(375, 전체 페이지, 44px 미만 / 24px 미만): 브리프 `/` 14·0, `/#videos` 10·1, `/#builder` 5·0, `/#demand` 5·0, `/issues` 11·0, 이슈 페이지 12·0, `/entities` 4·0, 인물 페이지 20·0, `/terms` 43·0, `/schedules` 28·17, `/indicators` 1·0, 지표 페이지 4·0, 영상 페이지 1·1, `/about` 12·0, `/privacy` 4·0, `/dates`·검색·없는 페이지 0·0. 1280의 24px 미만은 `/terms` 28, `/schedules` 18, `/#videos`·`/indicators`·영상 페이지·`/about` 각 1. 작은 것은 상자 탭(32px)·접기 버튼(32×32)·상자 일정 줄(30px)·'일정 전체 ›'(28px)·칩(28px)·이슈·인물 페이지의 줄 링크(30px)·용어 색인(30px)·일정 이름(22px)·일정 안의 글 링크(15px)·소개·처리방침 글 링크(25px) 등이다.
  - U1에서 넘어온 것(plan 3.20): 일정 화면의 일정 이름은 처음 근거 뉴스로 가고, 브리프 상자·펼친 카드·이슈 페이지의 같은 이름은 일정 화면으로 가 'C3 같은 이름은 같은 동작'과 다르다. 브리프 하단 섹션 탭이 DOM 끝(바닥글 뒤)에 있어 Tab 순서의 맨 끝이다.
- **바꾸려는 이유:** 브리프를 열면 바로 읽을 것(탭 본문)이 보이고, 빌더·수요에서 먼저 볼 칸(지금 할 일·기한, 요지·근거 수준)을 스크롤 없이 찾고, 칩을 눌러 빈 결과를 만나지 않고, 폰에서 어느 것이든 쉽게 누르게 한다(plan U2 목적).
- **쓰는 사람:** 매일 폰과 브라우저로 브리프를 보는 프로젝트 주인과, 검색으로 들어오는 공개 방문자.
- **충분한 수준:** plan U2의 끝난 상태 — 일정 상자가 접힌 채 시작하고, 영상·빌더·수요 탭에는 그날 요약이 없으며, 빌더·수요 항목이 접히고, 거르기 칩이 건수와 함께 있는 값만 보인다. 375 폭의 모든 화면이 누를 곳 44px 관문을 통과한다. design.md의 알려진 예외 (가)·(나)를 지운다. 감사가 넘긴 과제 둘을 처음 쓰는 사람이 헤매지 않고 해낸다.

## 2. 확정된 결정과 제약

### 2.1 계획과 감사에서 가져온 결정 (다시 묻지 않는다)

- **감사 승인(2026-11-06, 사용자):** C1·C6·C7·C8의 규칙은 design.md "위계와 상호작용 규칙"의 "먼저 보일 것", "빌더·수요 항목 접기", "같은 대상의 이름"(거르기 칩 부분), "누를 곳" 문장 그대로다. C6은 9.8·9.97 명세의 늘 펼침과 2026-11-02 '첫 실행 일주일 뒤 보기'를 뒤집었고, C7은 2026-11-01 '앱 상단 44px 그대로'를 뒤집었다(`docs/memory.md` 2026-11-06).
- **넘어온 것(plan 3.20, 사용자가 U2로 넘김):** 일정 이름 링크의 도착, 섹션 탭 Tab 순서.
- **기준 문서 안에서 지키는 결정:** 뉴스 줄에 펼침 표시를 두지 않는다(design.md "사람이 정할 일"). 이번 주 일정|지표 상자는 없애지 않는다(6단계 X7). 그날 요약·키워드는 뉴스 탭과 정적 HTML에 그대로 둔다(1·3단계 브리프 필수 요소). 출처·원문 링크, '틀린 내용 알리기', 커뮤니티 표본 설명은 펼친 칸에 늘 있다(약관·정책 요소). YouTube 약관 링크와 영상 제목 원문은 줄이거나 감추지 않는다. U1의 부품 모양·글자 크기 토큰·날짜 표기·되돌아가기 규칙은 바꾸지 않는다.
- **디자인:** 새 방향이 없다. 화면은 `docs/design.md`를 따른다. 접힌 빌더·수요 줄은 뉴스 줄의 기존 부품과 토큰으로 만든다(`write-spec` 5장, 시안 없음).
- **운영(D14, 2026-10-31 memory):** 매일 06시경 예약 `/brief`가 메인 폴더 main의 깨끗한 작업 트리로 돈다. 작업은 메인 폴더 밖 worktree에서 한다. CI는 없다.

## 3. 범위

### 넣는 것

1. 먼저 보일 것(C1): 일정 상자의 처음 상태 접힘과 펼침을 저장하지 않기(S6, 처리방침 목록 고치기 S7 포함), 영상·빌더·수요 탭의 요약·키워드 빼기.
2. 빌더·수요 항목 접기(C6, S8·S9·S12)와 펼칠 때 화면 튐 막기(S10, 뉴스 줄 포함).
3. 거르기 칩(C8, S1~S3·S11·S12): 있는 값만, 건수, 첫 칩 글, 넘침 표시.
4. 폰 누를 곳 44px와 모든 폭 24px(C7).
5. 일정 이름 링크의 도착(plan 3.20, S5).
6. 브리프 섹션 탭의 Tab 순서(plan 3.20, S4).
7. 기준 문서 고치기: 이 단계로 바뀐 것과 알려진 예외 (가)·(나)를 `docs/design.md`에 맞춘다.

### 넣지 않는 것

- 모든 뉴스 줄의 펼침 표시: 기준 문서가 사람이 정할 일로 남겼다.
- 정적 HTML의 빌더·수요 항목 접기와 일정 상자: 자바스크립트 없이 읽는 페이지라 지금처럼 모든 칸을 펼쳐 둔다(정적 HTML에는 일정 상자가 없다). 요약·키워드도 정적 HTML에 그대로 둔다(C1 규칙).
- 감사의 가설 H1~H5: 근거가 없어 다음 감사의 재료로 남겼다.
- U1 결과 보고서의 제안 중 인물 목록의 기준 해, E2E `stageU1` 묶음 시간: 이 단계의 목표와 관계없다. U1이 U2에 넘긴 정리 제안(누를 곳 44px을 `.text-link`·`a.nrow` 기본 규칙으로 올리기, `.seg` 채우기를 `Segmented` 변형으로, 기준 해를 화면 단위로 내리기)은 구현 방법이라 AI 재량이다(7장).
- README 두 파일의 첫 화면 이미지(`docs/images/site-home.jpg`): 3단계에 실제 데이터로 찍은 것이고, 새로 찍으려면 실제 데이터(이 명세서는 열지 않는다)나 지어낸 데이터 중 무엇을 보일지 사람이 정해야 한다. 결과 보고서 제안에 남긴다.
- 넓혀 보기에서 고르지 않은 것: 뒤로 가기로 펼친 카드 닫기(U1의 기록 되돌리기와 맞물려 뒤로를 여러 번 눌러야 하는 문제가 생길 수 있다), 펼친 칸 끝의 접기 버튼(근거가 엇갈린다), 탭마다 스크롤 위치 기억(근거가 약하고 뉴스 탭끼리는 맨 위가 맞을 수 있다).
- 데이터·수집·DB·`/brief` 단계: 화면만 바꾼다.

### 해당 없음

- 인증과 권한, 사용자 입력을 받는 서버, 개인정보 수집, 비용, 외부 서비스 연동, 예약 작업 변경: 정적 사이트의 화면만 바꾸고 새 저장·호출이 없다. 일정 상자의 펼침은 저장하지 않고 `history.state`로만 기억한다(S6). 저장 키 `tidwyn.weekBox`를 더 쓰지 않아 처리방침의 기록 목록에서 빠진다(새로 모으는 것은 없다).
- 배포: 구현 중에는 배포하지 않는다. 머지 뒤 다음 `/brief`가 빌드·배포한다(7장).
- 데이터 이전: 없다.

E2E — 로컬 스토리지에 `tidwyn.weekBox=open`을 넣고 열면 상자가 접힌 채이고 그 값이 지워진다.
3. **요약·키워드는 뉴스 탭에만:** 그날 요약 문단(`.headline`)과 키워드(`.kw`)는 뉴스 탭에서만 보이고, 영상·빌더·수요 탭에서는 그리지 않는다. 정적 HTML은 그대로다. 일정 상자는 모든 탭에 그대로 있다.
   - 확인: E2E — 측정 데이터 375에서 `/`(기본 '한국' 탭)·'전체' 탭에는 요약·키워드가 있고 `/#videos`·`/#builder`·`/#demand`에는 없다. 정적 HTML 단위 테스트는 지금 단언을 그대로 통과한다.
4. **첫 화면의 위계(목표 값):** 측정 데이터·라이트·첫 화면(뷰포트, `fullPage: false`)에서
   - 첫 뉴스 줄(`.list .item`) 윗선 y: 375 464px → 360px 이하, 1280 420px → 310px 이하(뉴스 탭에는 요약·키워드·칩·섹션 요약이 남는다. 상자를 접은 지금 코드로 375 336px·1280 292px이고, 접힌 줄이 44px가 되는 몫을 더했다).
   - 빌더 탭(`/#builder`) 첫 항목(`main .item`) 윗선 y: 375 454px → 240px 이하. 수요 탭 482px → 270px 이하(요약·키워드가 빠지고 상자가 접힌다).
   - `styles.boxes`(첫 화면): 375·1280 모두 전 값보다 작다.
   - 확인: 측정 도구로 재서 결과 보고서에 전·후 값. 위의 y 값 셋은 측정 데이터 E2E로도 단언한다(375).

### 4.2 빌더·수요 항목 접기 (C6)

1. **줄 전체가 펼침 버튼:** 앱의 빌더 탭(도구 변화, 새 제품, 뜨는 저장소)과 수요 탭 항목은 뉴스 줄처럼 줄 전체가 펼침 버튼(`aria-expanded`, `aria-controls`)이고 처음에는 접혀 있다. 펼침·접힘은 뉴스 줄과 같은 방식(한 번에 하나, 주소 `#<키>`, 펼침 스크롤 규칙)이다. 읽음 버튼은 줄 끝에 그대로 있고 지금처럼 읽음 기록을 바꾼다. 줄 끝에 펼침 표시를 둔다(뉴스 줄의 펼침 표시 규칙은 바꾸지 않는다).
   - 확인: E2E — 빌더·수요 탭의 모든 항목이 처음에 `aria-expanded=false`이고, 줄을 누르면 펼쳐져 나머지 칸이 보이고, 다른 줄을 누르면 앞의 것이 접힌다. 키보드(Tab·Enter·Space)로 같은 일을 한다.
2. **접힌 줄의 칸:** 도구 변화는 분야, 제목, '지금 할 일', 기한. 수요는 갈래·분야, 제목, 요지, 근거 수준. 새 제품·뜨는 저장소는 정정 표시 자리, 이름(글자), 용도(S9). 값이 '없음'인 칸은 접힌 줄에서 빼고 펼친 칸에는 그대로 둔다(S8). '정정됨' 표시는 접힌 줄에도 남는다. 접힌 줄의 기한은 글자로만 쓰고(버튼 안에 링크를 넣지 않는다), 일정 링크는 펼친 칸에 둔다. 빌더 '다시 알림' 링크(`.breminder`)는 펼친 칸에 둔다. 새 제품·저장소의 이름 링크(앱 밖)는 없애고, 원문은 펼친 칸의 출처로 연다(S9).
   - 확인: E2E — 측정 데이터의 빌더·수요 탭 모든 항목에서 접힌 줄 안에 `a`가 없고(axe 버튼 안 대화형 요소 없음은 `design-check` 객관 관문), 접힌 줄에 보이는 칸 제목이 위 칸뿐이다. '지금 할 일: 없음'·'기한: 없음'인 항목의 접힌 줄에 그 칸이 없고 펼친 칸에는 있다. 정정이 있는 항목의 접힌 줄에 '정정됨'이 있다. 새 제품·저장소의 펼친 칸 출처 링크 주소가 지금 이름 링크의 주소와 같다(새 제품·저장소가 있는 날짜로 본다).
3. **펼친 칸:** 나머지 칸은 펼치면 지금 순서대로 보인다. 출처·원문 링크, '틀린 내용 알리기', 커뮤니티 표본 설명은 펼친 칸에 늘 있다. 접힌 줄에 보인 칸을 펼친 칸에서 다시 보일지는 AI 재량이되 칸 순서(design.md)를 바꾸지 않는다.
   - 확인: E2E — 펼친 빌더·수요 항목에 출처 링크, 제보 링크, (커뮤니티 근거가 있는 흐름은) 표본 설명이 있다.
4. **링크로 들어온 항목은 펼쳐 연다:** 주소 `#<항목 키>`로 들어오면(빌더 '다시 알림', 수요 '이어짐', 일정에서 빌더 항목으로 가는 링크, 제보 메일의 주소, 정적 HTML에서 넘어온 경우) 그 항목이 펼쳐진 채 보인다. 펼친 항목은 브라우저 뒤로·U1의 기록 되돌리기로 돌아올 때 뉴스 카드처럼 되살아난다.
   - 확인: E2E — 다시 알림 링크와 수요 이어짐 링크를 누르면 원래 항목이 펼쳐져 보이고, 펼친 항목에서 이슈 페이지로 간 뒤 브라우저 뒤로를 누르면 그 항목이 펼쳐진 채다.
5. **목표 값:** 측정 데이터·375·라이트에서 빌더 탭 전체 페이지 높이 2809px → 1600px 이하, 첫 도구 변화 항목의 기한 글 윗선 y 721px → 420px 이하(접힌 줄의 기한 글로 잰다), 수요 탭 전체 페이지 높이 3156px → 1800px 이하. 지금 최근 날짜의 빌더 탭은 도구 변화 4건(항목 높이 497~562px), 수요 탭은 3건(638~1042px)이다.
   - 확인: 측정 도구, 결과 보고서에 전·후 값. 측정 데이터 E2E로도 단언한다.
6. **펼칠 때 화면 튐 막기(S10):** 뉴스 줄과 빌더·수요 줄에서, 위에 펼친 줄이 있을 때 그 아래 줄을 누르면 위 줄이 접히고 누른 줄의 윗선 y(화면 기준)가 누르기 전과 같다(±2px). 정정 기록 카드는 design.md "펼침 스크롤" 규칙이 그 뒤에 그대로 적용된다. 화면 위에서 펼친 줄이 이미 보이지 않을 때도 같다. 같은 y를 지킬 수 없으면(스크롤이 0보다 위로 가야 하면) 누른 줄의 윗선을 머리글 바로 아래에 둔다(S10).
   - 확인: E2E(375, Chromium, 브라우저의 자동 스크롤 보정을 끈 상태 `overflow-anchor: none`으로 Safari와 같은 조건을 만든다) — 측정 데이터 브리프에서 첫 뉴스 줄을 펼친 뒤 (a) 둘째 줄의 윗선이 화면 y 약 150에 오게 스크롤하고(같은 y를 지킬 수 있는 자리) 둘째 줄을 누르면 둘째 줄의 윗선 y가 누르기 전과 ±2px 안이다. (b) 첫 카드 끝을 읽은 자리(둘째 줄이 화면 아래쪽, 같은 y를 지킬 수 없는 자리)에서 누르면 둘째 줄의 윗선이 머리글 바로 아래(±2px)다. 수요 탭의 첫 항목(가장 긴 항목)과 둘째 항목으로 (a)·(b)를 본다. 정정 기록 카드의 기존 펼침 스크롤 E2E가 통과한다.

### 4.3 거르기 칩 (C8)

1. **있는 값만, 건수:** 모든 거르기 칩 줄(브리프 대분류, 브리프 영상 묶음, 이슈 목록의 대분류·상태, 일정 화면 대분류, 인물 목록 종류)은 지금 목록에 있는 값만 칩으로 보이고 칩마다 건수를 붙인다('IT·AI 3'). 첫 칩도 건수를 붙인다('모든 분야 12'). 두 줄인 이슈 목록은 다른 줄의 선택과 관계없이 전체 목록 기준으로 세어, 다른 줄을 바꿔도 칩이 사라지거나 나타나지 않는다. 브리프 대분류 칩은 지금 탭의 뉴스(주요 뉴스와 짧은 소식) 기준으로 세고, '안 읽은 것만'을 켜도 건수를 바꾸지 않는다(S1·S2). 인물 목록 종류 칩은 지금처럼 주소(`?kind=`)를 바꾼다(U1 S10).
   - 확인: 단위 테스트 — 칩 값과 건수를 정하는 함수(목록 → 보일 칩과 건수)가 0건 값을 빼고, 첫 칩 건수가 전체 수이고, 이슈 목록 두 줄이 다른 줄 선택과 관계없이 같다. E2E — 측정 데이터 375의 브리프 '한국'·'IT·AI' 탭, 영상 탭, 이슈 목록, 일정 화면(목록 보기의 두 탭 각각과 달력 보기의 보이는 달), 인물 목록에서 칩마다 건수가 있고, 각 칩을 누르면 보이는 줄 수가 칩의 건수와 같다(달력 보기는 고른 날의 일정만 줄로 보이므로, 칩을 누른 뒤 그 달 날짜 칸의 일정 수(`aria-label`의 '일정 N개') 합과 'N월 중' 묶음의 줄 수를 더한 값으로 본다. 달력의 표시 방식은 바꾸지 않는다) (브리프는 '안 읽은 것만'을 끈 상태, 이슈 목록은 다른 줄이 첫 칩일 때. 이슈 목록처럼 더 보기로 나눠 보이는 목록은 전체 건수 문구나 끝까지 펼친 줄 수로 센다).
2. **첫 칩 글:** 칩 줄의 첫 칩은 '전체'가 아니라 그 줄이 무엇의 전체인지 쓴다(대분류는 '모든 분야', 상태는 '모든 상태', 영상 묶음은 '모든 영상', 인물 종류는 '모든 종류'). 건수를 붙인 칩 글('IT·AI 3')은 섹션 탭 이름('IT·AI')과 다른 글로 본다(S3).
   - 확인: E2E — 위 칩 줄의 첫 칩 글이 '전체'로 시작하지 않고 정해진 글로 시작한다. 측정 데이터의 모든 칩 글이 섹션 탭 이름 중 하나와 똑같지 않다(거르기 칩 중 건수 없는 칩이 없다. '안 읽은 것만' 토글은 거르기 칩이 아니라 뺀다).
3. **고른 값이 사라지면(S12):** 고른 칩의 값이 새 목록(다른 탭, 다른 날짜)에 없거나, 인물 목록에 주소로 들어온 종류(`?kind=`)가 0건이면 첫 칩으로 돌아간다(주소도 바꾼다). 이 경우를 단언하던 `test/e2e/stage4.spec.ts`의 빈 상태 테스트는 새 동작으로 고친다(4.7-2). 빈 목록과 '이 분류의 뉴스가 없다.'가 칩 없이 남지 않는다.
   - 확인: E2E — 브리프 '전체' 탭에서 '한국' 탭에 없는 대분류 칩을 고른 뒤 '한국' 탭으로 바꾸면 '모든 분야'가 골라져 있고 뉴스 줄이 보인다(측정 데이터에 그런 분야가 없으면 지어낸 데이터에 더한다, 7장 사전 승인).
4. **넘침 표시(S11):** 375에서 칩 줄이 폭을 넘치면 오른쪽 끝에 다음 칩이 있다는 것이 보인다(끝 칩이 일부만 보이거나, 줄을 바꿔 모든 칩이 보이는 등). '안 읽은 것만'은 375 첫 화면에서 스크롤 없이 보이거나, 칩 줄 끝의 일부만 보이는 칩으로 있다는 것이 보인다. 줄을 바꾸는 방법을 고르면 4.1-4의 목표 값을 함께 지킨다.
   - 확인: E2E — 측정 데이터 375의 브리프 '전체' 탭, 이슈 목록에서 칩 줄 `scrollWidth > clientWidth`이면 줄 안의 칩 중 오른쪽 끝이 줄의 보이는 오른쪽 끝을 넘고 왼쪽 끝은 그 안에 있는 칩이 있다(일부만 보임). 넘치지 않으면 모든 칩이 줄 안에 있다. 많은 데이터에서도 같다.

### 4.4 폰 누를 곳 44px (C7)

1. **목표:** 화면 18곳의 375·라이트·전체 페이지에서 44px 미만 누를 곳 0개, 24px 미만 0개. 1280에서 24px 미만 0개. 펼친 카드(첫 뉴스 줄을 누른 상태), 펼친 일정 상자, 펼친 빌더·수요 항목, 일정 화면의 달력 보기(날짜를 고른 상태 포함, S13), 많은 데이터·빈 상태·오류 상태의 브리프와 일정 화면도 같다. axe `target-size` 위반 0개. 보이는 글자와 줄 높이는 그대로 두고 design.md "배치와 반응형"의 음수 여백 방식으로 넓힌다. 글 안의 링크(소개·처리방침 문단)도 포함한다(design.md "누를 곳 (C7)"의 '소개 링크 포함').
   - 확인: 측정 데이터 E2E 한 묶음이 375 폭에서 화면 18곳과 펼친 상태·달력 보기의 누를 곳(측정 도구와 같은 판정)을 세어 0인지 보고, 1280에서 24px 미만이 0인지 본다. 많은 데이터·빈 상태·오류 상태는 측정 도구와 `design-check`로 본다(E2E로도 보려면 별도 사이트를 더하고 포트는 4323부터 쓴다). 측정 도구로 재서 결과 보고서에 화면별 전·후 값. `design-check` 객관 관문(누를 곳, axe) 깨끗한 회차.
2. **누를 곳이 겹치지 않음:** 넓힌 누를 곳이 이웃 누를 곳과 겹쳐 다른 것이 눌리지 않는다(axe `target-size`가 겹침도 본다). 
   - 확인: 4.4-1의 axe, E2E가 넓힌 요소 중 이웃한 둘(칩 줄, 상자 탭, 소개 문단의 링크)의 가운데를 눌러 의도한 것이 눌리는지 본다.

### 4.5 일정 이름 링크 (plan 3.20, S5)

1. **이름의 도착:** 일정 이름은 어디서나 일정 화면의 그 일정(`/schedules/<id>`)으로 간다: 브리프 상자의 일정 줄, 펼친 카드의 일정 칩, 이슈 페이지의 일정 줄, 일정 화면의 결과 '연기 → …'. 일정 화면(목록·달력의 일정 줄)과 정적 HTML 일정 목록(`/schedules`)의 일정 이름은 링크가 아닌 글자다.
2. **출처 링크:** 일정 화면의 일정 줄에는 처음 근거로 가는 글 링크(`.text-link` 모양, 끝 ›)를 따로 둔다. 근거가 뉴스면 '출처 뉴스 ›'(지금 이름 링크와 같은 주소, 그 날짜 브리프의 그 뉴스), 근거 뉴스가 없고 빌더 항목이면 '빌더 항목 ›', 둘 다 없으면 두지 않는다. 정적 HTML 일정 목록(`/schedules`)도 같다. 이 링크로 간 빌더 항목은 펼쳐진다(4.2-4). 누를 곳은 4.4를 따른다.
   - 확인: 단위 테스트 — 정적 HTML 일정 목록(`/schedules`)의 이름이 `a`가 아니고 출처 링크의 글·주소가 위와 같다. E2E — 일정 화면에서 이름은 링크가 아니고 '출처 뉴스 ›'를 누르면 그 뉴스가 펼쳐진 브리프로, '빌더 항목 ›'을 누르면 그 항목이 펼쳐진 빌더 탭으로 간다. 브리프 상자·펼친 카드·이슈 페이지의 일정 이름을 누르면 일정 화면의 그 일정(강조 줄)으로 간다. U1 E2E에서 일정 이름 `a.t`의 밑줄을 단언하던 것은 새 동작으로 고친다(4.7-2). 과제 수행 "이번 주에 예정된 일정 하나를 찾아 그 일정과 관련된 뉴스를 연다"(4.7-3).

### 4.6 섹션 탭 Tab 순서 (plan 3.20)

1. 브리프 하단 섹션 탭(`nav.tabs`)은 화면 아래에 고정된 채로, 키보드 Tab 순서에서 머리글 다음, 본문(요약·상자·칩·목록) 앞에 온다(S4). '본문으로 건너뛰기'는 지금처럼 본문으로 간다.
   - 확인: E2E — 브리프에서 Tab을 누르면 건너뛰기 → 머리글 → 섹션 탭 → 본문 순으로 포커스가 간다. 화면의 탭 위치(아래 고정)는 그대로다: E2E가 375·1280에서 탭 아랫선이 뷰포트 아랫선에 붙어 있고, 끝까지 스크롤했을 때 바닥글의 마지막 링크가 탭에 가리지 않는지 본다(S14). 탭 여섯·일곱 개인 날의 좁은 폭(320·360)은 `design-check`.

## 7. 진행 규칙

- 작업 폴더는 worktree `../tidwyn-stageU2`이다. Bash 명령은 worktree 절대 경로로 `cd`한 뒤 실행하고, 파일 도구는 그 절대 경로를 쓴다. 서브에이전트 지시에도 넣는다. 실제 데이터 폴더 `data/`와 운영 주소(`tidwyn.vercel.app`)는 열지 않는다. 예외: 머지 시점을 판단할 때만 메인 폴더 `data/runs/` 실행 기록의 아래 칸(`push`, `officialDemand`)을 읽고, 다른 칸은 출력하지 않는다.
- **예약 실행과 겹치지 않는 때:** U1 명세서(`docs/specs/20261106-1150-site-cleanup/spec.md`) 7장과 같다. 00:00~05:49, 또는 메인 폴더 `data/runs/`에 오늘(KST) 시작한 실행 기록 중 가장 늦게 시작한 것이 있고 그 `push`가 null이 아니며 `officialDemand`가 있고 그 `calls`가 2 이상이거나 `hitDeadline`이 거짓이거나 `status`가 `done`이 아닐 때. 머지는 이때 메인 폴더에서 한다. 아니면 사용자에게 알리고 그때까지 기다린다. 머지 뒤 worktree와 브랜치를 지운다. 작업 브랜치는 push하지 않는다.
- 커밋되는 파일과 메시지에 홈 절대 경로를 쓰지 않는다. 측정 결과와 스크린샷 원본은 `.test-data/` 아래(무시됨)나 세션 임시 폴더에 두고, 보고서에 넣을 스크린샷만 명세서 폴더의 `screenshots/`(무시됨, 2026-10-29 결정)에 둔다.
