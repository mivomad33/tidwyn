명세서: [spec.md](spec.md) · 진행 기록: [progress.md](progress.md)

## 사용자가 할 일

1. **접힌 줄의 칸과 위계 정하기**: 아래 [스크린샷](#스크린샷)(브리프 첫 화면, 접힌·펼친 빌더·수요 항목, 칩 줄)을 보고, 접힌 줄에 보이는 칸(빌더: 묶음·이름·기한, 수요: 분야·수준·한 줄 요지)과 위계를 그대로 둘지 정합니다.
2. **위아래로 붙은 글 링크의 누를 곳 정하기(디자인 점검의 사용자 판단)**: 폰(375)의 일정 줄에서 '출처 뉴스 ›'와 '이슈:' 링크는 줄 간격이 약 18px이라, 44px로 넓힌 누를 곳이 서로 겹칩니다(아래 링크가 겹친 자리를 받습니다). `docs/design.md`의 "글 링크 44px", "줄 높이 그대로", "이웃과 겹치지 않게"가 함께 지켜지지 않습니다. 권하는 안: 지금처럼 두고 design.md에 "위아래로 붙은 글 링크는 나중 링크가 겹친 자리를 받는다"를 더하거나, 두 링크를 한 줄에 둡니다. [디자인 점검](#디자인-점검)
3. **실제 폰 확인(머지 뒤, 머지 승인의 조건이 아님)**: 배포된 사이트를 iPhone Safari로 엽니다. 브리프의 칩·상자·탭·일정 줄을 눌러 보고, 펼친 줄 아래의 줄을 펼칠 때 화면이 튀지 않는지 봅니다. E2E는 Chromium에서 Safari 조건을 흉내 낸 것입니다.
4. **머지 승인**: 직접 머지하지 않습니다. 보고서 맨 위의 사용자 확인 항목이 끝나면 새 세션에서 `/review-done`으로 이 보고서를 검토합니다. 통과와 머지를 승인하면 `review-done`이 머지하고 `docs/specs/README.md`의 상태를 '완료'로 바꿉니다.
   - 머지하면 일어나는 일:
     - 예약 실행과 겹치지 않는 때(명세서 7장)에 메인 폴더에서 main으로 squash merge합니다.
     - 공개 전 점검(`node src/cli.ts precheck`)을 돌리고, 통과하면 `git push origin main`을 합니다.
     - worktree `../tidwyn-stageU2`와 브랜치를 지웁니다. CI는 없습니다.
     - 사이트는 다음 `/brief`가 빌드·배포할 때 바뀝니다.

보류한 것과 승인할 제안은 없습니다(디자인 점검의 사용자 판단 1건은 위 2번). 제안은 [아래](#제안범위-밖)에 있습니다.

## 만든 것

- **먼저 보일 것(C1)**
  - 브리프의 '이번 주' 상자는 처음에 접힙니다. 펼침은 `history.state`에 담아 뒤로 오면 되살립니다. 날짜 화살표는 펼침을 넘깁니다.
  - 옛 저장 키(`tidwyn.weekBox`)는 앱 시작 때 지웁니다. 처리방침의 브라우저 기록 목록도 고쳤습니다.
  - 탭 위 요약·키워드는 뉴스 탭에만 보입니다.
- **빌더·수요 항목 접기(C6)**
  - 줄 전체가 펼침 버튼입니다. 접힌 줄에는 꼭 볼 칸만 있고 줄 끝에 ▸가 있습니다.
  - `#키`로 온 항목은 펼쳐 둡니다.
  - 펼칠 때 위쪽 줄이 접혀도 누른 줄의 화면 위치를 지킵니다. 뉴스 줄에도 적용됩니다.
- **거르기 칩(C8)**
  - 칩은 있는 값만, 건수와 함께 보입니다. 첫 칩은 '모든 분야 N'처럼 건수가 붙습니다.
  - 고른 값이 사라지면 첫 칩으로 돌아갑니다. 375에서 칩 줄이 넘치면 끝 칩이 일부만 보입니다.
  - 적용한 곳: 브리프 뉴스, 영상, 이슈, 인물, 일정(목록·달력).
- **폰 누를 곳 44px(C7)**
  - 375의 모든 누를 곳을 44px 이상으로 넓혔고, 보이는 크기는 그대로입니다. 고대비(강제 색) 모드에서만 넓힌 칸 전체를 테두리 상자로 그려 칩·관련 링크·상자 탭이 커 보입니다.
  - 넓히는 방법: 투명 테두리 + `background-clip`, 글 링크는 아래 여백, 줄 링크는 여백 + 음수 여백.
  - 달력 날짜 칸도 44px입니다.
- **일정 이름 링크(S5)**: 일정 이름은 글자이고, 줄 아래 '출처 뉴스 ›' 또는 '빌더 항목 ›' 링크가 출처로 갑니다. 앱과 정적 HTML이 같은 `sourceLink`를 씁니다.
- **섹션 탭 Tab 순서(S4·S14)**: 섹션 탭이 DOM에서 머리글 바로 뒤로 왔습니다. 화면에는 `order`로 그대로 아래에 붙어 있습니다.
- **기준 문서**: `docs/design.md`에서 알려진 예외를 지우고, C4·C6·C7·C8·C10, 키보드, 펼침 스크롤 규칙과 결정 기록을 고쳤습니다(76a012e).

### 새 테스트가 기능 없이 실패하는 것을 본 방법

- U2 E2E(`stageU2.spec.ts`)를 main 1cc2a3c 코드로 빌드한 사이트(포트 4432)에 돌렸습니다. 기존 동작을 그대로 확인하는 테스트를 빼고 36개가 실패했습니다.
- 그 뒤에 더한 테스트는 고친 부분을 빼고 돌려 실패하는 것을 봤습니다. 대상은 세 가지입니다.
  - 대분류가 없는 탭에 갔다 오는 테스트
  - 펼침 표시를 누르는 테스트
  - 정적 일정 이름 단위 테스트
- 디자인 점검에서 더한 칩 줄 흐림 E2E(4.3-4의 320 테스트)는 고치기 전 코드에서 돌려, 넘치는 320 줄에 `data-more`가 없어 실패하는 것을 봤습니다. 같은 테스트의 1280 이슈 목록 부분은 표시가 넘침과 같은지만 보므로, 칩이 넘치지 않으면 기능 없이도 통과합니다. 근거는 320 부분입니다.
