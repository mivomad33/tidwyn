## 사용법

`/brief`가 차례로 부른다. 손으로 부를 일은 없다. `--run`은 그 실행의 실행 기록 파일이다.

| 명령 | 하는 일 |
|---|---|
| `node src/cli.ts video-fetch --run <실행 기록>` | 가장 늦은 브리프 날짜의 영상 후보를 받아 목록을 쓴다. 이미 고르기가 끝났거나 이 실행에서 이미 받았으면 YouTube를 부르지 않는다 |
| `node src/cli.ts video-check --run <실행 기록>` | 고르기 파일(`work/videos.pick.json`)을 검사만 한다 |
| `node src/cli.ts video-apply --run <실행 기록>` | 검사 → 한 번에 적용 → 고르기 끝남 → 영상 작업 파일 지우기. 실패하면 실행 기록에 남기고 파일을 둔다 |

- **새 화면 주소:** `/privacy`(개인정보 처리방침). 영상 탭은 브리프 주소 뒤에 `#videos`를 붙인다.
- **키 문제:** 요약에 "키 확인 필요"가 나오면 `docs/operations.md`의 영상 절을 본다.

   - **결과(사용자 결정, V3을 고침):** 차트는 정보성 4개(뉴스·정치, 교육, 과학·기술, 비영리·사회운동)와 엔터테인먼트·코미디만 받고, 그 밖과 전체 차트는 받지 않는다(5bb39b2). 시험에서 고른 16개의 실제 카테고리를 YouTube에서 확인하니 교육 6, 과학·기술 5, 엔터테인먼트 2(KBS 다큐), 게임 1, 인물·블로그 1, 비영리 1이었고, 카테고리가 엉뚱한 4개는 모두 검색으로 들어왔다. 차트에서 고른 3개는 모두 과학·기술 차트였다. 사용자가 든 지식 채널 12곳의 최근 영상 카테고리도 확인했다: 슈카월드는 코미디, 지식한입·간다효는 엔터테인먼트라서 두 카테고리를 남겼다. 확인에 YouTube를 검색 12번, 약 1,300단위 썼다(PT 10-30). 즐겨 보는 채널 목록에서 받는 방식은 사용자가 하지 않기로 했다.
2. **고르기 기준 보완(스킬 문서):** 시험에서 고른 서브에이전트가 따르기 어렵다고 한 점이다.
   - 1,600여 줄을 걸러 읽는 요령이 없다. 예: 검색 후보를 먼저 보고, 차트는 교육·과학·다큐 카테고리만 본다.
   - "제품 리뷰"와 "분석", "같은 주제"의 경계가 애매하다.
   - 설명이 120자에서 잘려, 추천 이유가 제목을 바꿔 말한 수준에 그치기 쉽다.

   사용자가 검토 파일을 본 뒤 기준과 함께 고치면 좋다.
3. **start의 사이트 폴더 읽기 비용:** 30일 지우기가 사이트 입력·결과물의 JSON을 모두 열어 본다. 지금은 하루 한 번 몇 초지만, 사이트가 커지면 파일 이름으로 날짜를 먼저 거르는 방식이 낫다.
