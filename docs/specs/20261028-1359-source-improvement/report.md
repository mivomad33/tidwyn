### 남은 한계

- **Reuters·AP를 대표 출처로 쓰지 못했습니다.** 후보 목록에 기사는 많이 들어오지만, 원문 주소를 웹 검색으로 거의 찾지 못했습니다. 검색 도구가 이 도메인을 거부하거나, 결과에 나오지 않았습니다.
  - 그래서 우선 출처 비율은 국내외 일간지·방송·IT 매체로 채워졌습니다.
  - Reuters·AP 후보 목록은 지금 "그날 무엇이 중요한가"를 고르는 신호로 쓰입니다.
  - 통신사 원문 링크를 얻으려면 다른 수단이 필요합니다. 예를 들어 구글 뉴스 중간 주소를 풀기(명세서가 범위 밖으로 둠)나 매체 공식 피드를 더 찾는 방법이 있습니다. 이는 제안으로 남깁니다.
- 연합뉴스·BBC 공식 RSS는 최근 몇 시간~하루치만 담아서, 늦게 수집하는 날짜에는 원문 링크가 있는 항목이 줄어듭니다.
- 후보 md 목록이 큽니다(이번 260KB, 약 1,700건). 스킬은 매체별로 나눠 읽거나 주제어로 찾아 읽도록 안내합니다.

## 재량으로 정한 것

- **등록 도메인 계산:** "나라 도메인 + 2단계 접미사면 셋째 이름까지"로 근사했습니다. 공개 접미사 목록을 쓰지 않은 것은 런타임 의존성을 두지 않기 위해서입니다.
- **후보 파일:** JSON(전체)에 더해 짧은 md를 만들었습니다. 실제 JSON이 약 900KB여서 Claude가 읽기 어려웠기 때문입니다.
- **구글 뉴스 검색 나누기:** 도메인마다 날짜 범위 2개와 주제어로 나눴습니다(Reuters 8개, AP 6개, 연합뉴스 6개).
  - 요청 사이 간격은 1초, 요청마다 시간 제한은 20초입니다.
  - User-Agent에는 개인 RSS 리더라고 밝힙니다.
- **백업 형식 버전:** 1로 유지했습니다. 새 항목이 선택 항목이라 이전 백업과 호환됩니다.
- **`main`과 `mainAsync`:** `main`은 동기로 두고, 네트워크를 쓰는 `feeds`만 `mainAsync`로 실행하게 했습니다. `main`의 반환 타입을 바꾸면 1단계 테스트 줄을 고쳐야 해서, 4.2-5에 걸리기 때문입니다.
