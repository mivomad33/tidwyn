## 재량 결정

- 우선 출처 판별·매체 묶기는 `src/outlets.ts`. 등록 도메인은 공개 접미사 목록 없이 "나라 도메인 + 2단계 접미사(co, go, or 등)면 셋째 이름까지"로 근사한다. 런타임 의존성을 두지 않기 위해서다.
- 후보 명령 이름은 `feeds`. 결과는 `work/<날짜>.candidates.json`(전체)과 `.candidates.md`(Claude가 읽는 짧은 목록). 실제로 받아 보니 JSON이 약 900KB(구글 뉴스 중간 주소가 김)라 Claude가 읽기 어려워 md를 더했다. md에는 중간 주소를 빼고 "(중간 주소)"로만 적는다.
- 구글 뉴스 검색 나누기: 도메인마다 [전날~다음 날], [대상일~이틀 뒤] 두 범위 + 주제어(Reuters 8, AP 6, 연합뉴스 6). BBC는 두 도메인(bbc.com, bbc.co.uk). 구글 요청 사이 1초, 요청마다 20초 제한, User-Agent는 개인 RSS 리더임을 밝힌다.
- 직접 받는 BBC 피드의 매체명은 구글 뉴스와 같은 "BBC"로 둬 중복을 줄였다.
- 백업 형식 버전은 1로 둔다. 새 항목은 있을 때만 들어가는 선택 항목이라 이전 백업과 호환된다. 그래서 backup.test.ts의 버전 숫자는 고치지 않았다.
- `main`은 동기 그대로 두고 네트워크를 쓰는 `feeds`만 `mainAsync`로 실행한다. `main`의 반환 타입을 바꾸면 flow.test.ts의 기존 줄을 고쳐야 해서(4.2-5가 허용하지 않음) 이렇게 했다. CLI 진입점은 `mainAsync`를 쓴다.
- 실행 요약의 우선 출처 비율은 DB에서 저장한 브리프를 읽어 계산한다.

## 명세서가 놓친 점

- 4.1-1: 후보 파일 형식은 재량이었지만, 실제 크기(구글 뉴스 중간 주소 때문에 약 900KB)는 명세서가 예상하지 못했다. Claude가 읽을 짧은 목록을 따로 만들었다.
- 4.2-5: `main`의 반환 타입을 바꾸는 것도 기존 테스트 줄 변경이 되어 막힌다. 함수를 나눠 피했다.

- 4.6-1: 시험 실행의 조사·작성은 서브에이전트가 했다(SKILL.md 0장의 서브에이전트 규칙대로). 시작(start test)과 후보 목록(feeds)은 실제 피드 확인을 겸해 먼저 돌린 같은 실행 기록을 썼다.
- 4.6: 웹 검색으로 Reuters·AP·BBC 기사의 원문 주소를 거의 찾지 못했다(검색 도구가 이 도메인을 거부하거나 결과에 나오지 않음). 그래서 우선 출처 비율은 주로 국내외 일간지·방송·IT 매체로 채워졌다. 명세서는 "원문 주소를 웹 검색으로 찾는다"를 전제로 했는데, 통신사에서는 이 전제가 잘 성립하지 않는다.
