## 재량 결정

- 명령 이름 `video-refresh`: 다른 영상 명령과 같은 모양이다.
- 되돌리는 설정은 `src/videoRefresh.ts`의 상수 `VIDEO_REFRESH_STOPPED`다: L1이 저장소 안의 값을 요구한다.
- 호출 실패는 종류와 관계없이 그 실행의 새로 받기를 멈춘다: 다음 실행이 다시 하고, 할당량을 더 쓰지 않는다.
- 읽을 수 없는 항목은 제목·채널·올린 시각·썸네일이 비었거나 길이를 못 읽는 경우다: 4.1-4가 정하지 않아 표시에 꼭 필요한 값으로 잡았다.
- 날짜별 영상 파일 `videos-<날짜>.json`, 달 목록은 `videoGroups`, 이슈 묶음은 `videoRefs`: 이름이 평평해 기존 noindex와 HTML 검사가 그대로 덮고, 파일 수가 날짜 수로 묶인다.
- 받은 날로 나눈 수를 달 목록에 둔다: 파일을 받기 전에 30일 지난 영상을 뺀 N을 내야 한다.
- 지어낸 데이터에 `videosArchive`와 별도 E2E 데이터(`video-data`)를 뒀다: 기존 E2E 데이터(7일)를 넓히면 다른 테스트 기대값이 흔들린다. 일정·지표 데이터와 같은 방식이다.
- 관련 영상은 처음 5개의 날짜 파일만 받고 더 보기를 누르면 나머지를 받는다. 앞 날짜가 받아질 때까지 뒤 줄을 보이지 않아 순서가 바뀌지 않는다.
- `recent`를 `picked`로 바꿨다: 날짜 조건이 사라져 이름이 거짓이 됐다. 테스트의 해당 줄이 바뀐다.
- `SITE_DATA_VERSION`은 올리지 않았다: 앱이 읽지 않는다(4.3-6).
