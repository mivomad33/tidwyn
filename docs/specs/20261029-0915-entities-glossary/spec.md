# 4단계 명세서: 인물·기관·국가와 용어 사전

- 작성일: 2026-10-29
- 요약: `/brief`가 뉴스에서 인물·기관·국가와 어려운 용어를 뽑아 연결하고, 이미 쌓인 뉴스에도 채운다. 사이트에 인물·기관·국가 페이지와 용어 사전을 더하고, 뉴스 카드에서 그곳으로 링크한다.
- 종류: 변경 건 (1~3단계의 `/brief`, 저장, 백업, 사이트를 바꾼다. 실제 데이터가 매일 쌓이고 사이트가 공개되어 있다)
- 단계: [`docs/plan.md`](../../plan.md)의 4단계(인물·기관·국가와 용어 사전). 3단계를 참조한다.
- 이 문서는 기획과 요구사항만 담는다. 설계(스키마, 라이브러리, 폴더 구조)와 작업 계획은 구현하는 AI가 정한다.
- 공개 여부: 원본 저장소와 사이트는 이미 공개다. 새 데이터(인물·용어 설명)도 백업과 사이트로 공개된다.

## 1. 목표

- **지금 상태:** `/brief`가 매일 브리프를 모아 DB에 저장하고, 뉴스를 이슈에 연결하고, 7일마다 중복 이슈를 합치고, `data` 브랜치에 백업하고, 사이트를 빌드해 `https://tidwyn.vercel.app`에 배포한다(1~3단계). 뉴스에 나온 인물·기관·국가와 용어는 데이터로 없다. 이슈 요약에 "핵심 인물·국가"가 문장으로만 들어 있다(2단계). 2026-10-29 기준 실제 DB(스키마 버전 3, 백업 형식 2)에 날짜 2개(2026-10-27, 10-28), 뉴스 62건, 이슈 53개가 있다. 원본 저장소 `mivomad33/tidwyn`은 공개다.
- **바꾸려는 이유:** 이슈와 다른 두 번째 연결 축(같은 인물·기관·국가가 여러 이슈에 걸쳐 나오는 이력)과, 같은 설명을 반복하지 않는 용어 설명을 더한다(시드 "이해를 돕는 기능").
- **쓰는 사람:** 프로젝트 주인 한 사람. 사이트는 공개라 누구나 볼 수 있다.
- **충분한 수준(E5):** 실제 DB의 복사본으로 시험 실행한 결과가 다음을 보인다. 뽑은 대상·용어가 적절한지는 사용자가 마지막에 본다(5장).
  - 저장된 모든 날짜의 뽑기가 끝났다(뽑은 것이 0개인 뉴스도 "처리함"이다).
  - 두 날짜 이상에 나온 인물·기관·국가가 1개 이상 있다.
  - 용어가 1개 이상 있고, 그중 본문 밑줄로 보이는 용어가 1개 이상 있다.
  - 그 결과로 빌드한 사이트가 Vercel 미리보기로 배포되어(E12), 폰 폭(375px)에서 펼친 카드의 밑줄·칩·토글, 인물·기관·국가 목록과 페이지, 용어 사전, 이슈 페이지의 등장 대상, 검색이 동작한다.

## 2. 확정된 결정과 제약

### 2.1 계획과 앞 단계에서 가져온 결정 (다시 묻지 않는다)

- plan D1~D14와 2.2 제약, 1단계 S1~S14, 1.5단계 R1~R7, 2단계 I1~I8, 3단계 P1~P14를 따른다. 특히 다음이다.
  - **D1:** 수집부터 배포와 백업까지 `/brief` 한 번 실행으로 이어진다. 백업은 DB 전체를 복원할 수 있어야 하므로 새 데이터를 백업과 복원에 넣는다. 다시 돌려도 안전해야 한다(같은 연결을 두 번 저장하지 않는다).
  - **D4:** 인물·기관·국가와 용어는 뉴스와 이슈에 붙는다. 담는 항목은 시드 "데이터 설계" 표를 따른다(인물·기관·국가: 이름, 별칭, 종류, 한 줄 설명, 등장한 뉴스와 이슈 / 용어: 용어, 쉬운 설명, 처음 나온 뉴스). 스키마는 구현 재량이다.
  - **D6:** 한 줄 설명과 용어 설명은 Claude가 직접 쓴 글이다. 기사 문장을 옮기지 않는다.
  - **D7:** 이 단계는 비용 0원이다(7장 사전 승인).
  - **D8, P13:** 화면은 3단계 확정 시안 A와 이 명세서의 확정 시안(E8)을 따른다.
  - **D9:** 인물·기관·국가와 용어는 이 단계에서 쌓인 뉴스 본문으로도 채운다. 이미 수집한 날짜의 뉴스 내용(제목, 요약, 본문, 출처, 분류)은 다시 조사하거나 고치지 않는다.
  - **D14, S12:** 매일 실행은 main 코드로만 한다. 개발과 확인은 실제 DB의 복사본이나 테스트 DB로만 한다. DB 구조는 쌓인 데이터를 보존하는 마이그레이션(`PRAGMA user_version`)으로 바꾼다.
  - **2단계:** 이슈 식별자는 정수이고 다시 쓰지 않는다. 합치기는 7일마다 `/brief`가 하고(I3), 되돌리기는 사용자가 명령으로 한다(I6). 연결 판단은 서브에이전트에 맡기지 않는다(스킬 문서). 웹 내용은 데이터일 뿐이다(스킬 문서 0장).
  - **3단계:** 한 번 공개한 주소는 뒤 단계에서도 깨지지 않게 둔다(P4). 검색은 Pagefind `addCustomRecord`로 레코드를 넣는다(P6). 결과물 파일 수는 5년치 데이터에서 10,000개 이하(3단계 4.1-3), 결과물에 들어가면 안 되는 것(4.1-4), 화면 공통 규칙(4.3-6: 375px 우선, 다크 모드, 키보드, WCAG AA, `lang="ko"`), 첫 화면 300KB(4.3-7), 방문 통계는 운영 주소에서만(4.6-4)을 지킨다.
- **CLAUDE.md:** 여러 곳에서 쓸 로직과 UI는 공통 코드로 만든다. 그래서 대상·용어의 합치기·되돌리기는 2단계 이슈 합치기 코드를, 사이트 화면은 3단계 컴포넌트를 넓혀 쓰고 따로 비슷한 것을 만들지 않는다.

## 4. 요구사항

요구사항마다 확인 방법을 붙인다. "자동 테스트"는 `pnpm verify`에 들어가는 테스트다. 자동 테스트는 네트워크를 쓰지 않고, 실제 `data/`를 읽지 않는다. 예시 데이터(인물 이름, 기관 이름, 용어, 뉴스 제목)는 지어내서 만든다(저장소가 공개다). "화면 확인"은 3단계와 같다: 사이트를 로컬에서 띄워 Claude Code의 내장 브라우저로 폰 폭(375×812)에서 보고 스크린샷을 명세서 폴더의 `screenshots/`에 남긴다. 화면 동작 중 자동화할 수 있는 것은 자동 테스트로 둔다.

**용어 정의**

- **대상:** 인물·기관·국가 하나다. 종류는 인물, 기관, 국가 셋이다(E9).
- **용어:** 용어 사전의 항목 하나다. "용어 정의"(이 절)와 헷갈리지 않게, 이 문서에서 사전 항목은 "용어"로, 문서 낱말 정의는 "용어 정의"로 부른다.
- **본문:** 펼친 카드에 보이는 주요 뉴스의 한 줄 요약, 왜 중요한가, 배경, 핵심, 비유, 전망이다. 제목은 본문이 아니다.
- **본문 표기:** 용어가 그 뉴스 본문에 실제로 나온 글자 그대로의 표기다(E8). 없으면 비운다.
- **뽑기:** 한 날짜의 뉴스에서 대상과 용어를 정하고 연결하는 일이다.
- **뽑기 파일:** 한 날짜의 뽑기 결과를 Claude가 쓰는 작업 파일이다. 데이터 폴더의 `work/` 아래에 둔다.
- **뽑기 완료:** 한 날짜의 뽑기 파일이 검사를 통과해 적용된 상태다. 뽑은 것이 0개인 뉴스와 날짜도 완료다.
- **합치기, 흡수, 되돌리기:** 2단계 4.3과 같은 뜻을 대상과 용어에도 쓴다.
- 데이터 폴더, 실제 DB, 실행 조건, 시험 모드, 실행 기록, 뉴스 키, 사이트 데이터, 결과물은 1~3단계 명세서의 용어 정의와 같다.

### 4.1 데이터와 저장

1. **대상 항목:** 대상마다 고정된 정수 식별자(다시 쓰지 않는다), 이름(한국어로 널리 쓰는 표기), 별칭 목록(다른 표기, 영어·원어 이름, 옛 이름. 0개 이상), 종류(E9), 한 줄 설명(E4), 한 줄 설명을 마지막으로 고친 날짜와 근거 뉴스를 저장한다. 처음 등장일·최근 등장일과 뉴스 수는 연결에서 계산한다(저장할지는 구현 재량). 흡수된 대상은 남는 대상을 가리킨다.
   - 확인: 자동 테스트로 대상을 만들고 여러 날짜의 뉴스에 연결한 뒤 읽으면 위 항목이 나오고, 처음·최근 등장일과 뉴스 수가 연결과 맞는다. 합치거나 지운 뒤 새로 만든 대상의 식별자가 앞의 것과 다르다.
2. **용어 항목:** 용어마다 고정된 정수 식별자(다시 쓰지 않는다), 이름, 별칭 목록(약어, 영어 표기 등), 쉬운 설명(E3), 처음 나온 뉴스(날짜와 뉴스 키)를 저장한다. 처음 나온 뉴스는 연결 중 가장 이른 것으로 계산해도 된다. 흡수된 용어는 남는 용어를 가리킨다.
   - 확인: 자동 테스트로 용어를 만들고 뒤 날짜 뉴스에도 연결하면 처음 나온 뉴스가 가장 이른 뉴스다. 그보다 이른 날짜를 나중에 뽑아(채우기 순서가 바뀐 경우) 연결해도 처음 나온 뉴스가 가장 이른 뉴스로 바뀐다.
3. **연결:** 뉴스-대상 연결과 뉴스-용어 연결(본문 표기 포함)을 저장한다. 같은 뉴스와 같은 대상(또는 용어)의 연결은 하나만 둔다. 날짜마다 뽑기 완료 여부를 남긴다(뽑은 것이 0개여도 완료).
   - 확인: 자동 테스트로 같은 뽑기 파일을 두 번 적용해도 연결이 하나씩만 남고, 뽑은 것이 없는 날짜도 완료로 나온다.
4. **마이그레이션:** 지금 형식(버전 3)의 DB를 열면 새 버전으로 마이그레이션되고, 기존 브리프·뉴스·이슈·연결·합치기 기록은 그대로 남으며, 모든 날짜가 "뽑기 안 함"이 된다. 마이그레이션 전에 실행 전 사본이 남는 순서(1단계)는 그대로다.
   - 확인: 자동 테스트로 버전 3 스키마의 DB(브리프, 이슈, 합치기 기록 포함)를 새 코드로 열면 마이그레이션되고, 기존 데이터를 그대로 읽으며, 모든 날짜가 뽑기 대상으로 나온다.
5. **기존 저장과의 관계:** 브리프 작업 파일 형식과 연결 파일 형식에 대상·용어 항목을 더하지 않는다(뽑기는 뽑기 파일이 맡는다, E6). 1·1.5·2단계의 저장·검사·연결 동작은 바꾸지 않는다.
   - 확인: 1~3단계 테스트가 통과한다(4.10-1).

### 4.2 뽑기 단계 (E1, E3, E4, E6, E9, E11)

1. **실행 순서와 입력:** `/brief`에서 뽑기는 다음 순서로 돈다.
   - 2단계의 소급 연결(스킬 문서 7단계)을 마친 뒤, 새 날짜를 조사하기 전에 "뽑기 안 함"인 저장된 날짜를 오래된 날부터 뽑는다. 이미 쌓인 날짜와 지난 실행에서 뽑기가 실패한 날짜가 여기에 든다. 그 날짜의 이슈 연결이 아직 실패 상태여도 뽑기는 한다(서로 기대지 않는다).
   - 새 날짜마다 그 날짜의 이슈 연결(스킬 문서 12단계)을 마친 직후 그 날짜를 뽑는다. 연결이 실패했어도 뽑기는 한다. 저장하지 못한 날짜는 뽑지 않는다.
   - 뽑기의 입력은 DB에 저장된 그 날짜 뉴스의 글(제목과 본문, 짧은 소식은 요약)뿐이다. 뽑으려고 웹 검색을 하거나 원문 페이지를 읽지 않는다. 한 줄 설명과 용어 설명은 그 글과 Claude의 일반 지식으로 쓴다(E3).
   - 뽑기는 서브에이전트에 맡기지 않고 메인이 한다(앞 날짜에서 새로 생긴 대상·용어를 읽어야 하기 때문이다. 이슈 연결과 같다).
   - 날짜 단위로 적용한다. 한 날짜의 뽑기 파일이 검사를 통과하면 그 날짜의 새 대상·용어, 연결, 설명 고침을 한 번에 적용하고 뽑기 완료로 둔다. 통과하지 못하면 아무것도 적용하지 않는다.
   - 확인: 스킬 문서(4.9-1)에 이 순서와 각 단계가 부르는 명령이 있다(읽어서 확인, 문서 속 명령 이름이 실제 명령과 같은지 자동 테스트). 4.10-2 시험 실행에서 이 순서대로 진행된다.
2. **후보 목록과 검색:** 날짜마다 뽑기 전에 스크립트 명령이 그 날짜의 뉴스와 후보 목록을 데이터 폴더의 `work/` 아래 파일로 쓴다.
   - 뉴스: 뽑기 파일에서 가리킬 뉴스 키, 섹션, 종류(주요 뉴스·짧은 소식), 제목, 본문(짧은 소식은 요약), 주 이슈 이름.
   - 후보 대상·용어: 기존 대상·용어 중 이름이나 별칭이 그 날짜 뉴스 글에 나오는 것, 그리고 그 날짜 뉴스의 주 이슈에 이미 연결된 대상. 항목마다 식별자, 이름, 별칭, 종류, 한 줄 설명(용어는 설명 앞부분), 최근 등장일. 대상·용어가 늘어도 목록 길이가 전체 수에 비례해 커지지 않게 한다.
   - 목록에 없는 기존 대상·용어는 검색 명령(이름·별칭·설명의 낱말)으로 찾는다. 검색어가 지운 이름(E13)과 같으면(정규화한 해시 비교, E15) 결과에 "지운 이름과 같음"이 보인다.
   - 확인: 자동 테스트로 지어낸 DB에서 후보 목록에 본문에 이름이 나온 기존 대상과 별칭이 나온 기존 용어가 들어가고, 관계없는 대상은 들어가지 않으며, 대상 3,000개를 넣어도 목록 줄 수가 그 날짜에 관계된 것만큼이다. 검색 명령이 별칭으로 대상을 찾고, 지운 이름(띄어쓰기만 다른 표기 포함)으로 검색하면 "지운 이름과 같음"이 나온다.
3. **뽑기 파일과 검사:** Claude는 날짜마다 뽑기 파일에 뉴스별로 대상(기존 식별자 또는 새 대상의 이름·별칭·종류·한 줄 설명)과 용어(기존 식별자 또는 새 용어의 이름·별칭·설명, 그리고 본문 표기)를 쓴다. 기존 대상을 고칠 때(E4, 4.2-4)는 근거 뉴스 키와 함께 새 한 줄 설명, 새 이름(옛 이름은 별칭으로 옮긴다), 더할 별칭 중 필요한 것을 쓴다. 기존 용어에 더할 별칭(다른 표기, 약어)도 근거 뉴스 키와 함께 쓸 수 있다. 새 이름과 더할 별칭은 새 대상·용어의 이름과 같은 겹침 검사를 받는다. 스크립트가 검사해 다음을 거부한다.
   - 없는 뉴스 키, 그 날짜의 모든 뉴스가 파일에 나오지 않음(뽑은 것이 없는 뉴스는 빈 목록으로 적는다)
   - 주요 뉴스 한 건에 대상 7개 이상, 짧은 소식 한 건에 대상 4개 이상(E1, E11)
   - 주요 뉴스 한 건에 용어 4개 이상, 짧은 소식에 용어(E3, E11)
   - 종류가 인물·기관·국가 밖(E9)
   - 없는 식별자, 흡수된 대상·용어의 식별자(남는 것을 쓰라고 알린다), 지운 대상·용어의 식별자
   - 새 대상·용어의 이름이나 별칭(기존 것에 더하는 새 이름·별칭 포함)이 기존 대상·용어(같은 종류의 대상, 또는 용어)의 이름·별칭과 겹침, 같은 파일 안의 새 것끼리 겹침, 지운 이름(E13, 해시 비교 E15)과 겹침(지운 이름 기록에 대상의 종류나 "용어"를 함께 남기고, 기존 것과의 겹침과 같은 범위 안에서만 비교한다. 예: 용어 "IMF"를 지워도 기관 "IMF"는 막지 않는다). 겹침 비교는 띄어쓰기·대소문자·가운뎃점 같은 표기 차이를 무시한다(정규화 방법은 AI 재량)
   - 새 대상에 한 줄 설명이 없음, 새 대상이나 고친 한 줄 설명이 한 문장이 아니거나(문장 끝 부호가 둘 이상. 시안처럼 명사구도 된다) 60자를 넘음
   - 새 용어에 설명이 없음, 설명이 세 문장을 넘거나 250자를 넘음(E3의 2~3문장은 스킬 문서의 쓰기 기준이고, 검사는 이 둘만 거부한다)
   - 본문 표기가 비어 있지 않은데 그 뉴스 본문에 글자 그대로 나오지 않음
   - 고침의 근거 뉴스 키가 그 날짜 뉴스가 아니거나, 고치는 대상·용어가 그 뉴스에 연결되지 않음
   - 대상 고침의 근거 뉴스 날짜가 그 대상의 한 줄 설명을 마지막으로 고친 근거 뉴스 날짜보다 이르면(이름 바꾸기에도 같다. 실패한 날짜를 나중에 다시 뽑을 때 옛 직함으로 돌아가지 않게 한다)
   - 같은 뉴스에 같은 대상·용어가 두 번
   - 확인: 자동 테스트로 위 거부 경우를 하나씩 넣은 파일이 거부되고 DB가 바뀌지 않으며, 맞는 파일(이름 바꾸기와 별칭 더하기 포함)은 통과해 적용된다. 이름을 바꾼 대상은 새 이름이 이름이고 옛 이름이 별칭이다. 거부 경우에는 고친 한 줄 설명이 61자인 파일도 넣는다.
4. **뽑기 기준(스킬 문서에 적는다):** 판단 기준은 스킬 문서(4.9-1)에 적고 Claude가 따른다. 기계로 검사할 수 없어 사용자가 마지막에 본다(E5).
   - 대상은 그 뉴스 이야기의 중심이 되는 것만 뽑는다. 지나가며 언급된 것은 뽑지 않는다(E1).
   - 인물은 공적 역할로 뉴스에 나온 공인만 뽑는다. 사건의 피의자·피해자·목격자·유족 같은 일반인은 이름이 기사에 나와도 뽑지 않는다(E1). 애매하면 뽑지 않는다.
   - 한 줄 설명은 직함·소속·역할 같은 중립적 사실만 쓴다. 평가, 혐의, 논란, 사생활은 쓰지 않는다(E4).
   - 붙는 뉴스가 직함·소속·역할이 바뀐 것을 알리면(취임, 사임, 인수, 이름 변경 등) 한 줄 설명을 고친다. 이름이 바뀌면 새 이름을 이름으로, 옛 이름을 별칭으로 둔다(E4).
   - 국가처럼 다뤄지는 지역은 국가로 둔다. 도시·해협 같은 장소는 뽑지 않는다(E9).
   - 용어는 일반 독자가 모를 만한 경제·법·외교·과학·기술 용어와 약어만 뽑는다. 설명은 시점에 따라 바뀌지 않는 정의만, 쉬운 말로 쓴다(E3). 본문에 나온 표기를 본문 표기로 적는다(E8).
   - 이름은 한국어로 널리 쓰는 표기로 쓰고, 영어·원어 이름은 별칭으로 둔다.
   - 확인: 스킬 문서에 위 기준이 모두 있다(읽어서 확인). 4.10-2 시험 결과의 일반인 여부와 설명은 사용자가 마지막에 본다(5장).
5. **고쳐서 다시 검사와 실패:** 위반이 나오면 Claude가 뽑기 파일을 고쳐 다시 검사한다. 날짜마다 최대 2번이다(1·2단계와 같다). 그래도 위반이 남으면 그 날짜는 적용하지 않고 실행 기록에 실패로 남긴다. 뉴스와 이슈 연결은 그대로 두고, 다음 실행이 그 날짜를 다시 뽑는다(E6). 뽑기 실패는 그 실행의 다른 날짜, 합치기, 백업, 빌드, 배포, 요약을 멈추지 않는다.
   - 확인: 자동 테스트로 실패로 기록된 날짜가 다음 실행의 "뽑기 안 함" 날짜에 다시 나오고, 그 날짜의 뉴스와 이슈 연결은 바뀌지 않는다(데이터 폴더 지정 실행으로 확인한다). 시험 모드 실행(실행마다 새 폴더를 쓴다)에서는 뽑기 실패가 실행 기록과 요약에 남고 다른 단계를 멈추지 않는다.

### 4.3 합치기, 되돌리기, 지우기 (E2, E10, E13)

1. **7일 합치기에 함께 넣기:** 2단계의 7일 합치기(같은 점검일, 같은 실행 위치)에서 이슈 후보와 함께 비슷한 대상 쌍(같은 종류끼리)과 비슷한 용어 쌍 후보를 뽑는다. 쌍마다 이름, 별칭, 종류, 설명, 등장한 뉴스 몇 건(날짜·제목)을 담는다. 비슷함을 정하는 방법은 AI 재량이다. 흡수된 것, 지운 것, 되돌려서 "합치지 않음"이 된 쌍은 후보에서 뺀다. Claude가 같은 대상(같은 사람·기관·나라, 같은 뜻의 용어)인지 판단해 합치기 파일에 쓰고, 스크립트가 검사·적용한다. 판단 기준은 스킬 문서에 적는다. 점검일을 바꾸는 규칙(합친 것이 없어도 바꿈, 검사가 2번 고쳐도 실패하면 바꾸지 않음)은 이슈·대상·용어를 함께 한 번으로 본다. 합치기 파일의 이슈 부분이 실패해도 대상·용어 부분을 따로 적용할지는 AI 재량이되, 점검일은 모두 통과했을 때만 바꾼다.
   - 확인: 자동 테스트로 이름이 거의 같은 두 대상(같은 종류)과 별칭이 겹치는 두 용어가 후보에 나오고, 종류가 다른 대상 쌍, 관계없는 쌍, "합치지 않음" 쌍, 지운 것은 나오지 않는다. 점검일 규칙이 2단계 테스트와 같이 동작한다.
2. **합치기 적용:** 흡수되는 것의 연결을 남는 것으로 옮기고(같은 뉴스에 둘 다 연결돼 있으면 하나로 줄인다), 흡수되는 것의 이름과 별칭을 남는 것의 별칭에 더한다. 한 줄 설명·용어 설명은 합치기 파일에 쓴 남는 것의 설명으로 한다(없으면 남는 것의 설명 그대로). 흡수된 것은 지우지 않고 남는 것을 가리킨다(옛 주소를 남는 것으로 보내기 위해서, 3단계 P4). 합치기 기록에 날짜, 둘, 이유, 되돌리기에 필요한 합치기 전 상태를 남긴다. 거부: 없는 것, 이미 흡수되거나 지운 것, 같은 것끼리, 대상의 종류가 다름, 이유가 없음, 설명 규칙(4.2-3) 위반.
   - 확인: 자동 테스트로 적용 결과(연결 이동과 중복 정리, 별칭 추가, 설명, 흡수 표시, 기록)가 맞고, 거부 경우마다 거부되며 DB가 바뀌지 않는다.
3. **되돌리기:** 대상·용어의 합치기 기록 하나를 골라 되돌리는 명령을 둔다(2단계 `unmerge`를 넓히든 새 명령을 두든 AI 재량, 2단계 코드를 공통으로 쓴다). 규칙은 2단계 4.3-4와 같다: 흡수된 것을 합치기 전 이름·별칭·설명·연결로 되살리고, 남는 것은 합치기 전 별칭·연결로 되돌리되 그 뒤에 더해진 것은 둔다. 그 쌍은 "합치지 않음"이 된다. 그 뒤 남는 것이 다시 흡수됐으면 거부하고 먼저 되돌릴 기록을 알린다. 이미 되돌린 기록은 거부한다. 실제 데이터 폴더에서는 실행 조건(S12)을 따르고 바꾸기 전에 DB 사본을 남긴다. `/brief`는 이 명령을 실행하지 않는다. 합치기 기록 목록을 보는 명령 출력에 대상·용어 합치기도 나온다.
   - 확인: 자동 테스트로 합친 뒤 되돌리면 둘이 합치기 전과 같아지고, 합친 뒤 새 뉴스가 붙은 경우 새 연결이 남는 것에 남으며, 되돌린 쌍이 다음 후보에 나오지 않고, 연달아 합쳐진 경우와 실제 데이터 폴더 조건 위반(임시 git 저장소의 다른 브랜치)이 거부되고 DB가 바뀌지 않는다.
4. **지우기 명령(E13):** 사용자가 부르는 명령 하나로 대상 하나나 용어 하나를 식별자로 지운다. 흡수된 식별자를 주면 거부하고 남는 것의 식별자를 알린다(4.2-3과 같다).
   - 그 대상·용어의 연결을 모두 지우고, 식별자는 다시 쓰지 않는다. 이름과 별칭을 "지운 이름"으로 기록해 다음 뽑기에서 같은 이름의 새 대상·용어를 거부한다(4.2-3). 지운 이름은 정규화한 표기의 비밀 키 해시로만 남기고(키 파일의 위치·형식은 AI 재량, E15), 지운 것의 이름·별칭·설명은 DB에 남기지 않는다(E15). 지운 것이 든 합치기 기록의 합치기 전 상태와 이유도 가리고(예: "지운 항목이 든 합치기"), 그 기록은 되돌리기를 거부한다. 지운 것에 흡수되어 있던 것의 이름·별칭·설명도 남기지 않는다. 흡수된 것(별칭으로 들어간 이름 포함)을 가리키는 옛 식별자도 지운 것으로 본다.
   - 지운 것의 주소는 사이트에서 없는 페이지가 된다(4.7-6). 다음 빌드·배포부터 사이트와 검색에서 빠진다.
   - 실제 데이터 폴더에서는 실행 조건(S12)을 따르고 바꾸기 전에 DB 사본을 남긴다. `/brief`는 이 명령을 실행하지 않는다. 출력에 지운 이름, 끊은 연결 수, 다음 `/brief`가 백업·배포한다는 것, 이미 push된 `data` 브랜치 이력, 뉴스 본문(D9), 이슈 이름·별칭·요약(바꾸지 않는다, 범위 밖)에는 남는다는 것, 바로 내리려면 운영 문서의 손으로 하는 배포(main에서 사이트 빌드 뒤 `deploy --dir --db`)를 쓰라는 것을 보인다.
   - 지우기는 되돌리지 않는다(사본으로 복원은 운영 문서에 적는다). 지운 이름을 다시 쓰고 싶을 때 지운 이름 기록을 풀어 주는 방법을 둘지는 AI 재량이고, 두지 않으면 운영 문서에 사본 복원으로 안내한다.
   - 확인: 자동 테스트로 지운 뒤 연결이 없고, 사이트 데이터·검색 색인·DB·백업 파일 어디에도 뉴스 글(제목·본문·요약) 밖에서 그 이름·별칭·설명 글자가 없으며(합치기 기록의 이유와 흡수되어 있던 것 포함. 테스트의 합치기 이유에는 지울 이름을 넣고, 뉴스 글에는 넣지 않는다. DB는 SQL로 읽은 내용으로 보고, 바꾸기 전에 남긴 비공개 사본은 제외한다), 키 파일이 백업·사이트 데이터에 없고, 그 대상이 든 합치기 기록의 되돌리기가 거부되고, 같은 이름(별칭 표기, 띄어쓰기만 다른 표기 포함)을 새로 뽑는 뽑기 파일이 거부되고, 흡수된 식별자로 지우면 거부되고 출력에 남는 것의 식별자가 나오고, 실제 데이터 폴더 조건 위반이 거부된다.

### 4.4 백업과 복원 (D1)

1. **백업 형식:** 백업에 대상, 용어, 연결(본문 표기 포함), 날짜별 뽑기 완료, 대상·용어의 합치기 기록과 "합치지 않음" 쌍, 지운 이름 기록(해시만, E15)을 넣는다. 날짜에 묶이지 않는 데이터는 이슈처럼 날짜 밖 파일에 둔다(파일 나누기는 AI 재량이되 백업 파일 이름 규칙은 3단계 4.1-4의 구분이 유지되게 한다). 대상·용어 데이터가 하나도 없는 DB의 백업은 형식 버전 숫자와 날짜별 뽑기 완료 표시 말고는 지금과 같은 파일과 키를 낸다(2단계 4.5-1과 같은 이유: 기존 백업 테스트의 파일 목록·`meta.json` 단언이 4.10-1 범위 안에서 통과하게 한다). 형식 버전을 올리고, 복원은 지금 형식(1, 2)과 새 형식을 모두 읽는다. 옛 형식 백업을 복원하면 모든 날짜가 "뽑기 안 함"이 된다.
   - 확인: 자동 테스트로 대상·용어·연결·합치기·지우기가 있는 DB를 백업하고 빈 곳에 복원하면 같은 데이터가 나오고(왕복), 가장 큰 식별자의 대상·용어를 지운 DB를 백업·복원한 뒤 새로 만든 대상·용어의 식별자가 지운 것과 다르며(4.1-1의 다시 쓰지 않음이 복원 뒤에도 지켜진다), 형식 2 백업을 복원하면 모든 날짜가 뽑기 대상으로 나온다.
2. **공개 데이터 검사:** 새 백업 데이터도 3단계의 push 전 공개 전 점검과 결과물 검사(메일 주소 모양, 홈 경로, 비밀 값)를 그대로 받는다. 글자 모양 검사 규칙은 바꾸지 않고, 결과물에 들어가면 안 되는 파일 이름 목록(`src/siteCheck.ts`의 백업·작업 파일 이름)에는 이 단계의 새 백업 파일, 뽑기 파일·후보 목록 파일, 지운 이름 키 파일 이름을 더한다(3단계 4.1-4).
   - 확인: 기존 공개 전 점검 테스트가 통과하고, 4.10-2 시험 결과물이 결과물 검사를 통과한다.

### 4.5 실행 요약과 `start` 출력

1. **`start` 출력:** 지금 출력(대상 날짜, 이슈를 연결할 저장된 날짜, 합치기)에 "뽑기할 저장된 날짜(채우기·재시도)" 줄을 더한다. 지운 이름 기록이 있는데 키 파일이 없거나 지금 키와 지문이 다른 기록이 있으면 "지운 이름 일부를 막지 못한다"는 줄도 보인다(E15).
   - 확인: 자동 테스트로 뽑기 안 한 날짜가 있는 DB에서 그 줄에 날짜가 나오고, 없으면 "없음"이다. 지운 이름 기록이 있고 키가 없는 데이터 폴더와, 그 뒤 새 지우기로 새 키가 생긴 데이터 폴더에서 경고 줄이 나온다.
2. **요약:** 실행 요약에 다음을 더한다: 뽑기한 날짜마다 연결한 대상·용어 수, 새로 만든 대상·용어 수, 고친 한 줄 설명 수. 뽑기에 실패한 날짜와 남은 위반. 아직 뽑기 안 한 날짜 수. 합치기 줄에 대상·용어 합치기(남는 것, 흡수된 것, 이유)와 되돌리는 명령. 사이트 빌드 줄에 대상 수와 용어 수. 4.5-1과 같은 조건의 "지운 이름 일부를 막지 못한다" 줄(E15).
   - 확인: 자동 테스트로 요약 출력에 위 줄이 나온다. 지운 이름 경고 줄은 키가 없는 경우와 새 키가 생긴 경우에 나온다.

### 4.6 사이트 데이터와 검색 (E7)

1. **사이트 데이터:** 빌드할 때 DB에서 다음을 사이트 데이터에 더한다. 흡수된 것과 지운 것은 목록에서 빼고, 흡수된 것의 식별자는 남는 것으로 가는 정보만 남긴다.
   - 펼친 카드 본문(3단계의 펼친 카드 데이터)에 뉴스마다 연결된 대상(식별자, 이름, 종류, 한 줄 설명)과 용어(식별자, 이름, 설명, 본문 표기).
   - 대상 목록(식별자, 이름, 종류, 한 줄 설명, 최근 등장일, 뉴스 수)과 대상마다 별칭, 처음·최근 등장일, 등장한 이슈(이슈 식별자·이름과 그 이슈에서 나온 뉴스 수, 흡수된 이슈는 남는 이슈로 묶는다), 등장한 뉴스(날짜, 뉴스 키, 제목, 주 이슈 이름. 최근 순).
   - 용어 목록(식별자, 이름, 별칭, 설명, 처음 나온 뉴스의 날짜·뉴스 키·제목, 나온 뉴스 수).
   - 이슈 데이터에 등장 대상(그 이슈 뉴스에 나온 횟수 순, 최대 10개, 식별자·이름·횟수).
   - 확인: 자동 테스트로 지어낸 DB(날짜 3개 이상, 대상 여럿, 합친 대상 1개, 지운 대상 1개, 용어 여럿, 합친 용어 1개, 합친 이슈 1개)에서 위 항목이 나오고, 흡수된 이슈에 나온 대상이 남는 이슈 쪽으로 세지며, 지운 것은 어디에도 없다.
2. **파일 수와 크기:** 3단계 4.1-3의 파일 수 한도(5년치 데이터에서 결과물 10,000개 이하)를 대상·용어를 더한 5년치에서도 지킨다. 5년치는 3단계 측정 조건(1,826일, 하루 약 42건, 이슈 15,000개)에 대상 15,000개(뉴스당 평균 3개 연결), 용어 5,000개(주요 뉴스당 평균 1개 연결)를 더한 것이다. 그 안에 뉴스 5,000건 이상이 붙은 대상을 하나 넣는다. 3단계 4.3-7의 첫 화면 크기(gzip 300KB 이하)도 그대로 지킨다. 그리고 다음 화면이 처음 받는 사이트 데이터는 각각 gzip 300KB 이하다(5년치에서도): 대상 목록(종류로 거른 각 상태 포함), 뉴스 5,000건이 붙은 대상의 페이지(나머지는 "더 보기"로 받는다), 용어 사전. 나누는 방법은 AI 재량이다.
   - 확인: 지어낸 5년치로 빌드해 결과물 파일 수가 10,000개 이하이고, 위 화면들이 처음 받는 데이터 크기가 300KB 이하다(명령이나 테스트). 보고서에 그때의 결과물 크기·파일 수와 3단계 보고서 값(105.6MB, 2,262개)과의 차이, 실제 데이터 복사본의 값, 1년 뒤 예상 크기(Vercel 무료 한도 100MB에 닿는 예상 시점 포함)를 적는다.
3. **같은 DB, 같은 결과:** 3단계 4.1-2를 새 데이터에도 지킨다.
   - 확인: 3단계의 같은 결과 테스트가 대상·용어가 있는 DB로도 통과한다.
4. **검색(3단계 P6을 넓힘):** 검색 색인에 대상(이름, 별칭, 한 줄 설명)과 용어(이름, 별칭, 설명)를 더한다. 결과를 "인물·기관·국가", "용어", "이슈", "뉴스"로 나눠 보인다(순서는 AI 재량). 대상 결과는 이름·종류·한 줄 설명을 보이고 누르면 그 페이지로, 용어 결과는 이름·설명 앞부분을 보이고 누르면 용어 사전의 그 용어로 간다. 레코드 단위는 4.6-2의 파일 수 한도 안에서 AI 재량이다(3단계처럼 묶어도 된다).
   - 확인: 자동 테스트로 지어낸 데이터의 검색 색인에서 대상 별칭(영어 표기)과 용어 이름이 각각 찾아지고, 조사가 붙은 이름(예: "가짜전자가")이 조사 없는 검색어로 찾아진다. 지운 대상은 찾아지지 않는다. 화면 확인(결과 묶음).

### 4.7 화면 (E7, E8)

화면은 [design/site.html](design/site.html)(확정 시안 D와 새 화면)을 따른다. 시안에 없는 것은 3단계 확정 시안 A와 지금 사이트의 색·글꼴·간격·컴포넌트를 쓴다. 3단계 4.3-5(없는 페이지, 불러오기 오류와 다시 시도, 대기 표시)와 4.3-6(화면 공통)을 모든 새 화면과 동작에 지킨다.

1. **펼친 카드의 용어(E8):** 용어마다 본문 표기가 있으면 본문(한 줄 요약부터 전망까지 순서로)에 그 표기가 처음 나온 곳 하나에 점선 밑줄을 긋는다. 밑줄 낱말을 누르면 그 낱말이 강조되고 그 문단 바로 아래에 설명 상자(이름, 설명, "용어 사전에서 보기" 링크)가 펼쳐진다. 카드 아래 "용어" 칩 줄에는 그 뉴스의 모든 용어가 있고(본문 표기가 없는 용어 포함), 칩을 누르면 같은 설명이 펼쳐지고 칩이 강조된다(본문 표기가 있으면 밑줄 아래, 없으면 칩 줄 아래에 펼친다). 설명은 토글이다: 같은 낱말이나 칩을 다시 누르면 닫히고, 다른 용어를 누르면 그 설명으로 바뀐다(한 카드에 열린 설명은 하나). 밑줄 낱말과 칩은 키보드로 열고 닫을 수 있고 열림 상태를 보조 기술에 알린다(`aria-expanded` 등). 용어가 없으면 칩 줄을 보이지 않는다.
   - 확인: 자동 테스트로 본문 표기가 본문에 여러 번 나와도 밑줄이 하나이고, 본문 표기가 없는 용어는 칩으로만 나오며, 토글(열기, 같은 것 다시 눌러 닫기, 다른 것으로 바꾸기)과 키보드 조작이 맞다. 화면 확인(닫힌 카드, 밑줄 누른 상태, 칩만 있는 용어를 연 상태, 다크).
2. **펼친 카드의 인물·기관·국가:** 카드 아래 "인물·기관·국가" 칩 줄에 그 뉴스의 대상이 이름(인물은 한 줄 설명을 작게)으로 나오고, 누르면 그 대상 페이지로 간다. 대상이 없으면 칩 줄을 보이지 않는다. 칩 줄의 위치는 시안 D대로 본문 아래, 용어 칩 줄 위다. 시안에 없는 지금 카드의 확인 정도·함께 엮인 이슈·출처와의 순서는 전망 → 인물·기관·국가 칩 줄 → 용어 칩 줄 → 확인 정도 → 함께 엮인 이슈 → 출처다.
   - 확인: 화면 확인. 자동 테스트로 칩 링크가 대상 페이지 주소다.
3. **인물·기관·국가 목록:** 모든 대상(흡수·지운 것 제외)을 최근 등장일 순으로 보이고, 종류(전체·인물·기관·국가)로 거른다. 줄마다 종류, 최근 등장일, 뉴스 수, 이름, 한 줄 설명이 나온다. 대상이 많아도 처음 화면이 4.6-2의 크기를 지킨다(나머지는 더 보기 등, AI 재량).
   - 확인: 자동 테스트로 정렬과 거르기 결과가 맞다. 화면 확인.
4. **대상 페이지:** 시안대로 종류, 이름, 한 줄 설명, 별칭, 처음·최근 등장일과 뉴스 수, 등장한 이슈(뉴스 수, 누르면 이슈 페이지), 등장한 뉴스(최근 순, 날짜·주 이슈 이름·제목, 누르면 그 날짜 브리프의 해당 카드. 짧은 소식은 그 날짜 브리프의 해당 줄)를 보인다. 뉴스가 많으면 처음에 일부(개수는 AI 재량)를 보이고 "더 보기"로 이어서 보인다. 흡수된 대상의 주소로 들어오면 남는 대상 페이지를 보이고 "이 항목은 <날짜>에 <남는 것>에 합쳐졌다"를 한 줄 보인다(3단계 이슈와 같다). 없는 식별자와 지운 식별자는 없는 페이지를 보인다.
   - 확인: 자동 테스트로 흡수된 대상 주소가 남는 대상으로 가고, 되돌린 DB로 다시 빌드하면 원래 대상을 보이며, 지운 대상 주소가 없는 페이지다. 화면 확인(뉴스가 많아 더 보기가 있는 대상 포함).
5. **용어 사전:** 모든 용어(흡수·지운 것 제외)를 가나다순으로 한 화면(한 주소)에 보이고, 첫 자음(ㄱ, ㄴ, …, 영문·숫자)별로 묶는다. 데이터는 첫 자음 묶음별로 나눠 필요할 때 불러와도 된다(4.6-2의 크기 때문). 용어마다 이름, 별칭, 설명, 처음 나온 뉴스(날짜·제목, 누르면 그 카드), 나온 뉴스 수가 나온다. 용어마다 고정된 주소가 있어 그 주소로 들어오면 그 용어 위치로 가고 강조된다(카드의 "용어 사전에서 보기"와 검색 결과가 이 주소를 쓴다). 흡수된 용어의 주소는 남는 용어로 가고, 지운 용어와 없는 식별자는 없는 페이지를 보인다. 용어가 많아도 처음 화면이 4.6-2의 크기를 지킨다.
   - 확인: 자동 테스트로 정렬(가나다, 영문·숫자 위치)과 묶음이 맞고, 용어 주소가 그 용어를 가리키며, 흡수·지운 용어 주소가 위 규칙대로다. 화면 확인.
6. **주소:** 대상 페이지, 대상 목록, 용어 사전, 용어 주소는 정수 식별자를 쓰는 깔끔한 경로다(경로 이름은 AI 재량, 3단계 P4와 같은 방식). 한 번 공개한 주소는 뒤 단계에서도 깨지지 않게 둔다. 직접 열거나 새로 고쳐도 화면이 나온다(3단계 4.6-2의 대체 경로 설정에 더한다). 없는 식별자는 없는 페이지다.
   - 확인: 자동 테스트로 새 주소들이 라우팅되고 없는 식별자가 없는 페이지로 간다. 로컬 보기 서버(3단계 `pnpm site:preview`, Vercel과 같은 주소 규칙)에서 각 주소를 직접 요청해 200과 화면 틀이 온다.
7. **이슈 페이지:** 타임라인 아래, 관련 이슈 위에 "등장 인물·기관·국가"를 칩으로 보인다(횟수 순, 최대 10개, 이름과 횟수, 누르면 대상 페이지). 없으면 보이지 않는다.
   - 확인: 화면 확인. 자동 테스트로 순서와 최대 개수.
8. **메뉴와 바닥글:** 머리 메뉴에 "인물·기관·국가"와 "용어 사전"을 더한다. 바닥글에 더할지는 AI 재량이다. 사이트 소개(`/about`)에 인물·기관·국가와 용어 설명도 AI가 쓴 글이라 틀릴 수 있다는 것과, 잘못된 내용은 원본 저장소 이슈로 알려 달라는 것을 한 줄 더한다.
   - 확인: 화면 확인(메뉴 연 상태, 사이트 소개).
9. **화면 확인의 상태:** 위 화면을 375px 라이트로, 펼친 카드와 대상 페이지는 다크로도, 대상 목록은 넓은 화면(1440px)으로도 확인한다. 빈 상태(용어가 하나도 없는 사전, 거른 결과가 없는 대상 목록)와 데이터를 불러오지 못한 오류 상태(3단계 4.3-5)도 새 화면마다 하나씩 본다. 새 화면의 글자 색 대비가 WCAG AA(4.5:1) 이상이다(강조된 낱말 배경 위 글자 포함).
   - 확인: 스크린샷을 보고서에 링크한다. 대비는 시안 색으로 계산해 보고서에 적는다.

### 4.8 미리보기 배포 (E12)

1. **미리보기 배포 명령:** 결과물 폴더를 Vercel 프로젝트 `tidwyn`에 미리보기(운영이 아닌)로 배포하는 방법을 둔다(3단계 `deploy --dir`에 선택을 더하든 새 명령을 두든 AI 재량). 3단계 4.6-1의 규칙(결과물 폴더만 올림, `--scope mivomad33 --project tidwyn`으로 겨냥, Vercel에서 빌드하지 않음, Git 연결 없음, 새 프로젝트를 만들지 않음, 결과물 검사를 통과해야 올림, 대화형 질문 없음)을 그대로 지킨다. 운영 별칭(`tidwyn.vercel.app`)은 바뀌지 않는다. 출력에 미리보기 주소를 보인다. `/brief`는 이 명령을 부르지 않는다(매일 실행은 지금처럼 운영 배포다).
   - 확인: 자동 테스트(가짜 vercel 명령)로 미리보기 배포가 `--prod` 없이 결과물 폴더만 겨냥하고, 결과물 검사에 걸리면 올리지 않는다. 4.10-2에서 실제 미리보기 배포 뒤 `vercel inspect <미리보기 주소> --scope mivomad33`가 준비됨(Ready)을 보이고, 로그인 없이 `curl`로 미리보기 주소를 요청하면 사이트 내용이 아닌 응답(401·403 또는 Vercel 로그인으로 보내는 응답)이 오며, 미리보기 배포 직후 `vercel inspect tidwyn.vercel.app --scope mivomad33`의 배포 ID가 시작 때 진행 기록에 적은 것(5장)과 같다(운영이 바뀌지 않았다. 복사본의 최근 날짜가 운영과 같아 날짜 비교로는 가려낼 수 없다).
2. **운영 문서:** 미리보기 배포 방법과 폰에서 보는 법(Vercel 로그인), 보호가 꺼져 있으면 공개된다는 주의를 운영 문서에 적는다.
   - 확인: 읽어서 확인.

### 4.10 기존 기능 유지와 시험 실행

1. **기존 테스트와 검증:** 1~3단계 테스트가 통과한다. 기존 테스트에서 허용하는 변경은 2단계 명세서 4.8-1과 같다(버전 숫자에 묶인 줄, 새 테스트와 import). 여기에 사이트 데이터·결과물의 파일 목록을 단언하는 줄(예: `test/siteData.test.ts`의 파일 목록)에 이 단계의 새 파일 이름을 더하는 것을 허용한다(대상 목록·용어 사전은 비어 있어도 파일이 있어야 4.7-9의 빈 상태와 불러오기 오류를 나눠 보일 수 있다). 백업 파일 목록 단언은 4.4-1의 규칙으로 바꾸지 않고 통과한다. 새 항목(펼친 카드의 대상·용어, 이슈의 등장 대상, 대상·용어 검색 레코드)은 비어 있으면 빼서(지금 `analogy`처럼) 기존 통째 비교 단언을 바꾸지 않는다(파일은 위대로 비어 있어도 둔다). 스킬 문서·요약·`start` 출력의 바뀐 줄을 보는 기존 테스트는 바뀐 동작에 맞게 고쳐도 되고, 고친 줄과 이유를 보고서에 적는다.
   - 확인: `pnpm verify` 통과. `git diff main -- test/`의 기존 줄 변경이 허용 범위뿐이다(보고서에 목록).
2. **시험 실행:** 실제 `data/tidwyn.db`를 읽기만 해서 `.test-data/` 아래 새 폴더에 복사하고, 그 복사본으로 다음을 한다. 실제 `data/`와 실제 DB, `refs/heads/data`에는 쓰지 않는다.
   - 데이터 폴더 지정(`TIDWYN_DATA_DIR`=복사 폴더) `/brief` 흐름으로 `start`를 돌려 마이그레이션과 "뽑기할 저장된 날짜"를 확인한다.
   - 그 모든 날짜를 스킬 문서의 뽑기 절차대로 뽑는다. 구현하는 AI가 Claude의 역할(뽑기 파일 쓰기)을 스킬 문서 기준(4.2-4)대로 한다. 새 날짜 수집은 하지 않는다.
   - 합치기 주기가 되었으면 합치기도 한다(대상·용어 후보가 없으면 "합친 것이 없다"로 끝나도 된다). 이어서 백업(지정 폴더라 커밋 없음), 빌드까지 돌리고 요약을 확인한다.
   - 그 결과물을 미리보기로 배포하고(4.8-1, 사전 승인) 4.8-1의 확인을 한다.
   - 같은 결과물을 로컬 보기 서버로 띄워 4.7의 화면 확인 스크린샷을 남긴다(미리보기는 로그인이 필요해 AI가 열지 않는다).
   - 백업 결과를 빈 폴더에 복원해 다시 빌드하면 같은 사이트 데이터가 나온다.
   - 확인: 보고서에 시험 폴더 경로, 뽑기한 날짜 수, 대상 수(종류별)와 용어 수, 뽑힌 대상 전체 목록(종류, 이름, 한 줄 설명, 뉴스 수)과 용어 전체 목록(이름, 설명, 본문 표기 유무)이 든 검토 파일의 경로(5장 사용자 확인 2번에 쓴다. 검토 전 목록이 공개 main에 들어가지 않게, 이 파일은 git이 무시하는 시험 폴더 안에 두고 보고서에는 경로와 수만 적는다. 진행 기록에도 대상 이름 목록을 적지 않는다), 두 날짜 이상에 나온 대상 수(목록은 검토 파일에), 본문 밑줄이 있는 용어 수, 실패와 고친 횟수, 합치기 결과(수만 적고 이름은 검토 파일에), 빌드 결과(대상 수, 용어 수, 크기, 파일 수), 미리보기 주소와 4.8-1 결과, 복원 비교 결과, 스크린샷 링크가 있다. 1장 "충분한 수준"의 네 가지가 모두 보인다.
3. **실제 데이터 보호:** 구현을 시작할 때 `data/tidwyn.db`의 해시와 `git rev-parse refs/heads/data`를 진행 기록에 적고 끝날 때 다시 본다. 다르면 `data/runs/`로 사용자의 실제 실행 때문인지 확인해 보고서에 적는다.
   - 확인: 비교 결과를 보고서에 적는다.
