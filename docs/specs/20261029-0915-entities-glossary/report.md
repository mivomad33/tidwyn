## 만든 것과 사용법

`/brief`가 이제 날짜마다 뉴스에 나온 인물·기관·국가(대상)와 용어를 뽑아 DB에 쌓는다. 사이트에는 다음이 생겼다.
- 대상 목록과 대상 페이지, 용어 사전
- 펼친 카드의 용어 밑줄·칩과 대상 칩
- 이슈 페이지의 등장 대상
- 검색 결과의 대상·용어 묶음

### 새 명령

| 명령 | 하는 일 | 누가 |
|---|---|---|
| `refs --run <파일> --date <날짜>` | 그날 뉴스와 후보 대상·용어 목록을 `work/<날짜>.refs.md`에 쓴다 | `/brief` |
| `ref-search [--run <파일>] --q <낱말>` | 이름·별칭·설명으로 찾는다. 지운 이름과 같으면 알린다 | `/brief`, 사용자 |
| `ref-check --run <파일> --date <날짜>` | 뽑기 파일 `work/<날짜>.refs.json`을 검사한다 | `/brief` |
| `ref-apply --run <파일> --date <날짜>` | 검사한 뒤 적용하고 그 날짜를 뽑기 완료로 둔다. 실패하면 실행 기록에 남긴다 | `/brief` |
| `merge-list`, `merge-check`, `merge-apply` | 7일 합치기에 대상·용어 쌍을 함께 다룬다. 합치기 파일 키는 `entityMerges`와 `termMerges`다 | `/brief` |
| `merges` | 합치기 기록을 보여 준다. 대상·용어 합치기도 나온다 | 사용자 |
| `ref-unmerge --id <번호>` | 대상·용어 합치기 하나를 되돌린다 | 사용자만 |
| `ref-delete --entity <번호>` / `--term <번호>` | 대상이나 용어 하나를 지운다. 되돌릴 수 없고, 사본으로만 복원한다 | 사용자만 |
| `deploy --dir <결과물> --preview` | 미리보기로 배포한다. 운영 주소는 바뀌지 않고, 로그인해야 열린다 | 사용자 |
| `pnpm e2e` | Playwright E2E로 3·4단계 화면을 본다. `pnpm verify`와 따로 돈다 | 개발 |

절차와 한계는 [운영 문서](../../operations.md)의 "인물·기관·국가와 용어" 절에 있다. 다루는 것: 지우기는 push된 `data` 이력·뉴스 본문·이슈 글에 남는다, 바로 내리는 법, 4단계 이전 코드로 돌아가는 법, 미리보기 배포. 실행 순서는 [스킬 문서](../../../.claude/skills/brief/SKILL.md)의 5장, 7-1, 12-1에 있다.

## 머지 뒤 첫 실제 `/brief`

1. **마이그레이션:** 실행 전 사본을 남긴 뒤 DB가 v3에서 v4로 올라간다. 모든 날짜가 "뽑기 안 함"이 된다.
2. **쌓인 날짜 뽑기:** 소급 연결 뒤, 새 날짜를 조사하기 전에 저장된 모든 날짜(지금 2026-10-27, 10-28)를 오래된 날부터 뽑는다.
   - 구현하는 동안 작업 브랜치 때문에 실제 실행이 멈춰 밀린 날짜가 있으면, 그 날짜도 새로 모은 뒤 저장 직후에 뽑는다.
3. **걸릴 시간:** 시험 실행에서 한 날짜 뽑기(후보 목록 읽기, 뽑기 파일 쓰기, 검사·적용)에 Claude가 약 10분 걸렸다. 평소 실행에 날짜 수 × 약 10분이 더해진다(2개 날짜 + 밀린 날짜). 그다음부터는 하루 한 날짜만 뽑는다.
4. **검토 없이 공개된다:** 시험 결과는 복사본의 것이다. 첫 실행은 실제 DB의 모든 날짜를 다시 뽑아 그대로 운영에 올린다. 그 실행 뒤 <https://tidwyn.vercel.app/entities>를 한 번 보고, 일반인이나 틀린 설명이 있으면 `node src/cli.ts ref-delete --entity <번호>`로 지운다.
   - 실행 조건(S12)을 따르니 main에서, 실제 데이터 폴더로 한다.
   - 다음 `/brief`가 백업하고 배포한다. 바로 내리려면 운영 문서의 손으로 하는 배포를 쓴다.

- **E2E(사용자 결정, 리뷰 세션 전달, 2026-10-29):** Playwright E2E를 `pnpm e2e`로 따로 두었다. 4단계 화면과 3단계 화면 전체를 다룬다. `@playwright/test`는 devDependency로 설치했다(사전 승인).

## 기준 보완 제안

- **화면 확인의 도구를 정한다.** 명세서는 "화면 확인은 내장 브라우저로 본다"고 정했다. 하지만 상태가 많으면(오류, 빈 상태, 다크, 넓은 화면) 스크린샷은 스크립트로 찍는 편이 다시 하기 쉽다. 기준에 "화면 확인의 스크린샷은 스크립트(헤드리스 브라우저)로 찍어도 되고, 내장 브라우저로 직접 보는 점검은 따로 둔다"처럼 도구를 정하게 하는 문장을 더하기를 제안한다.
- **공개 저장소에 들어갈 근거 파일을 미리 다룬다.** 실제 데이터로 찍은 스크린샷에 사람 이름이 들어갈 수 있다. 명세서가 검토 파일은 시험 폴더에 두게 했지만 스크린샷은 다루지 않았다. 기준에 "공개 저장소에 들어갈 근거 파일(스크린샷 등)에 검토 전 데이터가 들어가는지, 들어가면 어떻게 할지를 명세서가 정한다"를 더하기를 제안한다.
- **테스트용 가짜 마이그레이션의 버전 충돌을 피한다.** 기존 테스트가 다음 버전 숫자를 가짜 마이그레이션에 써서 새 실제 마이그레이션과 부딪혔다. 이 프로젝트에만 해당하는 일이라 기준이 아니라 `docs/memory.md`에 둘 것을 제안한다. 내용은 "테스트용 가짜 마이그레이션은 큰 버전 숫자(예: 1000)를 쓴다"이다.
