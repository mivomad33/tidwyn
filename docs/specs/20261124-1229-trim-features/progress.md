## 재량 결정

- 옛 마이그레이션(7~14)의 지운 표 만들기 문장은 남긴다. 새 DB도 1부터 차례로 올라가므로 지우면 버전 번호와 뒤 마이그레이션이 어긋난다. 15가 그 표를 모두 지운다(4.1-6의 "표를 지우는 DB 업그레이드"로 본다).
- 지운 탭의 옛 해시(`#video` 등)나 옛 저장값은 기본 탭으로, 모르는 해시는 지금처럼 무시한다(T7). 뉴스 키가 아닌 옛 읽음 키는 세지 않고 지우지도 않는다(4.3-5, 브라우저 기록은 사용자 것이라 건드리지 않는다).
- `LICENSE`와 `docs/operations.md`는 명세서의 고칠 파일 목록 밖이지만 고쳤다. LICENSE는 지운 `builder.json`의 가격 행 권리 문장이 지금 결과물을 가리켜서 "2026-11-24 전 `data` 커밋"으로 좁혔고(README 두 파일과 같게), operations의 백업 형식 줄은 형식 11이 되어 맞췄다.
- 의존성은 지운 기능만 쓰던 것이 없어 하나도 빼지 않았다(`package.json` 그대로).
- 배포만 실행 표시는 `start --deploy-only` 인자로 고르고 실행 기록(`deployOnly: true`)에 남긴다. 따로 명령을 만들지 않은 것은 `start`가 실행 전 사본·업그레이드를 이미 하고 나머지 단계가 같은 실행 기록을 읽기 때문이다.

- 기존 테스트 둘의 기대값을 이 문서가 바꾼 동작에 맞췄다(4.4-1): `test/skillDoc.test.ts`(스킬의 18-1단계가 없어져 "다음 명령으로 넘어간다"), `test/backup.test.ts`(형식이 11이 되어 "모르는 형식"을 12로).
- T11의 빌더만 근거인 일정 지우기는 다른 일정이 흡수되어 들어온 일정도 남긴다. 그 일정은 합치기 기록의 남는 쪽이라 지우면 기록이 깨지므로 더 엄격한 쪽(남김)으로 두고 테스트에 넣었다.

- 기존 테스트 기대값을 이 문서가 바꾼 동작에 맞춘 것(4.4-1, 첫 전체 검증에서 드러남): DB 버전 14→15(`corrections`·`indicators`·`issueFlow`·`refs`·`schedules`·`store` 테스트), 백업 형식 10→11(`backup`·`corrections`), 브리프 기억에서 `chip` 칸이 빠짐(`siteNavState`, T7), 사이트 되쓰기 4→3(`siteBuild`, 영상 주소, 4.3-2), 소개의 일정 문구 '뉴스와 공식 문서에서'→'뉴스에서'(`test/e2e/stage5.spec.ts`, 빌더 일정 지움 T11).
- `siteCleanup`의 "정적 빈 상태" 테스트는 이 지어낸 데이터에서 빈 상태를 내던 빌더·수요 구역이 없어져 대상이 0개가 되었다. 기대값을 낮추지 않고, 목록이 빈 작은 사이트(`days: 2`)를 같은 테스트에서 따로 빌드해 빈 상태를 갖게 했다.
- E2E에서 메뉴 테스트 둘(stage5 '머리 메뉴에 일정', stage95 'Tab으로 빠져나가면 닫힘')이 실패했다. 브리프 데이터가 오기 전에 연 메뉴가 데이터가 오면 닫히는 앱 동작 때문이다(d8e97e2에서 stage6 하나만 기다리게 고친 것과 같은 원인, 지운 데이터로 화면이 빨라져 더 자주 드러남). 이 문서가 정하지 않은 동작이라 테스트를 바꾸지 않고 원인을 고쳤다: 브리프 페이지가 읽는 중에는 공통 `Layout`을, 데이터가 온 뒤에는 Fragment를 돌려줘 머리 줄이 다시 만들어졌다. 읽는 중·오류 틀도 같은 Fragment 모양으로 그리게 했다(`site/src/pages/BriefPage.tsx`의 `frame`). 고치기 전 전체 E2E에서 두 테스트가 실패했고, 고친 뒤 stage5·stage6·stage95를 세 번씩 돌려 195개 모두 통과했다.
- T10(4): 지우기 전 윈도우 기준 이미지와 비교해 29개 화면이 달랐다. diff 이미지를 보니 바닥글의 YouTube 동의 줄, 일정 안내의 '공식 문서', 브리프 섹션 탭(영상·빌더·수요)처럼 모두 지운 것 때문이라 `--update-snapshots`로 다시 찍었다.

- 마지막 검증의 재사용과 단순화(`/simplify`, 서브에이전트): 지운 기능만 쓰던 도우미(`precheck.ts`의 백업 경로·메일 검사, `run.ts`의 `removeWorkFiles`, E2E `base.ts` 상수)를 지우고, `frame`이 공통 `Layout`을 함수로 불러 쓰게 하고, 더는 닿지 않는 `currentTab`·`hashPicksTab`을 지웠다(`stateForHash`가 그날 없는 탭을 첫 섹션으로 바꾸는 것을 메인이 확인). 정적 일정 목록 설명의 '뉴스와 공식 문서에서'도 빌더 일정을 지워 '뉴스에서'로 맞췄다. 그 뒤 `pnpm verify` 677개 통과(16.9분), `pnpm e2e`는 328 통과·2개가 `beforeEach`(시계 고정)에서 30초를 넘겨 실패했고 두 파일을 두 번씩 다시 돌려 108개 모두 통과했다(기계 부하로 봄).
