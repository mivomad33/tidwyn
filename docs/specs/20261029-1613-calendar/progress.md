## 재량 결정

- 지운 일정은 행을 남긴다(이름·예정일, deleted=1). 이 행이 "지운 일정 기록"이고, 식별자가 다시 쓰이지 않으며 백업·복원 뒤에도 남는다(AUTOINCREMENT + 행 보존).
- 연기 대상이 지워져도 postponed_to는 그대로 두고 "연기(새 날짜 모름)"는 사이트 데이터를 만들 때 계산한다(되돌리기 쉽게).
- 날짜 확정도 뉴스별 일정 개수에 센다(명세 "기존 일정에 근거를 더하는 것도 센다"를 엄격하게). 연기·취소 알림 연결은 세지 않는다(그 뉴스의 일정이 아니라 다른 일정의 결과라서).
- 결과 연결은 뉴스 키 여러 개를 받는다. 같은 일정에 결과를 두 번 쓰면 거부.
- 날짜 확정의 새 날짜에도 예정일 범위 검사를 한다(더 엄격한 쪽).
- 되돌리기의 "연달아 합쳐진 경우"는 그 기록 뒤에 남는 것이나 흡수된 것이 든 다른 합치기(되돌리지 않은 것)가 있으면 거부로 읽었다(더 엄격한 쪽).
- 합치기 파일의 `due`는 두 일정의 예정일 중 하나만 받는다.
- 기존 일정 후보의 낱말 일치: 흔한 낱말을 뺀 이름 낱말 중 min(2, 개수)개 이상이 그날 글에 나오면 든다.
- 사이트 데이터: 일정을 예정일의 달별 파일(`schedule-month-YYYY-MM.json`)과 색인(`schedule-index.json`), 식별자 1000개 묶음의 주소 풀이 파일(`schedule-ref-N.json`)로 나눈다. '이번 주 일정'은 그날 목록 파일에 앞 5개와 전체 수만 둔다. 색인은 일정이 없어도 낸다.
- 일정 명령은 4단계와 같은 이름 짜임으로 새로 두었다(`schedules`, `schedule-search`, `schedule-check`, `schedule-apply`, `schedule-unmerge`, `schedule-delete`). 합치기는 기존 `merge-list/check/apply`에 `scheduleMerges` 키로 넣었다.
- 스킬 문서의 단계 번호는 7-2(채우기 일정 뽑기), 12-2(그 날짜 일정 뽑기)로 두었다.
