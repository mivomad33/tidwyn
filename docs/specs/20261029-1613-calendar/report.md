## 만든 것

- **일정 저장(마이그레이션 5):** 일정(이름, 일·달 단위 예정일, 대분류, 결과), 뉴스-일정 연결(근거·결과·연기·취소 알림), 날짜별 일정 뽑기 완료, 일정 합치기 기록, "합치지 않음" 쌍. 지운 일정은 이름과 예정일만 남는다(`src/db.ts`, `src/schedules.ts`).
- **일정 뽑기 단계:** 후보 목록, 검색, 일정 파일 검사와 적용(`src/scheduleExtract.ts`). `/brief`의 7-2단계(채우기)와 12-2단계(새 날짜)에서 돈다.
- **합치기·되돌리기·지우기:** 7일 합치기에 일정 쌍을 함께 넣었다(`src/scheduleMerge.ts`).
- **백업 형식 4:** `schedules.json`과 월별 파일의 `scheduled` 표시. 형식 1~4를 읽는다(`src/backup.ts`).
- **사이트:**
  - 일정 화면(`/schedules`, 목록·달력)과 일정 주소(`/schedules/<번호>`)
  - 브리프 위 '이번 주 일정', 펼친 카드의 일정 칩, 이슈 페이지의 일정, 메뉴와 바닥글의 '일정'

- **문서:** 스킬 문서 "6. 일정", 운영 문서 "일정" 절, README 두 언어에 한 줄씩.

### 새 명령

| 명령 | 하는 일 |
| --- | --- |
| `node src/cli.ts schedules --run <실행 기록> --date <날짜>` | 그날 뉴스와 기존 일정 후보·결과 후보 목록(`work/<날짜>.schedules.md`)을 만든다 |
| `node src/cli.ts schedule-search [--run <실행 기록>] --q <낱말> [--from <날짜>] [--to <날짜>]` | 이름의 낱말과 예정일 범위로 일정을 찾는다. 지운 일정과 같으면 "지운 일정과 같음"이 나온다 |
| `node src/cli.ts schedule-check --run <실행 기록> --date <날짜>` | 일정 파일(`work/<날짜>.schedules.json`)을 검사한다 |
| `node src/cli.ts schedule-apply --run <실행 기록> --date <날짜>` | 검사한 뒤 적용하고 일정 뽑기 완료로 둔다. 실패하면 실행 기록에 남는다 |
| `node src/cli.ts schedule-unmerge --id <번호>` | 일정 합치기 하나를 되돌린다(사용자가 직접 실행) |
| `node src/cli.ts schedule-delete --id <번호>` | 일정 하나를 지운다(사용자가 직접 실행) |

- 일정 합치기는 기존 `merge-list`, `merge-check`, `merge-apply`에서 `work/merges.json`의 `scheduleMerges` 키로 한다.
- `merges`는 일정 합치기 기록도 보인다.
- 자세한 사용법은 `docs/operations.md`의 "일정" 절에 있다.

### 새 화면 주소

- `/schedules`: 일정 화면. 기억한 보기로 연다(목록 또는 달력).
- `/schedules?view=list`: 목록 보기로 연다('이번 주 일정'의 '일정 전체').
- `/schedules/<번호>`: 목록 보기의 그 일정으로 가서 강조한다. 흡수된 번호는 남는 일정으로 가고, 지운 번호와 없는 번호는 없는 페이지를 보인다.

## 머지 뒤 첫 실제 `/brief`

- **마이그레이션:** 실제 DB가 버전 5로 바뀐다. 그 전에 실행 전 사본이 `data/snapshots/`에 남는다.
- **쌓인 날짜 전체 일정 뽑기:** 저장된 모든 날짜가 7-2단계(채우기 일정 뽑기)에 든다. 지금은 2개이고, 구현 중 실제 `/brief`가 멈춰 있었으므로 머지 뒤 첫 실행이 밀린 날짜도 함께 수집한다. 밀린 날짜도 12-2단계에서 일정을 뽑는다.

- **검토 없이 공개:** 뽑힌 일정이 검토 없이 운영 사이트에 올라간다. 실행 뒤 운영 사이트의 일정 화면을 한 번 보고, 잘못 뽑힌 일정이 있으면 `node src/cli.ts schedule-delete --id <번호>`로 지운다. 바로 내리려면 운영 문서의 "손으로 빌드·배포하기"를 한다.
- **5단계 이전 코드로 돌아가야 할 때:** 운영 문서의 "5단계 이전 코드로 돌아가야 할 때"를 본다. 실행 전 사본 복원이 기본이다.

## 재량으로 정한 것

- **지운 일정:** 행을 남긴다(이름·예정일, 지움 표시). 이 행이 "지운 일정 기록"이라, 식별자가 다시 쓰이지 않고 복원 뒤에도 남는다.
- **연기(새 날짜 모름):** 연기 대상이 지워져도 연기 대상 값은 그대로 두고, "연기(새 날짜 모름)"는 빌드 때 계산한다.
- **개수 세기:** 날짜 확정은 뉴스별 일정 개수에 센다(엄격한 쪽). 연기·취소를 알린 연결은 세지 않는다.
- **결과 연결:** 뉴스 키를 여러 개 받는다. 같은 일정에 결과를 두 번 쓰면 거부한다.
- **날짜 확정:** 새 날짜에도 예정일 범위 검사를 한다(엄격한 쪽).
- **연달아 합친 경우:** 남는 것이나 흡수된 것이 그 뒤의 다른 합치기에 들어 있으면 되돌리기를 거부한다(엄격한 쪽).
- **합치기 예정일:** 합치기 파일의 `due`는 두 일정의 예정일 중 하나만 받는다.
- **기존 일정 후보의 낱말 일치:** 흔한 낱말(발표, 결정 등)을 뺀 이름 낱말 중 min(2, 개수)개 이상이 그날 글에 나오면 후보에 든다.
- **사이트 데이터 나누기:**
  - 예정일의 달별 파일, 색인, 식별자 1,000개 단위의 주소 풀이 파일로 나눈다.
  - '이번 주 일정'은 그날 목록 파일에 앞 5개와 전체 수만 둔다.
- **명령 이름:** 4단계와 같은 짜임(`schedule-*`)으로 두었다. 합치기는 기존 `merge-*`에 넣었다.
- **화면:**
  - '일정 전체'는 `/schedules?view=list`로 간다. 기억한 보기는 바꾸지 않는다.
  - 일정 주소로 들어오면 그 줄로 이동해 초점을 주고 4초 동안 강조한다.
  - 달력은 화살표, Home, End 키로 움직인다.
  - 카드의 일정 칩 줄은 '전망' 바로 뒤에 둔다.
  - 보기·접기 기억 키는 `tidwyn.scheduleView`, `tidwyn.weekBox`다.
  - 브라우저 저장소 코드는 공통 코드(`site/src/lib/storage.ts`, `site/src/storage.ts`)로 옮겨 읽은 기록과 함께 쓴다.

## 브라우저 점검

- **점검 날짜:** 2026-10-29. 지어낸 데이터로 빌드한 결과물을 로컬 보기 서버로 띄워 앱 안 브라우저(375px, 다크, 1440px)로 눌러 보았다. 4.7 화면 요구사항과 4.6의 화면에 드러나는 데이터를 항목으로 나눴고, 브라우저로 볼 수 없는 4.1~4.6 항목은 자동 테스트로 판정했다.

- **고친 것:** 시작 때 `pnpm e2e`의 stage5 "이슈 페이지의 '일정'이 타임라인 아래에 다가오는 일정 다음 지난 일정으로 있다"가 계속 실패했다. 화면은 맞았고, 테스트가 이슈 페이지를 그리기 전에 제목을 읽은 것이 원인이었다. '일정' 제목이 보일 때까지 기다린 뒤 읽게 고쳤다(`test/e2e/stage5.spec.ts`, 앱 코드 변경 없음). 점검 끝에 `pnpm verify` 444개와 `pnpm e2e` 128개가 모두 통과했다.
- **점검 뒤 고친 것:** 일정 목록에서 '더 보기'를 누르면 버튼이 잠깐 대기 표시로 바뀌어 키보드 포커스가 문서 처음으로 갔다. 받은 뒤 새로 보인 첫 일정으로 포커스를 옮기게 고쳤다(`site/src/pages/SchedulesPage.tsx`).
