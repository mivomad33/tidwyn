## 재량 결정

- 명령 이름: `issues`, `issue-search`, `link-check`, `link-apply`, `merge-list`, `merge-check`, `merge-apply`, `merges`, `unmerge`, `render --all`. 기존 `validate`/`save` 짝과 같은 모양으로 했다.
- 뉴스 키: 주요 뉴스 `<섹션>-<순위>`, 짧은 소식 `<섹션>-s<위치>`. 백업과 합치기 기록은 DB 번호 대신 `<날짜>/<키>`를 쓴다(복원해도 바뀌지 않는다).
- 시작일·최근 업데이트일·전개 수·전개 순서는 저장하지 않고 연결에서 계산한다(어긋날 일이 없다).
- 후보 이슈: DB의 가장 늦은 대상일에서 30일 안에 업데이트된 이슈, 최근 순 최대 150개. 검색은 이름·별칭(2점)과 요약(1점)의 낱말 포함, 최대 30개.
- 합치기 후보: 이름·별칭의 두 글자 묶음 겹침 비율(작은 쪽 기준)이 같은 대분류면 0.5, 다르면 0.7 이상, 최대 30쌍.
- 연결 파일 검사를 명세보다 엄격하게 한 곳: 이미 연결된 뉴스를 가리키면 거부, 어느 뉴스에도 안 쓰인 새 이슈 거부, 뉴스가 붙지 않는 이슈의 요약·상태 변경 거부, 앞선 날짜의 뉴스만 붙는 이슈의 상태 변경 거부(4.2-6의 "종료는 가장 최근 전개일 때만"을 검사로 막음). 다시 적용할 때 이슈가 없는 뉴스가 없으면 검사 전에 "할 일 없음"으로 끝낸다.
- 한 합치기 파일 안의 연달아 흡수(A→B, B→C)와 두 번 흡수는 검사에서 거부한다. "합치지 않음" 쌍을 다시 합치는 것도 거부한다.
- 되돌리기의 "그 뒤 더해진 것" 판정: 그 뒤의 되돌리지 않은 합치기가 같은 남는 이슈로 들어왔거나, 지금 연결·관계에 합치기 직후에 없던 것이 있으면 더해진 것으로 본다. 다른 합치기로도 들어온 뉴스·별칭·관계는 남긴다.
- 되돌리기는 실제 데이터 폴더가 아니어도 실행 전 사본을 남긴다(더 안전한 쪽).
- 백업 형식 2: `meta.json`에 `firstLinkedOn`, `mergeCheckedOn`을 값이 있을 때만 넣고, 이슈 데이터는 이슈 데이터가 있을 때만 `issues.json`에 둔다. 형식 1과 2를 모두 읽는다.
- 복원 뒤 마크다운: 복원 명령은 마크다운을 만들지 않고 `render --all`로 만든다(운영 문서에 적음). 연결·합치기·되돌리기 뒤에는 브리프와 이슈 마크다운을 모두 다시 만든다(내용이 같은 파일은 다시 쓰지 않는다).
- 스킬 문서 실행 순서를 15단계로 다시 번호를 매겼다(대화창 출력은 15단계). 4.6-1의 "12단계 요약 설명"은 15단계 절에 넣었다.
