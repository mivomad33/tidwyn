# 4.5단계 명세서: 읽은 뉴스 표시

- 작성일: 2026-10-29
- 요약: 사이트에서 읽은 뉴스를 방문자의 브라우저(로컬 스토리지)에 기록하고, 뉴스 제목이 나오는 모든 목록에서 읽은 뉴스를 알아볼 수 있게 한다. 브리프에는 읽음 버튼, '안 읽은 것만' 거르기, 날짜 목록에는 읽은 정도, 사이트 소개에는 기록 지우기를 더한다. 로그인은 없고, 수집·DB·백업은 바꾸지 않는다.
- 종류: 변경 건 (3·4단계의 공개 사이트 화면과 사이트 빌드를 바꾼다. 사이트는 공개되어 있고 매일 배포된다)
- 단계: [`docs/plan.md`](../../plan.md)의 4.5단계(읽은 뉴스 표시). 3·4단계를 참조한다.
- 이 문서는 기획과 요구사항만 담는다. 설계(저장 형식, 컴포넌트 구조, 파일 형식)와 작업 계획은 구현하는 AI가 정한다.
- 공개 여부: 원본 저장소와 사이트는 이미 공개다. 읽은 기록은 방문자 각자의 브라우저에만 있고 어디로도 보내지 않는다.

## 1. 목표

- **지금 상태:** `/brief`가 매일 브리프를 모아 DB에 저장하고 이슈·인물·기관·국가·용어를 연결한 뒤, 사이트를 빌드해 `https://tidwyn.vercel.app`에 배포한다(1~4단계). 4단계는 main에 머지되었고, 머지 뒤 첫 실제 `/brief`(실행 기록 `data/runs/20261029-123819.json`)가 DB를 스키마 버전 4로 올리고 운영 배포를 마쳤다. 2026-10-29 기준 실제 DB에 날짜 2개(2026-10-27, 10-28), 뉴스 62건, 인물·기관·국가 119개, 용어 73개가 있다. 사이트는 로컬 스토리지나 쿠키를 쓰지 않는다. 같은 뉴스가 브리프, 펼친 카드의 이전 전개, 이슈 타임라인, 인물·기관·국가 페이지, 검색 결과, 용어 사전의 "처음 나온 뉴스"에 다시 나오지만, 이미 읽었는지 알 수 없다.
- **바꾸려는 이유:** 매일 브리프와 이슈·인물 페이지를 오가다 보면 같은 뉴스를 여러 화면에서 다시 만난다. 이미 읽은 뉴스를 알아보면 안 읽은 것에 집중할 수 있다.
- **쓰는 사람:** 프로젝트 주인 한 사람. 사이트는 공개라 누구나 쓰지만, 기록은 각자의 브라우저에만 있다.
- **충분한 수준:** 실제 DB의 복사본으로 빌드한 사이트가 Vercel 미리보기로 배포되어, 폰 폭(375px)에서 다음이 동작한다. 사용자가 폰에서 마지막에 본다(5장).
  - 브리프에서 주요 뉴스를 펼치거나, 짧은 소식 글을 누르거나, 읽음 버튼을 누르면 읽음이 되고, 버튼을 다시 누르면 안 읽음으로 돌아간다.
  - 읽은 뉴스가 브리프와 다른 목록(이전 전개, 이슈 타임라인, 대상 페이지, 검색 결과, 용어 사전)에서 같은 규칙으로 표시된다.
  - '안 읽은 것만' 거르기, 날짜 목록의 읽은 정도, 사이트 소개의 기록 지우기가 동작한다.
  - 새로 고침하거나 사이트를 다시 열어도 기록이 남아 있다.

## 2. 확정된 결정과 제약

### 2.1 계획과 앞 단계에서 가져온 결정 (다시 묻지 않는다)

- plan D1~D14와 2.2 제약, 앞 단계 결정(1단계 S1~S14, 1.5단계 R1~R7, 2단계 I1~I8, 3단계 P1~P14, 4단계 E1~E15)을 따른다. 특히 다음이다.
  - **plan 4.5단계:** 기록은 로그인 없이 브라우저(로컬 스토리지)에만 두고, 오래된 기록은 지워 용량을 지킨다. 수집·DB·백업은 바꾸지 않는다.
  - **D3, P4:** 사이트는 Vite + React SPA이고 순수 정적 파일이다. 한 번 공개한 주소는 깨지지 않게 둔다(새 주소는 만들지 않아도 된다).
  - **D8, P13, 4단계 E8:** 화면은 3단계 확정 시안 A와 4단계 확정 시안, 이 명세서의 확정 시안(M3)을 따른다.
  - **D9:** 이미 저장된 날짜의 뉴스는 다시 수집하거나 고치지 않는다. 그래서 뉴스는 "날짜 + 뉴스 키"(예: `2026-10-28`과 `한국-1`, 짧은 소식은 `한국-s1`)로 계속 같은 뉴스를 가리킨다. 읽은 기록은 이 식별자로 남긴다. 사이트 데이터의 모든 뉴스 목록(브리프, 이전 전개, 이슈 타임라인, 대상 페이지, 검색 결과, 용어 사전의 처음 나온 뉴스)에 이미 이 두 값이 있다.
  - **D14, S12:** 개발과 확인은 실제 DB의 복사본이나 지어낸 데이터로만 한다. 실제 `data/`를 바꾸지 않는다.
  - **3단계 화면 공통(4.3-6):** 375px 우선, 넓은 화면은 가운데 한 단, 다크 모드는 기기 설정, 키보드로 모든 링크와 버튼을 쓸 수 있음, 본문 글자 대비 WCAG AA(4.5:1), `lang="ko"`.
  - **3단계 첫 화면 속도(4.3-7):** 가장 최근 날짜의 첫 화면에 필요한 전송 크기 합은 gzip 300KB 이하다(한 달이 가득 찬 경우 포함).
  - **3단계 파일 수(4.1-3):** 결과물 파일 수는 5년치 데이터에서 10,000개 이하다.
  - **P10:** 방문 통계는 Vercel Web Analytics의 페이지 보기만 모으고 사용자 정의 이벤트를 쓰지 않는다. 운영 주소에서만 켠다.
  - **4단계 E12:** 새 화면은 운영에 배포하지 않고 Vercel 미리보기로 사용자가 폰에서 먼저 본다. 운영 사이트는 머지 뒤 첫 실제 `/brief`가 바꾼다.
- **CLAUDE.md:** 여러 곳에서 쓸 UI와 로직은 공통 코드로 만든다. 읽은 기록을 읽고 쓰는 로직과 읽음 표시(굵기, 체크)는 공통 코드 하나로 두고 모든 목록이 같이 쓴다. 기존 공통 코드(`site/src/components/common.tsx`, `site/src/lib/`, `src/siteTypes.ts`)를 먼저 넓혀 쓴다.
- **docs/memory.md:** 명세서 폴더의 화면 확인 스크린샷은 git에 넣지 않는다(`.gitignore`). 테스트용 가짜 마이그레이션 버전 규칙은 이 단계에 마이그레이션이 없어 해당하지 않는다.

- 화면 공통 규칙과 화면 확인 → 4.8
- 미리보기 배포와 문서 → 4.9
- 기존 기능 유지와 실제 데이터 보호 → 4.10

### 넣지 않는 것

- 로그인, 서버 저장, 여러 기기·브라우저 사이 기록 맞추기: plan 4.5단계가 "로그인 없이 브라우저에만"으로 정했다.
- 같은 브라우저의 다른 탭에 바로 반영하기: 사용자가 고르지 않았다(M6). 다른 탭의 기록은 그 탭을 새로 고치거나 다시 열 때 반영된다.
- 수집(`/brief` 스킬 문서와 수집 명령), DB 스키마, 백업 형식의 변경: plan 4.5단계. 사이트 빌드(`site` 명령이 만드는 사이트 데이터)는 날짜 목록의 읽은 정도에 필요한 만큼 바꿔도 된다(4.5-1).
- 다른 목록(이슈 타임라인, 대상 페이지, 검색 결과 등)의 읽음 버튼과 '안 읽은 것만' 거르기: M4. 브리프에만 둔다.
- 읽은 기록 내보내기·가져오기: 요청이 없었다. 기록은 기기의 브라우저에만 있고 지우면 되살릴 수 없다는 것을 사이트 소개에 적는다(4.6-1).
- 기능 끄기 설정(읽음 표시를 아예 안 보이게): 요청이 없었다.
- 읽은 기록을 방문 통계로 보내기(읽은 수 집계 등): P10은 사용자 정의 이벤트를 쓰지 않는다.
- 뒤 단계 기능(일정 달력 5단계, 지표 6단계, 영상 7·8단계, 리포트 10단계)의 목록: 그 단계가 이 단계의 공통 코드를 써서 표시한다(그 단계 명세서가 정한다).
- 운영 배포: 머지 뒤 첫 실제 `/brief`가 한다(E12와 같다).

### 해당 없음

- 인증과 권한: 로그인이 없다.
- 남용 방지와 입력 제한: 새 입력란이 없다. 로컬 스토리지 값은 방문자 자신의 것이라 깨진 값만 다룬다(4.1-4).
- 외부 서비스 연동: 새로 부르는 외부 서비스가 없다. Vercel은 미리보기 배포에만 쓴다(4.9-1).
- 예약·백그라운드 작업: 없다. 오래된 기록 정리는 사이트를 열 때 한다(4.1-3).
- 데이터 이전: DB와 백업을 바꾸지 않는다. 로컬 스토리지는 처음 쓰는 것이라 옮길 기존 기록이 없다.
- 비용: 0원이다(7장).

## 4. 요구사항

**용어**
- **뉴스 식별자:** 날짜(`YYYY-MM-DD`)와 뉴스 키(`한국-1`, `한국-s1` 같은 것)의 짝. 사이트 데이터에 이미 있다(2.1 D9).
- **읽은 기록:** 방문자의 브라우저 로컬 스토리지에 둔, 읽음인 뉴스 식별자의 모음.
- **뉴스 목록:** M4의 여섯 곳. 브리프(주요 뉴스, 짧은 소식), 펼친 카드의 이전 전개, 이슈 타임라인, 대상 페이지의 등장 뉴스, 검색 결과의 뉴스, 용어 사전의 처음 나온 뉴스.
- **자동 테스트:** `pnpm verify`에 들어가는 단위·통합 테스트. 네트워크를 쓰지 않고 실제 `data/`를 읽지 않는다.
- **E2E:** `pnpm e2e`(Playwright, 4단계에서 만듦)의 테스트. 지어낸 데이터로 빌드해 로컬 보기 서버로만 돈다. 브라우저의 로컬 스토리지를 실제로 쓰고 읽는다.
- **화면 확인:** 지어낸 데이터나 실제 복사본으로 빌드한 사이트를 로컬에서 띄워 스크린샷을 찍어 명세서 폴더의 `screenshots/`에 남기는 것(git이 무시한다, 2.1). 스크립트(헤드리스 브라우저)로 찍어도 된다.

### 4.1 읽은 기록 (M1, M2, M5)

1. **저장:** 읽은 기록은 뉴스 식별자만으로 남기고, 같은 사이트 주소의 로컬 스토리지에 둔다. 쿠키, 세션 스토리지, IndexedDB, 서버는 쓰지 않는다. 같은 뉴스를 여러 번 읽어도 기록은 하나다.
   - 확인: 자동 테스트(단위). 기록을 더하고 빼고 다시 읽는 공통 로직이 같은 뉴스를 두 번 더해도 하나만 남기는지 본다. E2E: 읽음 버튼으로 읽음으로 바꾼 짧은 소식이 `#` 없는 브리프 주소로 새로 고친 뒤에도 읽음이고(주소의 `#`로 다시 읽음이 되는 4.2-3과 섞이지 않게), `document.cookie`가 비어 있다.
2. **어느 화면에서나 같은 기록:** 한 탭 안에서 화면을 옮기면(브리프 → 이슈 페이지 → 뒤로 가기 등) 바뀐 기록이 새로 고침 없이 바로 보인다.
   - 확인: E2E. 브리프에서 읽음으로 바꾼 뉴스가 이슈 타임라인과 검색 결과에서 바로 읽음으로 보이고, 이슈 페이지에서 뒤로 가 브리프로 돌아와도 그대로다.
3. **1년 지난 기록 지우기:** 사이트를 열 때(화면 틀을 처음 불러올 때) 뉴스 날짜가 오늘(KST)로부터 365일보다 오래된 기록을 지운다. 오늘은 브라우저 시계를 KST로 바꾼 날짜다. 정확히 365일 전 날짜의 기록은 남는다.
   - 확인: 자동 테스트(단위). 시계를 고정해 366일 전 기록은 지워지고 365일 전과 그 뒤 기록은 남는지 본다. KST 날짜 경계(UTC 15:00 앞뒤)에서도 본다. E2E의 지어낸 데이터는 날짜가 고정되어 있으므로(`test/e2e/prepare.ts`의 `END`), 읽은 기록을 쓰는 E2E는 브라우저 시계를 그 날짜 근처로 고정한다(Playwright의 clock 등). 그러지 않으면 1년 뒤 기록이 지워져 E2E가 실패한다.
4. **저장이 안 되거나 값이 깨졌을 때:** 로컬 스토리지를 쓸 수 없거나(사생활 보호 모드, 막힌 설정, 용량 초과) 저장된 값이 깨져 있으면, 사이트는 오류 화면 없이 그대로 동작한다. 그 경우 읽음 표시는 그 탭 안에서만 유지된다. 깨진 값은 버리고 새로 시작한다(다른 키의 값은 건드리지 않는다).
   - 확인: 자동 테스트(단위). 스토리지가 예외를 던질 때와 깨진 값(JSON이 아님, 형식이 다름)일 때 로직이 예외 없이 빈 기록으로 시작하고, 미리 넣어 둔 다른 키의 값은 남는다. E2E: 로컬 스토리지 접근이 예외를 던지게 한 페이지에서 브리프를 열고 카드를 펼쳐도 `pageerror`가 없고, 펼친 카드가 그 탭에서 읽음으로 보인다.
5. **용량:** 하루 뉴스 42건을 1년 동안 모두 읽은 기록이 1MB(UTF-16 기준 로컬 스토리지 사용량) 이하다.
   - 확인: 자동 테스트(단위). 지어낸 365일 × 42건 기록을 직렬화한 크기를 잰다. 잰 값을 보고서에 적는다.

### 4.2 브리프의 읽음 동작 (M1, M2)

1. **주요 뉴스 펼치기:** 주요 뉴스 카드를 펼치면 그 뉴스가 읽음이 된다. 카드를 접어도 읽음으로 남는다. 이미 읽음이면 그대로다.
   - 확인: E2E. 안 읽은 카드를 펼치면 버튼 상태가 읽음이 되고, 접어도 읽음이다.
2. **짧은 소식 글 누르기:** 짧은 소식의 글(요약 문장)을 누르면 읽음이 된다. 짧은 소식 줄의 이슈 링크를 누르는 것은 이슈 페이지로 가는 것이라 읽음으로 바꾸지 않는다. 글 누르기는 키보드로도 할 수 있다.
   - 확인: E2E. 글을 누르면 읽음이 되고, 다시 눌러도 읽음이다. 글에 키보드 초점을 두고 Enter를 눌러도 읽음이 된다. 이슈 링크를 누른 뒤 뒤로 오면 그 짧은 소식은 안 읽음이다.
3. **링크로 들어오기:** 주소에 `#<뉴스 키>`가 있는 브리프로 들어오면(다른 목록의 뉴스 링크, 직접 연 주소) 그 뉴스가 읽음이 된다. 주요 뉴스는 지금처럼 펼쳐지고, 짧은 소식은 지금처럼 강조된다. 주소의 `#<뉴스 키>`로 화면이 열릴 때마다(새로 고침, 뒤로·앞으로 가기 포함) 읽음이 된다. 그래서 펼친 카드(주소에 `#`이 붙어 있다)를 버튼으로 안 읽음으로 바꾼 뒤 새로 고치거나 다른 화면에 갔다 뒤로 오면 다시 읽음이 될 수 있고, 이것은 감수한다.
   - 확인: E2E. 이슈 타임라인에서 주요 뉴스 링크와 짧은 소식 링크를 각각 누르면, 브리프에서 그 뉴스가 읽음이 된다. 주소를 직접 열어도 같다.
4. **읽음 버튼:** 브리프의 모든 뉴스 줄(주요 뉴스, 짧은 소식) 오른쪽에 읽음 버튼이 있다. 누르면 읽음과 안 읽음이 바뀐다. 버튼을 눌러도 카드가 펼쳐지거나 접히지 않는다. 키보드로 초점을 옮겨 Enter와 Space로 누를 수 있다. 보조 기술에는 그 뉴스 제목을 담은 이름과 눌림 상태(`aria-pressed` 등)로 읽음 여부를 알린다. 누르는 자리는 44×44px 이상이다.
   - 확인: E2E. 버튼을 두 번 누르면 읽음 → 안 읽음으로 돌아오고 카드 펼침은 바뀌지 않는다. Tab으로 버튼에 가서 Space로 누를 수 있다. 버튼의 접근 이름에 뉴스 제목이 들어 있고 상태 속성이 바뀐다. 버튼의 크기가 44×44px 이상이다.
5. **펼친 카드에서도:** 펼친 주요 뉴스의 버튼도 같은 자리에서 동작한다. 펼친 상태에서 안 읽음으로 바꾸면 펼친 채 안 읽음이 된다(다시 접었다 펼치면 읽음이 된다).
   - 확인: E2E. 펼친 카드의 버튼을 누르면 안 읽음이 되고 카드는 펼친 채다.

### 4.3 뉴스 목록의 읽음 표시 (M3, M4)

1. **같은 규칙:** 모든 뉴스 목록에서 안 읽은 뉴스는 굵게, 읽은 뉴스는 같은 글자 색의 보통 굵기로 보인다. 지금 보통 굵기로 보이는 목록(짧은 소식, 이전 전개 등)도 안 읽은 줄은 굵게 바뀐다. 브리프 밖의 목록은 읽은 줄 끝에 작은 파랑 체크(✓)를 더한다. 이 체크는 보조 기술에 "읽음"으로 읽힌다. 모양은 확정 시안(M3)을 따른다. 표시 로직과 모양은 공통 코드 하나로 두고 여섯 곳이 같이 쓴다.
   - 확인: E2E. 한 뉴스를 읽음으로 바꾼 뒤 브리프, 펼친 카드의 이전 전개, 이슈 타임라인, 대상 페이지, 검색 결과, 용어 사전의 처음 나온 뉴스에서 그 줄이 읽음(굵기 보통, 체크)이고 다른 줄은 안 읽음(굵게)이다. 코드 검토: 여섯 곳이 같은 공통 컴포넌트·함수를 쓴다(보고서에 이름을 적는다).
2. **표시만으로 기록이 바뀌지 않는다:** 브리프 밖의 목록을 보거나 스크롤하는 것만으로는 읽음이 되지 않는다. 그 목록의 링크를 눌러 브리프로 가면 4.2-3대로 읽음이 된다.
   - 확인: E2E. 이슈 페이지와 대상 페이지를 열고 스크롤한 뒤 브리프로 돌아오면 기록이 그대로다.
3. **흡수된 이슈·대상:** 흡수된 이슈·대상 주소로 들어가 남는 쪽 페이지가 보여도 표시 규칙은 같다(뉴스 식별자가 같으므로).
   - 확인: 자동 테스트(단위) 또는 E2E. 흡수된 이슈 주소로 연 타임라인에서 읽은 뉴스가 읽음으로 보인다.

### 4.4 '안 읽은 것만' 거르기 (M6)

1. **위치와 동작:** 브리프의 카테고리 칩 줄 끝에 '안 읽은 것만' 칩이 있다(시안). 켜면 그 섹션에서 읽은 주요 뉴스와 짧은 소식을 숨긴다. 카테고리 거르기와 함께 쓰면 둘 다 맞는 뉴스만 보인다. 섹션의 흐름 설명과 확인되지 않은 내용 줄은 지금 규칙(카테고리를 거르지 않을 때만 보임)을 그대로 따른다. 주소의 `#<뉴스 키>`로 들어온 뉴스는 이미 읽었어도 칩과 상관없이 보인다(카테고리 거르기가 `#` 대상을 숨기지 않는 지금 규칙과 같은 뜻이다. 칩을 끌지, 그 뉴스만 남길지는 AI 재량).
   - 확인: E2E. 칩을 켜면 읽은 뉴스가 사라지고 끄면 돌아온다. 카테고리 '경제'와 함께 켜면 안 읽은 경제 뉴스만 보인다. 칩을 켠 채 이미 읽은 주요 뉴스의 `#` 주소로 들어오면 그 카드가 펼쳐져 보인다(칩 상태가 남는 경로로 들어온다. 예: 칩을 켠 브리프의 펼친 카드에서 이전 전개 링크를 누름. 칩 상태 유지 방식은 이 확인이 가능하게 고른다).
2. **켠 동안 읽은 뉴스:** (2026-10-29 M9로 바뀜. 지금 동작은 M9를 따르고, 아래는 원안이다.) 켠 동안 펼치거나 버튼을 눌러 읽음이 된 뉴스는 바로 사라지지 않는다. 칩을 다시 켜거나, 섹션·날짜를 바꾸거나, 새로 고칠 때 빠진다. 펼친 카드가 눈앞에서 사라지지 않게 하기 위해서다. 단, 주소에 `#<뉴스 키>`가 남은 채 새로 고치면 그 뉴스는 4.4-1대로 보인다.
   - 확인: E2E. 칩을 켠 채 카드를 펼치면 카드가 그대로 펼쳐져 있고, 섹션을 바꿨다 돌아오면 그 카드가 없다.
3. **빈 상태:** 거른 결과 보일 뉴스가 없으면 "안 읽은 뉴스가 없다."처럼 빈 상태 문구가 보인다(카테고리 거르기의 빈 상태와 같은 모양).
   - 확인: E2E. 한 섹션의 뉴스를 모두 읽음으로 바꾸고 칩을 켜면 빈 상태 문구가 보인다.
4. **칩 상태:** 칩은 켜짐 상태를 보조 기술에 알리고(`aria-pressed` 등), 키보드로 쓸 수 있다. 켬·끔을 날짜를 옮기는 동안 유지할지, 새로 고침 뒤에도 남길지는 AI 재량이다(7장).
   - 확인: E2E. 키보드로 칩을 켜고 끌 수 있고 상태 속성이 바뀐다.

### 4.5 날짜 목록의 읽은 정도 (M6)

1. **표시:** 날짜 목록의 날짜마다 그날 뉴스(모든 섹션의 주요 뉴스와 짧은 소식)의 읽은 수와 전체 수를 "12/42 읽음"처럼 보인다. 모두 읽었으면 "✓ 다 읽음", 하나도 읽지 않았으면 아무것도 보이지 않는다(시안).
   - 확인: E2E. 어떤 날짜의 뉴스를 하나 읽으면 그 날짜 줄이 "1/<전체> 읽음"이 되고, 모두 읽으면 "다 읽음"이 된다. 읽지 않은 날짜는 비어 있다. 전체 수가 그날 사이트 데이터의 뉴스 수와 같다.
2. **사이트 데이터:** 날짜별 전체 수(또는 그것을 셀 수 있는 정보)는 사이트 빌드가 DB에서 만든다. 날짜 목록이 날짜 수만큼 월별 파일을 다 받는 방식은 쓰지 않는다. 더한 데이터가 첫 화면에 실리면 3단계 4.3-7(gzip 300KB)을 지키고, 결과물 파일 수는 3단계 4.1-3 안이다. 같은 DB로 두 번 빌드하면 같은 결과물이다(3단계와 같은 규칙).
   - 확인: 자동 테스트(통합). 지어낸 DB로 빌드한 사이트 데이터의 날짜별 수가 DB의 뉴스 수와 같다. 4단계와 같은 5년치 지어낸 데이터로 첫 화면 전송 크기와 파일 수를 재 보고서에 적는다(4단계 보고서 값과 비교).

### 4.6 사이트 소개와 기록 지우기 (M6)

1. **설명:** 사이트 소개에 "읽은 기록" 절을 더한다. 읽음 표시는 이 브라우저에만 저장되고 어디로도 보내지 않는다는 것, 다른 기기·브라우저와 맞춰지지 않는다는 것, 뉴스 날짜로 1년이 지난 기록은 저절로 지워진다는 것, 지우면 되돌릴 수 없다는 것을 쉬운 한국어 평서문으로 적는다(시안).
   - 확인: E2E. 사이트 소개에 그 절과 문장들이 보인다.
2. **지우기:** 그 절의 "읽은 기록 지우기" 버튼을 누르면 확인을 받은 뒤 읽은 기록을 모두 지우고, 지웠다는 문구를 보인다. 확인에서 취소하면 아무것도 지우지 않는다. 기록이 하나도 없어도 버튼은 동작한다(오류 없음). 이 사이트의 다른 로컬 스토리지 값(있다면)은 지우지 않는다.
   - 확인: E2E. 읽은 뉴스가 있는 상태에서 확인을 수락하면 브리프의 모든 뉴스가 안 읽음으로 보이고 지웠다는 문구가 보인다. 미리 넣어 둔 다른 로컬 스토리지 키의 값은 남는다. 취소하면 그대로다.

### 4.7 기록이 밖으로 나가지 않게 (비밀 값과 비공개 데이터)

1. **보내지 않음:** 읽은 기록은 어떤 요청(사이트 데이터 요청, 검색 색인 요청, 방문 통계)에도 실리지 않는다. 주소(경로, 쿼리, `#`)에 읽은 기록을 넣지 않는다. 방문 통계에 새 이벤트를 더하지 않는다(P10).
   - 확인: E2E. 뉴스 몇 개를 읽음으로 바꾸는 동안 페이지가 보낸 모든 요청의 주소와 본문에 기록에 쓰인 뉴스 식별자 목록이나 저장 키가 들어 있지 않다. `git diff main -- site/src/lib/analytics.ts`가 비어 있고, 코드 검색으로 사용자 정의 이벤트 호출(`track` 등)이 없다.
2. **결과물:** 결과물 검사(3단계 4.1-4)와 공개 전 점검(`node src/cli.ts precheck`)이 지금처럼 통과한다. 새 사이트 데이터에 뉴스 수 밖의 개인 정보가 없다.
   - 확인: 미리보기용 결과물(4.9-1)에 대해 `site` 명령의 결과물 검사가 통과하고, 작업 브랜치에서 `node src/cli.ts precheck`가 통과한다.

### 4.8 화면 공통과 화면 확인 (3단계 4.3-6, M3)

1. **공통 규칙:** 바뀌거나 새로 생긴 화면(브리프, 펼친 카드, 이슈 페이지, 대상 페이지, 검색, 용어 사전, 날짜 목록, 사이트 소개)이 3단계 화면 공통 규칙을 지킨다. 375px에서 가로 스크롤이 없고, 읽음 버튼 때문에 제목이 잘리거나 겹치지 않는다. 터치 화면에서 마우스 올리기 없이 모든 동작을 할 수 있다.
   - 확인: E2E(375px에서 각 화면의 가로 스크롤 없음, 키보드 조작은 4.2·4.4·4.6에 있음). 화면 확인.
2. **대비:** 읽은 뉴스와 안 읽은 뉴스의 글자 색 대비는 지금과 같다(색을 바꾸지 않는다). 파랑 체크는 배경과 3:1 이상, 채운 동그라미 안의 체크는 파랑과 3:1 이상이다(시안의 체크 색은 라이트 흰색, 다크 배경색 `#161618`이다. `design/site.html`의 `.D .rd .chk i`). 안 읽음 테두리의 연한 회색은 M3에서 감수했다. 날짜 목록·사이트 소개의 새 글자는 4.5:1 이상이다.
   - 확인: 자동 테스트(단위). 4단계처럼 테마 색으로 대비를 계산하는 테스트에 새 색을 넣는다. 값을 보고서에 표로 적는다.
3. **화면 확인:** 다음을 375×812 라이트와 다크, 1440px 라이트로 찍는다. 브리프(읽음과 안 읽음이 섞인 상태), 펼친 카드(이전 전개 포함), '안 읽은 것만' 켠 상태와 그 빈 상태, 이슈 타임라인, 대상 페이지, 검색 결과, 용어 사전, 날짜 목록, 사이트 소개(지운 뒤 문구 포함), 로컬 스토리지를 쓸 수 없는 상태의 브리프. 지어낸 데이터로 찍고, 실제 복사본으로는 브리프 한 장만 더 찍는다.

### 멈추고 물을 것

- 비용이 드는 것(유료 플랜, 유료 기능).
- 운영 배포, 원격 push, 저장소 설정 변경이 필요해 보일 때.
- 실제 `data/`, 실제 DB, `refs/heads/data`를 바꿔야 할 때.
- DB 스키마나 백업 형식을 바꿔야 할 것 같을 때(4.10-2). 사이트 빌드만으로 4.5를 할 수 없다는 뜻이므로 그 부분만 보류한다.
- 미리보기 배포가 로그인 없이 열릴 때(보호가 꺼져 있음). 그 미리보기는 지우지 않고(삭제는 사용자가 한다) 보고서에 적고, 더 배포하지 않는다.
- 이번 작업으로 다른 Vercel 프로젝트가 생겼을 때. 지우지 않고 보고서에 적는다.
- Vercel·GitHub 계정이 6장과 다를 때(그 부분만 보류).

### AI 재량

- 로컬 스토리지의 키 이름과 저장 형식(4.1 안에서), 기록을 화면 사이에 나누는 방법(React 상태, 구독 등), 오래된 기록을 지우는 시점의 세부(4.1-3 안에서).
- 날짜별 뉴스 수를 담을 사이트 데이터 파일과 형식(4.5-2 안에서).
- '안 읽은 것만' 칩의 켬·끔을 날짜를 옮기는 동안 유지할지, 새로 고침 뒤에도 남길지(남기면 같은 로컬 스토리지에 두고 4.6-2의 지우기 대상에서는 뺀다).
- 지우기 확인의 방식(브라우저 확인 창 또는 화면 안 확인)과 문구. 문구는 기존 사이트의 말투(설명은 "~다." 평서문, 부탁은 "~해 주세요")를 따르고, 시안의 합쇼체 문구("지울까요?", "지웠습니다.")는 뜻만 따른다.
- 화면 세부(간격, 체크 글리프, 문구)는 확정 시안을 따르고, 시안에 없는 것은 3단계 시안 A의 기준으로 정한다.
- 테스트 층(단위·통합·E2E)의 나눔. 4장에 E2E로 적은 확인은 E2E로 둔다.
